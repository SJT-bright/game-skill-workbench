# Cocos 游戏广告设计

修订：`2026-10-27.economy-v4`。

本 Skill 负责广告在玩法中的设计：哪里出现、什么时候出现、看完给什么、给多少、取消后怎么继续。英化＋优化与重塑都调用本入口。当前用户明确选择和项目授权优先；不要借广告设计重做玩法或强加用户排除的皮肤系统。

## 共用的广告设计

以下规则从既有[内置板块](../cocos-game-to-english/references/game-modules.md)整理；公式、数值和实现仍以该页及其 `AdRewards.ts` 为单一来源，不复制第二套计算模块。修改通用规则时同步本入口与原规则，不能只改其中一处。

| 场景 | 展示与收益 | 免费路径及范围 |
| --- | --- | --- |
| 通关结算 / 无尽每局结算 | 结算提供项目授权的双倍或增量入口；完整观看后只补本次合法差额，基础 `total` 包含当前装备的合法货币加成 | No thanks 领取基础 `total`；广告取消或失败仍领取基础收益，不追加广告奖励。有关卡游戏失败不发货币，也不展示结算广告，除非项目规则明确适用 |
| 奖励关结算 | 奖励关倍率和广告增量来自项目奖励表；不能对已经含倍率的收益重复乘算 | 不看仍领取项目规定的基础奖励；广告只补差额 |
| 首页礼盒 | 按项目奖励表、资格和冷却领取；资格成功提交后才进入冷却，不重置、不累积，除非项目规则明确允许 | 取消、失败、超时不发礼盒奖励、不耗资格；动画按美术 Skill 在适用页面检查 |
| 独立广告领币 | 奖励数量、资格和频率沿用项目经济表，与其他广告入口分开记账 | 取消/失败不发，不因本条强加额外广告入口 |
| 皮肤试用（项目启用皮肤板块时） | 触发关卡、资格和试用时长来自项目设计；试用仅按项目规定生效，不自动变成永久解锁 | No Thanks 出现即能点；广告非完成保留试用弹窗并可重试，只有明确免费继续才进关；全部拥有后不弹 |
| 体力补充（游戏有体力系统时必有） | 增量来自项目体力上限和奖励表，按钮/奖励预览必须写清实际增量，不能把 ×2 当作固定体力奖励 | 取消、失败、超时不加体力、不扣现有体力；可免费关闭；不足以完整容纳项目增量时不播放；无体力系统不新增体力 |
| 复活 | 按[复活审查](../cocos-game-to-english/references/rewarded-revive-and-help-layout.md)盘点已有复活及项目是否适用，明确次数、恢复状态与免费重开 | 不能把广告跳关包装成复活；只有完整观看才恢复本局，失败不消耗资格；不适用或当前用户排除时写明依据 |

结算广告按钮应与正常继续/Next 分开，并有可直接使用的 No thanks；按钮采用当前项目画风。**可领取广告双倍奖励时，“看广告 ×2”是结算页最醒目的主按钮；普通领取／免费继续是较小、视觉权重较低的次按钮。** 设计及验收读取[结算双倍主按钮层级](../cocos-game-to-english/references/mobile-button-size-and-home-layout.md#结算双倍主按钮层级用户-2026-10-27)，不能仅因广告入口存在、可点击就判展示合格。礼盒位置、皮肤试用和货币购买规则只来自当前项目设计与奖励表，不能把另一款游戏的数量、价格、关卡或冷却复制进来。

当广告按成功事件、里程碑或冷却触发时，触发状态必须是可验证的业务状态并按项目需要持久化；失败、未完成、取消和不完整操作不能推进节奏。基础奖励先按正常路径入账，广告只补合法增量；关闭、失败、超时和迟到回调不得撤销基础奖励或重复发放。用同一编译入口保留旧频率负例、修复频率和正常对照，并同时读回广告调用次数、基础余额、节奏状态和后续消费者；没有这种广告节奏机制的游戏标记 n/a，不为满足模板新增入口。

## 激励广告必须由玩家主动点击触发（2026-10-27）

所有激励广告 SDK 调用必须从当前可见广告按钮的真实触摸处理器进入。结算页、失败页、通用 `handleUI`/页面打开流程、概率字段或自动恢复流程不得调用 `rewardedVideo.show()`；页面出现后先断言 SDK 调用数为 0，再对广告按钮执行一次真实触摸，才允许出现一次 `create/show`。失败结算保留免费退出/重试路径，广告等待层不能先于玩家动作出现。旧版自动调用负例、修复版和正常对照都要绑定同一编译产物回归。

**签到/领取页的无操作反例（2026-10-27）**：标为手动领取的奖励，分别验证冷启动不触摸、只打开页面、触摸卡片说明/金额、已领取控件和正式领取按钮；记录余额、领取日期/收据与 SDK 次数。三倍开关默认免费，不能用整张展示卡的热区代替可见广告/领取控件；切换倍率本身不发奖、不播广告。`Done` 来自历史状态，不能仅凭截图断言本次自动发奖。旧错误热区须真实触摸复现并被本作问题门禁拒绝，再核正常领取、广告取消与完整完成、重复点击及重开读回。

## 为当前游戏落地

先盘点真实玩法、每种结算和已有广告入口，在项目现有设计文档内写清：触发条件、按钮/页面、奖励公式、领取频率、资格与持久化、取消/失败后的免费路径。复用已有清单，不为填表新增玩法。英化的原入口及收益按原项目授权保留，结合共用内置板块处理；重塑按启动包与当前规格落地。有冲突时记录具体冲突，服从当前用户明确选择，不用旧模板覆盖它。

明确禁止广告跳关；分享、排行榜等禁止功能不能成为广告入口。七日签到已恢复为用户可选模块，用户明确要求时按 skin-bonus-and-checkin.md 启用；每日基础签到免费领取，不因货币改造转为必须看广告。保留正常免费开始、重试、退出和基础结算收益；不能把原先免费的奖励改成必须看广告。结算只入账一次：若基础收益已经发放，广告完成只补差额，最终余额增量为 `doubled`，不能先发 `total` 再发整个 `doubled`。

每个入口覆盖完整观看、取消、失败、超时、连点、重复/迟到回调、离页后返回和保存恢复。广告未完成只是不发广告增量，不得扣掉已经合法取得的基础收益。广告前后暂停、声音、计时、输入与原玩法状态正确恢复。共用 AdRewards 只管数值与业务去重，不能替代真实 SDK 会话隔离与保存事务。

## 正常游玩可达性（2026-10-25）

入口数量不按SDK调用或商店按钮计数。用金币充足、不打开商店的正常玩家，从HOME自然开始→通关→下一关→回HOME，核对每种胜利结算的×2和大厅奖励入口实际可见、可点且能到账；不能只测缺币补给。沿用当前奖励表及免费继续，取消/失败不挡路，基础已到账时只补差额；记录入口来源、广告前后余额、领取状态和下一局恢复。同一流程在旧版应暴露缺失、新版通过；缺入口或没有业务结果断言不能记广告覆盖通过。

## 皮肤试用频率的项目验收（2026-10-27）

对每个本次制作、检查广告或出包的游戏，先盘点实际是否启用皮肤试用、关卡编号及可试用皮肤；无该功能或用户明确排除时记录依据，不为通过检查新增功能。有此功能时，AI 自己在与当前交付候选绑定的实际运行产物中验证，不依赖用户试玩、源码搜索或规则文本判断通过。确认有未拥有且可试用的普通皮肤，避免因资格不足把缺失弹窗误判为频率正确。

至少覆盖第 1、4、5、6、9、10、11、15 关：5、10、15 进入前各出现一次，其余不出现；确认实际显示关号，关闭免费继续后进入对应关卡并发生真实玩法状态变化。至少一次从正常通关/下一关路径跨过边界；其他边界可使用独立测试存档定位，不能改用户正式存档或把跳关工具放进交付包。检查重复进入、重试/恢复以及全部拥有或无合格皮肤时不误弹；结合游戏实际关卡结构补充适用边界。若能执行候选实际频率函数，再覆盖有效关卡范围，函数测试不能代替玩家路径。

记录候选身份及哈希、关号、初始资格、进入方式、实际弹窗次数、免费继续和玩法结果，保留可复核的运行证据；缺入口、错频、证据缺失或与最终候选不一致为未通过。发现问题修复、重建并针对旧故障及正常对照复验；出包授权已存在时继续完成出包。既有有效同版证据且相关实现、资格或流程未变可复用，不对无关改动重复测试。测试替身与本地验证不得宣称真实广告或真机通过。

## 玩家预览不得暴露模拟发奖（用户2026-10-26）

正常用户试玩和交付构建不得因缺SDK自动进入模拟广告，也不得提供COMPLETE/成功/发奖等能伪造完成回调的玩家按钮。没有真实广告接口时显示不可用并不发广告增量；测试替身只在独立测试运行器中注入，不用URL参数或玩家入口启用。待领取数量必须与当前库存区分。定点检查所有共享激励入口：先用旧UI复现不播广告点击即发奖，再核新UI无领取捷径，且完整SDK回调只发一次，取消/错误/拒绝/超时/迟到不发；标SIMULATED不能让玩家测试按钮成为可交付功能。


**上述规则的本地模拟例外（用户2026-10-26本轮明确）**：用户明确要求自己测试广告时，允许独立、本地服务注入的[手动模拟](../cocos-game-to-english/references/manual-ad-simulation.md)，由用户选择看完/取消/失败，经原业务处理并读取状态。它不是正常游戏或可上传功能；正常试玩不因缺SDK自动进入，Native/最终上传ZIP仍禁止携带。

## Native 广告前置链必须单独验收（2026-10-27）

广告模拟器只覆盖模拟回调和奖励消费者，不能覆盖 TikTok Native 存储桥。广告任务必须另外核查 `点击→存储读取→SDK create/show→回调→奖励保存→消费`，并在目标 adapter 边界分别注入相关缺省、合法 Boolean 和坏值。按目标平台契约及键语义处理，坏值仍阻断并提示恢复；广告在SDK之前被存档读取拦截时，记录为存储问题，不写成广告无填充。

广告设计、逻辑检查和测试包三个入口共享这一合同：实现者接公共读取入口，测试者交 `storage_boolean` 原始证据，出包者检查当前Native绑定；缺任何一项都不能标广告入口通过。

**2026-10-27 审查纠偏**：先依据目标平台存储 API 的实际契约和键的业务语义区分缺失、合法 Boolean、读取失败与损坏值；不能跨游戏一律把 `false` 当缺失、`true` 当 1。测试注入须说明替身位置并通过真实用户入口验证业务结果；本地替身和日志不证明平台真机行为。逐形状留可复核断言，缺失旧版反例、完整广告链或平台证据时分别标未验证。

**真实广告不是本地交付门槛（用户2026-10-27）**：电脑本地不要求真实 TikTok 广告填充或播放；用独立SDK边界模拟验证实际触摸、奖励与恢复，不得因缺少真实广告而停工、拒包或等待用户。适用检查通过即完成授权交付，日常不重复免责声明。统一规则见[电脑本地广告验收边界](../cocos-game-to-english/references/tiktok-device-stage.md#电脑本地广告验收边界用户2026-10-27明确)。

广告前置读取或 Native adapter 故障修复时，执行[本地广告修复闭环](../cocos-game-to-english/references/native-ad-local-repair.md)：忠实存储/能力替身、真实按钮到 SDK 与到账、超时重试、迟到回调、保存重试及原消费者；以业务结果和旧故障对照收口。

**每轮修改主动交预览（用户2026-10-28）**：每轮游戏代码、美术、玩法、广告或打包相关修改完成后，主动在回复中给出当前同版本可点击的固定手机预览链接，无需等用户再次索取。按[用户本地试玩](../cocos-game-to-english/references/user-phone-preview.md)执行；交接前确认服务可访问且指向本轮完成的构建。
