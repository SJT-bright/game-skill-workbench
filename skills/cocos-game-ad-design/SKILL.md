# Cocos 游戏广告设计

修订：`2026-10-27.economy-v4`。

本 Skill 负责广告在玩法中的设计：哪里出现、什么时候出现、看完给什么、给多少、取消后怎么继续。英化＋优化与重塑都调用本入口。当前用户明确选择和项目授权优先；不要借广告设计重做玩法或强加用户排除的皮肤系统。

## 共用的广告设计

以下规则从既有[内置板块](../cocos-game-to-english/references/game-modules.md)整理；公式、数值和实现仍以该页及其 `AdRewards.ts` 为单一来源，不复制第二套计算模块。修改通用规则时同步本入口与原规则，不能只改其中一处。

| 场景 | 展示与收益 | 免费路径及范围 |
| --- | --- | --- |
| 通关结算 / 无尽每局结算 | 结算提供 Watch ad ×2，完整观看后本次总收益为 `total × 2`；`total` 包含当前装备的合法货币加成 | No thanks 领取 `total`；广告取消或失败仍领取基础结算 `total`，不追加广告奖励。有关卡游戏失败不发货币，也不展示×2；无尽每局结算都有 |
| 奖励关结算 | 关卡收益已为普通关的3倍，看广告将这笔收益翻倍，即普通关的6倍 | 不看仍领3倍；不能在已含3倍的关卡数据上再次乘3 |
| 首页礼盒 | 看完并成功入账获得固定5个普通关基础奖励；初始一份，成功领取后30分钟冷却，显示倒计时，通关不重置、不累积 | 取消、失败、超时不发礼盒奖励、不耗资格；10帧礼盒动画由美术 Skill 在美术关检查 |
| 独立广告领币 | 每次完整观看领取5个普通关基础奖励，与礼盒共用B、与结算×2分开 | 取消/失败不发，资格与频率沿用项目授权；不因本条强加额外广告入口 |
| 皮肤试用（项目启用皮肤板块时） | 下一关前提供广告试用；第5、10、15……关进入前提供一次，其他关不弹；试用仅本关生效，不累计永久解锁 | No Thanks 出现即能点；广告非完成保留试用弹窗并可重试，只有明确免费继续才进关；限定皮肤不试用，全部拥有后不弹 |
| 体力补充（游戏有体力系统时必有） | 提供明确的激励广告入口，完整观看一次增加 **3 格体力**；按钮/奖励预览写清 `+3`，不能用 ×2 冒充 | 取消、失败、超时不加体力、不扣现有体力；可免费关闭。按原游戏上限设计：不足以完整容纳 +3 时不播放该广告，避免观看后奖励被截断；无体力系统不新增体力 |
| 复活 | 按[复活审查](../cocos-game-to-english/references/rewarded-revive-and-help-layout.md)盘点已有复活及项目是否适用，明确次数、恢复状态与免费重开 | 不能把广告跳关包装成复活；只有完整观看才恢复本局，失败不消耗资格；不适用或当前用户排除时写明依据 |

结算×2按钮在 Next 上方、略大于 Next，旁有可直接使用的 No thanks；按钮采用本游戏画风。礼盒位于首页下方功能图标排。皮肤试用细节见[收集与皮肤设计](../cocos-game-to-english/references/rarity-unlock-design.md)。默认皮肤为货币购买，不能误用旧的广告永久解锁模式；限定皮肤也按50个普通关基础奖励购买，已有首通赠送沿用设计且不重复补币。

## 为当前游戏落地

先盘点真实玩法、每种结算和已有广告入口，在项目现有设计文档内写清：触发条件、按钮/页面、奖励公式、领取频率、资格与持久化、取消/失败后的免费路径。复用已有清单，不为填表新增玩法。英化的原入口及收益按原项目授权保留，结合共用内置板块处理；重塑按启动包与当前规格落地。有冲突时记录具体冲突，服从当前用户明确选择，不用旧模板覆盖它。

明确禁止广告跳关；分享、排行榜和七日签到等禁止功能不能成为广告入口。保留正常免费开始、重试、退出和基础结算收益；不能把原先免费的奖励改成必须看广告。结算只入账一次：若基础收益已经发放，广告完成只补差额，最终余额增量为 `doubled`，不能先发 `total` 再发整个 `doubled`。

每个入口覆盖完整观看、取消、失败、超时、连点、重复/迟到回调、离页后返回和保存恢复。广告未完成只是不发广告增量，不得扣掉已经合法取得的基础收益。广告前后暂停、声音、计时、输入与原玩法状态正确恢复。共用 AdRewards 只管数值与业务去重，不能替代真实 SDK 会话隔离与保存事务。

## 正常游玩可达性（2026-10-25）

入口数量不按SDK调用或商店按钮计数。用金币充足、不打开商店的正常玩家，从HOME自然开始→通关→下一关→回HOME，核对每种胜利结算的×2和大厅奖励入口实际可见、可点且能到账；不能只测缺币补给。沿用当前奖励表及免费继续，取消/失败不挡路，基础已到账时只补差额；记录入口来源、广告前后余额、领取状态和下一局恢复。同一流程在旧版应暴露缺失、新版通过；缺入口或没有业务结果断言不能记广告覆盖通过。

## 玩家预览不得暴露模拟发奖（用户2026-10-26）

正常用户试玩和交付构建不得因缺SDK自动进入模拟广告，也不得提供COMPLETE/成功/发奖等能伪造完成回调的玩家按钮。没有真实广告接口时显示不可用并不发广告增量；测试替身只在独立测试运行器中注入，不用URL参数或玩家入口启用。待领取数量必须与当前库存区分。定点检查所有共享激励入口：先用旧UI复现不播广告点击即发奖，再核新UI无领取捷径，且完整SDK回调只发一次，取消/错误/拒绝/超时/迟到不发；标SIMULATED不能让玩家测试按钮成为可交付功能。


**上述规则的本地模拟例外（用户2026-10-26本轮明确）**：用户明确要求自己测试广告时，允许独立、本地服务注入的[手动模拟](../cocos-game-to-english/references/manual-ad-simulation.md)，由用户选择看完/取消/失败，经原业务处理并读取状态。它不是正常游戏或可上传功能；正常试玩不因缺SDK自动进入，Native/最终上传ZIP仍禁止携带。
