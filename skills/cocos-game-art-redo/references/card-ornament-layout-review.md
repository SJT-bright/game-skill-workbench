# 装饰卡片：实际内区、主体比例与切片内容短检

用于收藏/换装/角色列表出现边框挤占、角色很小、内容大段空白、名称/价格压花饰或混入邻格碎片。只检查受影响卡片组及实际共享调用方，沿用局部修改范围。

1. **先补完整实景**：保留可运行未修版，进入用户指明的页面和状态，等素材与布局稳定后拍整屏和局部。先分清用户截图裁边与游戏实际越界；入口能打开、矩形在屏内，不代表卡片内部已审查。已有布局检查的 safe/boxes 接口也需确认本页卡片确实逐组采集；safe_estimated 之类的估算内区不能代替源图装饰标定。
2. **从源图到实际内区**：看源面板与实际 RAW/SLICED、SpriteFrame rect、九宫格 insets、祖先缩放。标记避开叶片/花饰的正文内区；九宫格使用分段缩放映射到实际屏幕，不能直接把外框或源图内区等比套过去。装饰不适合缩成小卡时，可用等比整图或适配的小卡素材，不把固定像素的边距硬塞进小框。
3. **按完整卡片归组**：角色/插画、名字、条件/价格、主动作一起看，检查是否压装饰、内容互压、主体被边框淹没、连续大空隙。以当前设计意图和真实正常对照声明比例/间距，不把某款游戏的坐标、角色占比当作通用硬门槛；目标框、点击根框不能替代真实 Sprite 与字形。
4. **补切片内容检查**：同时看源图邻域与实际渲染切片，确认无邻格碎片、断边和缺失字形。按共用[图集切片内容检查](../../cocos-game-to-english/references/atlas-slice-integrity.md)处理；其透明图协议未覆盖的材料，先接真实适配器，不声称已自动检查。已知污染区可登记到项目数据，与实际取图区域比较；源图局部坐标必须先映射到打包纹理，旋转/裁边无法校准时报告不可检查。
5. **同一方法回放后再提升**：候选流程和采集器先放项目临时目录；同一 checker 须检出可运行未修版的具体缺陷，再检查修复版、正常布局及正常九宫格映射对照。截图、业务 bundle SHA 和实际采集绑定。空采集、缺图、未知内区/映射均不得填通过；已知污染区比对不等于能自动发现所有未知残片，仍需看整张合成图。
6. **局部实景收尾**：在受影响的两种手机比例看同页，覆盖最长名称、不同解锁文案、最外侧卡片及分页；点详情/返回确认仍有效。实景出现新缺陷就完善候选再回放；当前缺陷旧版能检出且修正版无此问题后才写入正式 Skill，不扩大为全游戏 CI。

辅助工具：`python3 scripts/check_card_layout.py CAPTURE.json`。它辅助检查声明的装饰内区、内容框、项目比例/间距和已知源图污染区；不独立判断美观，也不证明未知切片内容完整。退出 1 表示发现问题或输入不可检查。

采集需为真实 Cocos Sprite 屏幕几何，`producer: real_cocos_card_geometry`；包含 `viewport`、截图绝对路径与 SHA、`bundle_sha256`、非空 `cards`、项目 `layout_policy`。每卡含实际 `panel`（rect/node_size/frame/sliced/insets/loaded）、源图标定 `source_safe` 和角色/名称/条件/动作 `items`。可选 `known_art_exclusions` 明确坐标空间；源图局部污染区需配项目采集器提供的 `source_origin_in_texture`，从原图完整帧原点映射，而不是盲用被裁后帧的新原点。正常几何合成对照仅是脚本校准，不能写成真实运行证据。项目坐标、污染区域和采集器留项目，不写死到通用 Skill。
