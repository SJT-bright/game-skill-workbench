# 大型背景与静态层短检

用于棋盘垫、布面、房间地面等铺满较大游戏区域的高细节图，以及玩家反馈“每次点按都会移动/跳动”的静态背景。属于局部美术复查，不扩成全游戏验收。

1. **先留未修证据。** 保存用户原截图、实际使用的原始图及源码版本。量原始有效像素与运行时最大显示尺寸，记录 sprite frame 裁切、`RAW`/`CUSTOM`/`SLICED`、cover 比例、节点和父节点缩放。背景有效像素至少覆盖运行时最大尺寸的 1.5 倍；任何显示放大超过原图有效像素都不合格。布纹、刺绣、木纹、花纹等细节区不能以九宫格容器的平铺/延展豁免；只有明确标出的纯色或重复延展区域可按九宫格规则单独核。
2. **检查静态层是否随交互重建。** 阅读一次有效点按会经过的更新路径；确认静态背景不在每次点按都会清空/重建的玩法节点下。背景放在稳定层，透明触控区单独承接输入；非游戏页面用可见性切换，不反复销毁再创建背景。原版没有现成运行时探针时，记录一次有效触控前后的同帧截图、背景节点/变换框和节点存活状态。
3. **先验证检查法，再修复。** 在隔离候选中用同一短检检查未修改版本，必须能报出已知的低像素密度、随点按重建或截图可见缺陷；若没报出，先改检查法，不得把新规则写成已验证。完成修复后，用同一短检复查新图与实际运行画面，做一次有效触控并确认背景视觉位置/缩放/节点保持稳定；原版失败、修复版无同类发现才可沉淀规则。
4. **记录证据边界。** 保存两版截图、源图尺寸与运行时尺寸、触控前后测量和结果。只报告实际复查的游戏页面与视口；脚本静态匹配、源图分辨率、单张截图或 `art_check.py` 因缺少可识别的 Cocos 工程而跳过，都不能单独证明运行时通过。

本短检不要求完整玩法回归。若修复触及游戏规则、多个页面或公共布局，再按实际影响扩大检查范围。
