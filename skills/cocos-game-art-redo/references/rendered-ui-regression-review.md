# 成屏视觉缺陷回归

用于图片字、资源栏、集合卡片或面板反复出现“素材已换，实际仍不好看”的问题。原素材与失败版本保留，玩法和经济沿用用户授权范围。

1. 绑定当前业务 bundle、资源配置与贴图指纹；手机视口、DPR、触摸和 UA 在加载前设置并读回。等待资源、完整字形和实际绘制帧，保存同帧节点记录与原始截图。长等待分段观察，超时不能当通过。
2. 检查唯一画面所有者：旧 Sprite 是否仍 enabled、新旧组件是否同时绘制、异步回调是否写回旧节点。以 SpriteFrame UUID 找实际源图及裁片，不能只按可变帧名匹配。
3. 数字与小字同时核业务值、Alpha 紧框、CSS 字高、描边间正间隙、图标内区和合成对比度。奶白填充不自动代表清楚；在原尺寸看仍模糊就修轮廓或布局，不改阈值放行。
4. 列表看首屏与底部；遮罩按真实可见区域检查，保留未裁矩形用于源图投影。完整卡片查内容，过渡裁切查越界；父面板烘焙装饰也属于遮挡边界。
5. 区分产品缺陷、采集失败、检查器适配。适配只修观察边界，不能用节点名称豁免缺图、碰撞或低对比。模板页面必须先核真实业务路径；不为没有的机制新增玩法。适配代码和适用范围留项目。
6. 先模拟再推广：旧失败图或构建须被同一判据拒绝，正常与修复对照通过；保留真实碰撞、低对比等负例。检查两种手机比例的整页及原尺寸局部。涉及 Native 时另留真实输入后的玩法变化、故障后一次 Retry 产生新请求并恢复的证据。

只有以上校准与最终画面复查通过，才将通用流程纳入正式 Skill。项目例外、状态和测试产物不复制进全局规则；资源加载成功、节点矩形通过都不能单独证明视觉通过。

7. 绘制顺序必须在异步资源落地后核对：整按钮图替换旧 PanelArt 时停用旧画面；状态字须在自身底板之上，动态数值底板须在卡片之上、字形之下；弹窗遮罩必须高于整组 HUD。检查器遍历实际渲染层级，不能只查同级矩形。新规则必须用旧故障构建实测拒绝，再用修复与正常对照通过。
8. 测试适配错误保留原异常并补齐对应 SDK 边界；禁止按异常文本过滤、吞掉或改写首异常来取得通过。自动断言通过后仍复查两比例原尺寸整页；发现漏检，补对应可执行断言再回测旧失败版本。
