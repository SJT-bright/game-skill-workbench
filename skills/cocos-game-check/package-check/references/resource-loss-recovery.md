# 资源漏包：定位与恢复

适用于已验收画面在最终包中退回基础底板、按钮/标签消失，或 Web 与 Native 显示不一致。

- 先绑定准确故障 ZIP，再核业务请求的 `bundle + path + type`、已验收构建与最终 Native。ZIP 与原构建一致只证明复制完整，不能证明构建输入完整；fallback 可运行也不算资源加载通过。
- 若源图和 `.meta` 缺失，优先从保留的同版源资产/生成原件恢复，并核已验收构建中的 UUID、尺寸和 SpriteFrame。不要重生图替代用户已批准的素材；无法确定资源何时丢失，就只报告已证实的缺失阶段。
- 体积与资源齐全必须同时通过。恢复素材后超限应优化编码或分包，保留透明度、尺寸及图集/裁切契约，不能删被调用资源凑限额。压缩后更新指纹并核实际渲染。
- 同一探针须在准确旧包失败、修复包与正常对照通过，并接在项目 writer 写 ZIP 前。若解析器未覆盖资源映射，补当前适配，不能填空清单或直接抄整个 catalog。
- 对同一业务页保存旧/新资源加载状态、截图和点击结果。Native 资源放在 Web 引擎中对照可定位资源问题，但结论仅限资源加载；不得冒充 Native adapter 执行。
- 用户确认修复版通过后，项目记录确认日期、原话、交付版本/SHA和本地证据；未说明的设备/广告/全关范围不补写。共享 Skill 只保留方法，不复制项目路径、私人视频或整份测试报告。

这类定点检查不依赖全量 CI。有效证据绑定产物字节；资源、入口或构建改变后，旧 Web 通过不能自动转作新 Native 通过。
