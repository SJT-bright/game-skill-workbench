## 成品测试通过后自动出包（用户2026-10-26）

游戏制作或维护已进入成品功能测试阶段时，完成本轮测试与必要修复后，连续完成同版证据封装、正式writer、最终交付核验和上传测试ZIP交付，并附同版本手机尺寸本地试玩链接。用户说“继续未完成的测试”“开始测试”或“测试完了”承接当前成品流程，不把测试报告、门禁报告尚未封装、可信runner尚未登记或“没有再说一次打包”解释成停止点；这些都是Agent应继续完成的工作，不等待再次“继续”、不再询问是否出包。发现可修复拒包项就定点修复、复验并接着出包，不重复已有效通过的无关测试，不跳过门禁。只有用户明确限制为只检测/评审、只试玩、只改Skill、明确暂停，或确实缺少无法自主取得的材料/权限时才在对应边界停止并说明具体缺口。中途玩法/美术确认节点不提前出包；自动出包不包含平台上传、审核或发布授权。

# 检查后持续修复并交付（2026-10-24）

## 出包请求就是修复到交付的授权（用户2026-10-26）

“可以给我上传测试包”“给我测试包”“打包/重新打包”“出个可上传的包”“修好再给我包”及同义表达，目标均是当前游戏可交付的Native测试ZIP。请求同时授权处理阻止出包的产品缺陷、必要兼容适配、测试与证据补齐，不要求用户再次说“继续/修复/补测试”。“给我上传测试包”在索取文件的语境下不等于代替用户向平台上传；实际上传、提审、发布按明确授权执行。

按闭环持续推进：读取拒绝原因→区分产品缺陷、缺证据/旧绑定、工具适配缺口、真实外部阻塞→修复或补真实验证→仅复测受影响链→重建当前Native→运行正式writer及交付核对→主动给出最终ZIP链接。当前材料足够时，缺runner/协议支持属于Agent要补的实现工作，不自动变成向用户索取材料的理由；保留旧版/反例与当前绑定，不套用其他项目证据。

writer的“拒包”只禁止发布当前不合格产物，不是拒绝用户任务。还有可自主完成的修复、测试或适配时，失败清单、候选已修一项、“暂时不能交包”“缺运行证据”只在commentary汇报，不能据此final结束，不让用户用“继续”充当内部调度。原有“不重跑整套CI”继续有效，仅补实际阻断项；禁止删门禁、放宽断言、伪造通过或另走未受检压缩入口。

结束条件：已核对的同版测试ZIP已主动交付；或用户停止/工具安全停止；或确实需要用户控制的账号、设备、权限、缺失原始材料、超出当前授权的关键决策，且不依赖它的工作已经完成。外部阻塞要说明具体缺什么、已尝试什么、用户最小动作及保留的可续接状态；未经实际验证不得泛称“缺设备/缺runner所以不能做”。用户明确只要一轮检测/报告或只更新Skill时，遵守该范围，不自动修产品或出包。


**持续执行与进度汇报（2026-10-25纠错）**：用户已授权的开发、完整验收或出包，不按固定分钟、一次修复、固定测试数量或一次预览更新切成等待“继续”的回合。修好一项且局部回归通过后，只在 commentary 汇报进度，并在当前任务继续下一项；“整体未完成”是继续工作的状态，不是 final 收尾理由。省Token的检查点/回合提醒只用于保存进度，不构成停止授权。仅到用户明确要求的交付终点、既有必需人工确认节点、用户停止、工具安全停止或确需外部输入且独立工作已尽时才结束；如有真实限制说明具体原因，不让用户用“继续”代替内部调度。新聊天仅按已授权的阶段接续规则创建，不自动扩大跨聊天操作。


**美术检查前移（用户 2026-10-25）**：按[美术验收前移与试玩后锁定](../../../remake-art/references/art-before-trial.md)执行：所有美术测试在交用户试玩前完成；用户确认后到测试包交付之间不再美工测试、不重新评判已批准画面。最终画面字段只查运行故障，不夹带美术标准。


用于本会话制作的游戏，且用户已要求测试包/检测包/打包。门禁未通过是下一步修复输入，不是阶段结束或等待用户批准的节点。

- 读取每个拒绝项，区分实际产品缺陷、证据未采集、旧指纹、工具误报及外部条件；修产品或补真实证据，对误报给具体代码依据。复测受影响链路，直到正式 writer 能产出当前同版本测试包。

## 图片 UI 与测试顺序的实测补充（2026-10-24）

首次整套美术在对应阶段检查两种比例的页面/失败状态；已有美术结论时只复查受影响页。固定组装候选后执行一次完整适用功能矩阵；修复后按[审查顺序与去重](../../test/references/review-execution-plan.md)增量回归，最终核验不重演有效的整轮。美术变化后重跑受影响页面；不要在同一明显未完成的布局上反复启动整套关卡长测。

Cocos 2.x 的 Sprite 赋帧可能重置节点尺寸：先赋 spriteFrame、设置 CUSTOM/SLICED，再写实际尺寸。整图按钮保持独立点击容器和等比图片子节点，禁用旧根 Label，避免旧字重新转换为图片后叠印。

UI 观察器记录真实祖先 ID、实际启用且有帧的 Sprite 和完整图片文字组合。零尺寸容器可能不出现在 dump 中，不能只靠深度栈推断祖先；同名卡片不能靠字符串路径当成同一节点。对生成字的对比度，应从原图 alpha/字面掩码采样实际截图字面及描边，不能把字距中的背景判成字色。九宫格拉伸边距与可用的画面内容边界分别核验；工具误报先用原始节点与像素复现、增加正负校准，不直接删门禁或写假通过。

检测到共享 Skill 工具在别的任务中发生变化时，为当前候选保存带哈希的检查器/正式打包器快照与必要修复差异，固定同一套检查语义完成本次出包。保留校准、真实原始证据与版本绑定；这不授权跳过检测或放宽门槛。

## 续测时的构建完整性与测试所有权（2026-10-25）

构建日志的成功不能证明当前输出仍完整。续测先校验实际入口依赖和将要加载的页面资源；发现引擎或纹理文件缺失时保留当前失败路径与404记录，从当前源码重建并重新绑定文件清单，不复用重建前的通过报告。缺失文件的删除来源未查明时不要臆测根因。

同一个测试页面只允许一条操作序列。终止本地 CLI 不一定取消浏览器服务端已经提交的脚本；取消后须用受支持接口关闭该次自建页面并读回页面列表，后续使用新的 Page label，防止旧脚本继续跳转。实际产品失败与测试操作互相干扰分开记录，不能因此默认其余失败都是工具问题。

加载动画检测比较累计变化：缓慢连续运动的相邻帧差可能一直小于变化阈值。应与最后一次确认发生变化的参考帧比较，并以连续静止和长暂停反例验证仍能拒绝真正卡住；不放宽冻结时间阈值，不用 rAF 存活替代实际画面运动。


## 故障注入与输入回执的核对（2026-10-25）

故障测试的存档预置、导航、资源请求与服务端故障范围必须指向同一独立测试 origin。若服务端按 Host 隔离故障，使用新 QA hostname 时同步设置 scope_host，并从真实请求日志断言该 Host 命中故障；不能把没有实际注入的正常启动算恢复通过。触摸位置用当前相机、可见尺寸和 Canvas 实际矩形换算，先读实际关卡再断言输赢。

浏览器输入请求超时不等于游戏拒绝输入，也不等于输入成功。不得盲目重发可能已送达的购买/领奖动作；核对同一 URL、该次序号之后、同一坐标的真实 trusted touchstart/touchend，再继续断言实际页面和存档变化。没有完整送达证据就保留失败。原始输入方式、回执超时与真实业务结果分别记录，不将合成触摸声称为真机操作。

验证跨回合内存凭据时，两回合之间不得 reload；reload 会清空待验证的内存状态，掩盖凭据跨回合复用。对照必须在同一 JS 上下文完成前一回合凭据、写失败、退出、下一回合，并从实际 SDK 调用次数及存档余额核验需要新的凭据。


## 有进度的排队请求不能按总耗时拒绝（2026-10-25）

慢网出现 Retry 时，核对失败资源的真实下载阶段、浏览器连接队列与 onFileProgress。定时器从调用下载 API 起算，可能把连接排队算成单个请求无进度；其他同批资源仍在收到字节或成功完成时，不能仅因该请求调用已满十秒便强制中止。可使用该批真实字节增长/成功完成刷新空闲基准，仍保留十秒完全无进度失败和一次 Retry 创建新请求的合同；后台暂停单独计时，完成回调仍须去重。

修复前后都执行同一慢网原始启动，不只用“立即返回成功”的桩。确定性校准至少包含：一个请求等待，另一个九秒时有真实进度，十五秒时等待请求不能误失败；最后有效进度之后十秒完全无响应仍必须失败。保留旧代码失败、新代码通过及实际慢网与挂起请求两条 GUI 证据，不放宽空闲门限来解决误判。


## 瞬时连接失败的有限恢复（2026-10-25）

同一个图片请求出现浏览器 `ERR_INVALID_HTTP_RESPONSE`、XHR `status: 0(error)` 时，先核服务器请求、响应状态和实际资源字节，区分缺图、HTTP 明确错误与连接层失败。可对已确认的瞬时连接错误发起一次新传输；不要整体增加引擎重试次数，不重置最后真实进度的空闲时钟，不重试 404/503 等明确响应，也不无限吞掉第二次失败。

校准需要准确旧构建与修复构建面对同一外部连接故障：首次实际 HTTP 响应损坏、后续恢复正常。旧版应复现 Retry；新版应只新增一次真实请求，随后到可操作 HOME→可信输入进关→玩法变化→正常存档。另验明确 HTTP 失败仍显示 Retry、第二次连接失败仍交给用户重试、十秒无进度仍结束请求、迟到回调不能第二次提交。检查浏览器网络错误正文，不能将服务器 200 单独当作客户端成功，也不能把连接层异常写成不存在的图片缺失。


## 以实际输入与业务就绪时刻计时（2026-10-25）

浏览器控制请求发出、工具 ACK、真实 touchstart/touchend 和游戏可操作属于不同时间点。处理 `TOUCH_END` 的开始按钮，以实际可信且坐标匹配的 touchend 为业务等待起点；同时记录 `performance.timeOrigin`、原始输入事件、只读渲染观察器首次发现关卡可操作及玩法变化的时刻。工具排队、长按尚未结束或 ACK 延迟不能混进“加载动画静止”时段。原始请求与 ACK 时间保留为工具耗时，不替代浏览器事件。

旧记录缺少时钟原点时，不猜测绝对时间、不回写旧时间戳修成通过。先声明针对受影响条件的新计划，补真实浏览器时刻后定点重测，保留原失败记录及原因。未改动且已通过的条件不因一次测量边界错误重演整轮。成品维护的局部结果要明确范围，不能替换为完整制作目录的全通过签章。
