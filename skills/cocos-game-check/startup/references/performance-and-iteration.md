# TikTok性能与证据驱动迭代

新游戏首版建立与目标相称的基线；出现卡顿、资源/场景变更或性能反馈时检查受影响场景。局部文案改动不自动触发全套长时间测试。沿用PERF-01实际帧间隔与可见更新要求，不改变catalog状态、适用范围或测试候选延期权限。

## 性能记录

为实际测量项记录版本/源与构建指纹、设备/系统/Runtime、方向/Canvas/DPR、场景和操作、冷/热启动、缓存/网络条件、工具/方法、采样时长、原始输出和局限。目标阈值由本作需求与真实设备基线确定并说明理由，不写所有游戏通用的固定FPS/内存/启动秒数。

| 维度 | 观察与测量 |
| --- | --- |
| 启动/加载 | 从哪个事件开始到首个可交互画面；首屏依赖、下载/缓存及失败重试；冷/热分开 |
| 可见流畅度 | 帧间隔分布/长帧、实际动作或属性变化频率；与原速度/动画规则核对，平均FPS不单独定通过 |
| 渲染/纹理 | 当前可用引擎工具报告的Draw Call、纹理尺寸/估算或实占；注明工具与估算方式 |
| 内存/长期运行 | 同一设备重复进入/退出和较长游玩后变化，资源/监听/计时器是否积累；不把Web JS堆当Native全部内存 |
| 场景/生命周期 | 进出玩法、重开、前后台、音频与广告后恢复；不能有旧回调/重复奖励或持续加载 |

工具不提供的指标写未测/受阻，不编数值。先保留问题基线，再做最小修复，在同设备/方法/场景读回；改过帧率/调度/资源后另核输入、声音、真实业务和原玩法速度。纯离线结果、单帧截图或另一设备的改善不能标当前手机流畅。原始数据留项目证据，不放玩家UI或Native包。

## 弱网与资源方案

按实际使用的本地/分包/远程资源测试不可用→可见恢复→恢复正确字节后继续操作，不拿降低玩法或跳过校验冒充加载优化。首包/分包和缓存限额在实际构建时核当前国际TikTok官方资料，记录日期；构建目录与实际Native/ZIP一致，使用现有官方离线/独立核包流程。

## 产品指标与迭代

只选能回答当前体验问题的指标：首局/关卡完成率、失败点、游玩时长、广告请求/展示/完整播放/实际入账、加载失败和崩溃。为采用项写清事件、分子/分母、时间窗/地区/版本和数据来源；广告完整率不能与奖励保存成功率合并。没有采集系统则只记方案未实现，本地诊断不能冒充线上留存或收入。

如当前已授权需要远程统计/云端功能，按项目真实数据与部署条件设计；否则不为指标新增后端、账号或上传数据。隐私/平台/发行材料只对实际涉及能力查当前官方资料，不把国内清单复制成TikTok结论。

每次迭代按“原始观察→具体假设→最小改动→同版复查→更新需求/任务/证据”推进。对外测试、上传、送审、发布和正式指标采集仍按用户当前授权与实际证据记录，不因写完清单自动执行。
