# 模拟测试逐按钮覆盖

用户 2026-11-03 要求：模拟测试时，每一个按钮都要实际点击并核对结果。此规则约束执行者的盘点、操作和验收；自动扫描只作为辅助，不能以扫描通过代替完整按钮覆盖。

## 范围与盘点

完整功能验收须覆盖当前游戏实际存在的页面和条件状态，包括首页、局内、弹窗、暂停、胜利、失败，以及复活后再次失败等会改变可操作状态的流程。按页面与状态清点，不以首页打开的一层弹窗为上限。不存在的功能不新增；相同控件和业务状态不乘以关卡数。

局部修复须逐个核对受影响页面上的按钮，并覆盖受影响的前后状态。其他页面可引用同代码、资源、依赖和有效检查口径的既有证据；未测过的项不能写成复用。不因本规则无条件重跑无关流程。

执行者必须亲自查看实际运行画面，先按玩家能看见的控件建立清单，再与节点、源码和自动扫描交叉核对。按钮外形、动作文字、图标入口、关闭 X 和条件出现的按钮均纳入；只有 Sprite、没有 cc.Button 或触摸监听，不能作为排除理由。画面上像按钮且写着 TRY AGAIN 的区域必须实点，不能因节点叫 title 就当装饰。确属不可交互标题/装饰的，须以实际画面和设计语义说明；“没有绑定”本身可能正是缺陷，不能用来证明不是按钮。

## 逐项操作与结果

1. 每个独立可见入口，在其适用页面和状态至少完成一次真实点击/触摸。两个外观入口即使共用 restart 回调，也要分别实点；只验证回调不能覆盖两个命中区域。记录实际输入类型，不能调用控制器、直接 emit 或执行处理器来充当按钮操作。
2. 点击导致页面关闭、跳转或新一局开始时，重新到达相同测试前态，继续点剩余入口；不能因第一个按钮离开页面就漏掉同页其他按钮。正常失败与复活后再次失败分别覆盖适用入口，不以一次 Retry 代表所有失败状态。
3. 每次操作核对明确的业务结果：重开后进入可玩新局且本局数据按规则重置；复活后保留规则要求的数据并能继续操作；返回到目标页；奖励实际兑现。声音、按压缩放、日志、回调已执行或没有报错均不能单独算成功。对无效点击按现有[无响应定位](button-state-check.md#无响应故障的最短定位)处理。
4. 条件按钮到达真实适用状态后再测。灰态/禁用态保留在清单，实点核对不执行业务及规则要求的说明，再测试适用的启用状态；不强改 interactable 绕过条件。到不了的状态明确标未测/受限，不能把它从清单删掉或写通过。隔离生产方法测试可作补充，不能冒充页面真实点击。

本轮按钮涉及的广告完成/取消/失败、输入边界等继续按现有适用规则执行；“每个按钮点一次”是最低覆盖要求，不替代这些业务分支。

## 证据与通过条件

沿用项目现有证据/报告，不新建第二套门禁。至少逐行保留以下字段，可放进现有 button-plan/button-run 或项目测试表：

| 页面/状态 | 控件 ID 与画面文字/图标 | 到达步骤 | 预期业务结果 | 实际输入与结果 | 截图/原始记录及当前版本绑定 | 结论 |
|---|---|---|---|---|---|---|

最终报告必须列出：应测总项数、本次实点项数、有效证据复用项数、失败项数、未测/受限项数。总项数按“入口 × 适用状态”计算；失败项是已执行项的子集，不重复加入总数。汇总满足：应测 = 本次实点 + 有效复用 + 未测/受限，三者不重叠。装饰排除项单列理由，不混入已测数。

范围内仍有未测/受限项，结论为覆盖未完成；存在无响应或业务错误则为失败。两者均不得声称该范围“所有按钮通过”，也不得作为完整功能验收通过后继续交付。用户明确授权的局部或带待验项测试包沿用既有范围规则，如实附缺口，不擅自升级为完整验收。测试耗时长、套件 passed=true、notRun=[] 或识别到的按钮全部点完，都不能证明视觉清单完整。

当前 button_sweep 主要按 cc.Button/触摸监听发现候选，默认只扫首页、一层弹窗及刚进入游戏时的入口，不能独立证明胜负/复活后页面与按钮图片均已覆盖。其无响应诊断和结果可复用；缺失入口由执行者按画面清单补测。通用自动发现未增强前，报告须如实标明这项人工补齐，不能宣称已实现全页面自动识别。
