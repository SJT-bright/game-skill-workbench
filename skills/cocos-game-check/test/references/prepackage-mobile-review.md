## 用户试玩入口

Ego Lite **只是** Agent 自己的检查工具，**从不是**用户的试玩入口（用户 2026-10-23）。用户要求可玩结果时，用 `serve_preview.py --keep` 起本地服务，自动请求独立 Google Chrome 手机框窗口并在回复里保留本地链接（真实 Cocos 页面），并说明方向、已核验比例和最少操作；不要求用户进入受限 Ego 窗口操作或回复画风认可才能继续制作。

1. 复用本游戏健康服务，核对准确 Web 目录、版本与 HTTP 字节，从无关 cwd 实际验证启动器。普通试玩不含 QA 或模拟 SDK；不清存档，也不覆盖用户正在进行的游戏。
2. Agent 在**本会话自己新开的** Ego TaskSpace（或 `chrome_touch.py` 新开的独立窗口）中单独完成手机模拟检查（被占就再新开一个，不等，见[被占就开新的](../../../remake-core/references/machine-load.md#一遇到被占用要排队立刻新开一个绝不等待用户-2026-10-23最高优先)）：在引擎启动前配置视口、DPR、方向、移动端 UA、触摸和鼠标转触摸，再读回 DOM/Canvas、maxTouchPoints、引擎能力及实际输入链。具体方法沿用手机触屏 Skill 的 [启动与触控核验](../../../mobile-touch-computer-use/references/computer-use.md#启动与触控核验)。
3. Agent 实际点按必要入口，有拖动玩法时验证拖动，记录触摸与可见结果。单纯窗口缩放、手机外框、固定比例 iframe 或 HTTP 200 不算触屏通过；已有同版有效交互可作基线，不重复跑无关检查。
4. 在 Codex 回复里给本地预览链接，说明横屏或竖屏、尺寸及操作方法；不要把 Agent 的 Ego 设备配置说成用户的预览已开启手机模拟。**不在 Ego 里打开、置前或 handOff 试玩页给用户**；Agent 的检查空间测完马上 `browser_slots.py close --name <线名>`。

用户反馈是可继续承接的输入，不是本地美术、功能、配置或测试候选工作的等待门槛。浏览器模拟仍不等于物理手机或真实 IAA，也不新增后台、上传、安装或浏览器升级授权。

## 默认顺序

整体顺序以[四个阶段](../../../remake-core/references/stage-flow.md)为准：下面的检测都在用户试玩验收通过、锁定美术和玩法之后进行；本 Skill 不做上传后的真机检查。

检测开始前（英化不换声音文件，两类声音设置照做），在共通部件设计环节落实声音弹窗新背景、两类开关/十格/10%音量、实时状态及首页两个语义图标和真实路由。随后按下列顺序检查；测试 ZIP 前复查当前范围，不能临打包才发现声音设置仍是测试面板或首页入口只有文字占位。

1. 从当前游戏真实 Cocos 工程导出 Web 和 Native 目录，建立功能表、版本和干净源码指纹。先检查公开配置、原免费流程和项目的最小启动回归，再进入界面测试，不先生成最终交付 ZIP。
2. 引用用户试玩前已有的美术自审与认可结论；锁定后不复审美术或重新评判受影响页面，只对后续变化引起的运行、输入和资源故障定点核验。按当前指定的触屏执行器完成适用的主视口按钮、功能与关卡抽测，第二比例核关键输入、重开及原门禁明确要求的双比例项目，不重复整份关卡抽测。发现功能问题直接修复并复查，继续已授权的功能和接入工作。
3. 本地必要检查与自动门禁通过后，直接生成并独立复查已授权的唯一 Native 测试候选 ZIP，核对字节、根入口、分包、公开配置和当前输入门禁范围；附版本、SHA与手机/真实IAA待验说明。用户未回复不阻断该候选工作。
4. 汇报 Agent 在浏览器里已检查了什么；本 Skill 不做真机，不给扫码清单。
5. 收到实际手机或 IAA 反馈后，修复并更新版本与清单；已有确认只绑定实际报告范围，不重复索取。只有实际验收证据齐备才将对应项目标为通过；候选交付、手机验收、平台接受及发布分别记录。

真实 TikTok 手机预览有时必须先导入或上传代码包。用户已要求测试包时，在 Agent 本地检查和必要自动门禁通过后直接建立并交付**Native 测试候选 ZIP**，记录 SHA、App和版本；（锁定后）不再等待 Ego 操作或真机结果才生成测试输入。它不能标成最终手机验收或发布完成。候选测试通过后优先保持相同字节、仅整理最终文件名并复核 SHA；重新构建导致字节或源码变化时，原测试绑定不能直接放行，按变化重新验证。

没有设备、权限或用户明确只要待配置/扫码前候选时，继续完成已授权范围，明确待验项目；不自动把缺项改成通过，也不擅自上传。当前用户明确允许跳过或改变顺序时以其指令为准。

## 关卡抽测：哪些关必须真实触摸

关卡多的游戏不用每关都从头点到尾。首次完整验收或关卡/核心玩法广泛改动时，按下面规则决定哪些关用**真实触摸验证玩法**；同版有效基线不因再次出包自动重跑（用户 2026-10-19 定的规则）：

| 关卡 | 怎么测 |
|---|---|
| 第 1–15 关 | 每一关都真实触摸玩 |
| 第 16–30 关 | 测一关跳一关（16、18、20……30） |
| 第 31–40 关 | 测一关跳两关（31、34、37、40） |
| 第 41–50 关 | 测一关跳三关（41、45、49） |
| 之后每 10 关 | 每段比上一段多跳一关（51–60 测一跳四，61–70 测一跳五……） |
| 最后一关 | 一定测 |

- **不要自己数**，运行 `scripts/plan_level_tests.py --level-plan <实际关卡表level_plan.json> --out <清单.json>`，按输出的关卡号测，清单放进测试证据。
- **被跳过的关怎么到达**：只能用"测试专用跳关"。做法二选一：①在测试用 Web 构建里加跳关入口，代码里必须带固定标记 `__QA_LEVEL_JUMP__`（例如读 `?qaLevel=N` 参数）；②在隔离的测试存档（新的本地地址或测试账户）里，按游戏自己的存档格式写入已解锁的关卡后再启动。跳关只负责"到达"，**不改金币、道具、奖励**，不调用玩法或发奖函数。
- **到了要测的那一关，必须真实触摸验证该关玩法**：开局、操作、正常完成及结算/进度，并核该关新机制或特殊失败。共用 Retry/Home/Next、广告的全部故障分支和坏存档矩阵按实际入口与机制检查，不在每个抽中关重复；奖励关/限定关、独立分包或独立奖励实现另列代表。
- **跳关入口不能进上传包**：正式 Native ZIP 里出现 `__QA_LEVEL_JUMP__` 时，`verify_native_zip.py` 直接判失败。
- 不在关卡里的功能（首页、礼盒、商店、皮肤、设置、各个广告入口）不受抽测影响，照常全部真实触摸检查。
- 已有完整基线、只改某几关时，改过的关一定测，再加真实关联关、相关历史故障关及所用机制首现关；不自动重跑无关基础抽测。用 `plan_level_tests.py --scope changed --changed-levels ... --related-levels ... --regression-levels ...` 生成带逐关原因的增量清单。没有完整基线、核心机制广泛改变或实际门禁证据失效时，按实际要求补完整覆盖。


## 新玩法首现关与必测清单（2026-10-24）

制作关卡表时，每个新玩法首次出现的关卡都加 `"tags": ["intro"]`；一个关卡介绍多个玩法时仍只需一个 `intro` 标签。推荐在使用该玩法的各关记录稳定的 `"mechanics": ["wind", "ice"]` 标识，使脚本能核对首次出现是否漏标。`new: true` 表示新增关卡，不能代替新玩法的 `intro`。

```json
{"level": 17, "tags": ["intro"], "mechanics": ["wind"]}
```

生成骨架时可用 `make_level_plan.py --intro 17:wind --intro 23:ice ...`；随后按真实关卡补齐玩法标识和全部首现标记，不照抄示例玩法或关号。测试前运行：

```sh
python scripts/plan_level_tests.py --level-plan <实际关卡表level_plan.json> --out <本轮必测清单.json>
```

完整基线清单为原逐段抽测规则、末关与所有 `intro` 关卡的并集，再补本轮修改关和相关故障关；`--scope changed` 的局部清单只补其受影响机制的首现关，不包含无关首现关。即使某个首现关本来会被跳过，也必须真实触摸完整玩过。脚本在终端和 JSON 的 `warnings` 中提醒：没有关卡表、全表没有 `intro`、或 `mechanics` 首次出现却漏标。看到漏标后回关卡表补标并重新生成清单；没有玩法标识时不能靠脚本推断全部新玩法，须对照玩法规格人工核对。提醒不算测试通过，清单也不算实际游玩证据。

## 已解决故障的最小回归

每次扫码候选与最终上传前按统一catalog及 [通用问题适用范围](../../../remake-core/references/feedback-regressions.md) 检查。广告与奖励逐实际入口展开，重点核完成判断、发奖、保存、失败恢复、重复/迟到结果和按钮状态；再核加载、重叠、生命周期、输入与同版产物。玩法机制只按本游戏实际功能选择，不迁移其他游戏的个性化改动。已知自动失败必须在创建ZIP前拦住；真实手机待验与自动失败分别记录。

使用 `mobile-touch-computer-use/references/cold-start-regression.md` 的方法，把已解决故障留成项目内可执行的小样例，连接现有构建和汇总打包入口。存档初始化至少考虑平台缺键/对象返回、损坏与不完整旧记录、有效余额/进度及合法已领；日期固定。相同检查须证明故障版失败、修复版通过，报告源码与本次实际编译包的 SHA；工具缺失、读取失败或回归失败都阻止创建上传 ZIP/交付包。游戏规则和断言留本项目，不把一款游戏的金额、关卡数或方法名套给其他项目。

离线方法调用只在独立进程/内存中做，不操作用户正在玩的页面；它不能替代下面的 Ego Lite 界面操作、真实手机和广告验收。新增反馈优先追加最小失败样例并复测受影响流程；不靠清存储或换文件名隐藏问题。项目已有的必要广告/触控回归继续执行。

## 接入手机触屏 Skill

在可用技能目录中查找并读取 `$mobile-touch-computer-use` 的 `SKILL.md`；同根安装入口为 [mobile-touch-computer-use](../../../mobile-touch-computer-use/SKILL.md)，实际路径从当前Skill目录解析。沿用其 Ego Lite、隔离预览、被动输入证据和清理方法。先读取 `ego-browser` Skill，通过官方 `ego-browser nodejs` 在本会话自己新开的 TaskSpace 执行（被占就再新开一个、不等待，新开前 `browser_slots.py sweep --close`；审查做完马上自己关掉这个 TaskSpace：`browser_slots.py close --name <线名>`）；不引入外部 Playwright 或独立 CDP 连接。官方 `page.cdp()` 可按文档用于手机视口和触摸输入，报告实际 transport。

该 Skill 默认由 Agent 操作 Ego Lite 模拟触摸，用户不代做浏览器 UI 审查；需要用户协助的真实 TikTok 手机检查另列。Ego Lite 模拟结果不标成 iPhone/Android 真机、原生输入转换、真实 IAA 或平台接受通过。

Ego 测试空间不存在/失活/被占时直接新建自己的空间接着测，不问用户（用户 2026-10-23 已长期授权，见[新开测试空间不用问](../../../remake-core/references/machine-load.md#一遇到被占用要排队立刻新开一个绝不等待用户-2026-10-23最高优先)）；只有 Ego 卡到没法准确测试才问是否改用 Chrome。Ego Lite 不可用时记录具体阻挡，继续离线检查；用户明确指定备用浏览器时再沿对应工具文档执行，不静默切回 Chrome。缺少触摸能力或原始证据标受限，不伪造事件，不调用游戏控制器替代操作。仅改窗口尺寸、手机外框或固定比例 iframe 不能算触摸通过。

## 一键入口的内容

项目内生成适合当前系统的 `打开手机检查.command` 或对应启动入口。调用本游戏已核对的 HTTP 启动工具，读回实际端口、Web 目录与入口，健康检查后通过 Ego Lite 官方 CLI 打开本目标 TaskSpace 的结果页；重复启动复用健康的同一服务；端口或空间被别人占用时新开端口/新空间，不替换、不等待其他占用者，不清理原存档或登录。

进入真正全屏的 Cocos 导出页面；根据当前导出结构读出入口，不猜固定 `game/index.html`。设备模式通过 Ego Lite 官方 Page API/`page.cdp()` 设置并读回，启动器不能假称已自动开启触屏。QA 如需被动观察器，只放在独立同字节副本，不改游戏方法、事件传播或存储；保留源/QA 差异清单，不进入交付。

首次输入可能触发浏览器全屏、改变画布位置；重读状态后再继续。保留实际 URL、构建版本、Canvas CSS 尺寸、viewport、DPR、maxTouchPoints 和 touchstart/move/end/isTrusted。只收到 pointer/mouse 事件就只报告对应输入，不能填触屏通过。

## Ego Lite 必检范围

- 加载、主页、设置、声音、英文文字/图片、完整按钮边界和遮罩；长屏不裁切 HUD 或底部入口。
- 共通声音页仅 MUSIC/SFX 两类；逐个真实操作开关、0–100% 全十一档及边界，读回十格/百分比/实际增益，另一类保持；重开页、实际刷新、切场及暂停/可测广告/前后台恢复。两比例看主题弹窗背景与命中，不把播放日志或非零 PCM 当实际听感；玩家页无测试/试听库。
- 免费开始、实际核心拖动/滑动/点击玩法、原有计分/道具/碰撞；胜利、失败、重试、暂停继续、返回主页及再次开始。不存在的功能标不适用，不为凑清单增加关卡。
- 每个可见及条件按钮：按下反馈、松手一次执行、拖出不执行、连点保护、遮罩不穿透、关闭可重开、死亡/暂停后仍可操作。系统取消/多指受工具能力限制时保留未测。
- 每个广告入口及缺 SDK 的说明窗口：可以进入和退出，不发假奖，不强制阻断原免费开始；真实完整播放、取消、广告填充/失败与奖励消费留给平台测试。
- 两个回访入口：房子表示 Add to Home Screen，个人主页/回访图像表示 Profile Revisit，分别实际点击/关闭/重开，核真实路由、资格说明、已领/错误、库存/使用及空库存反馈；不能混淆为普通 HOME、返回或账号登录，浏览器不能伪造快捷方式、个人主页回访或资格奖励。
- 有关卡的游戏列实际关卡入口、解锁/通关/下一关/重复挑战，覆盖早期引导、玩法变化及边界；大关卡集记录测试范围，不称全量通关。无关卡的无尽游戏检查本局前中后段难度与重开，不新增关卡。
- 本项目用户反馈过的缺陷：按实际复现步骤加入项目回归；只把可复用的机制提炼进通用清单，不要求其他游戏实现相同对象、规则或视觉改动。

实际检查后更新功能表。只有已到达、操作和读回的项目才能标通过；未到达的条件状态保留待验或使用明确隔离的 QA 场景，不能冒称自然通关。

## 给用户的清单必须是当前游戏的清单

按 [清单模板](../../../remake-core/assets/mobile-test-checklist.md) 输出项目文档，填入本游戏真实名称、构建版本、App、平台测试版本、测试输入 SHA 和设备。每行有编号、到达步骤、操作、预期和结果；新增广告表逐行列**触发位置 → 广告位 → 完整观看奖励 → 取消/失败结果 → 免费替代**。

已声明备用位但没有入口时明确“备用，无玩家触发入口”，不写成第三个已接入奖励。奖励不是只看余额：领取、刷新持久、消费一次、技能或道具实际生效都列入检查。开局和复活分别测试完整观看、提前关闭、不可用、重复点击；晚回调/超时先由实际代码及隔离测试覆盖，手机无法稳定制造时记待验。

主页快捷方式与个人主页回访单独列操作、资格检查及奖励规则，不能算成 IAA 广告。真实平台结果和本地说明分开。用户可直接按编号回复“通过”或问题编号、截图/录像，无需自己读代码猜测试入口。

清单结果默认 `待测`，允许 `通过 / 失败 / 受限 / 不适用 / 用户跳过`，不批量预填通过。用户反馈保存原话和对应范围；仅凭“试玩正常”不能填所有广告分支、两种手机或发布通过。未解决失败先修复，不生成最终完成结论。

## 与现有交付门禁衔接

仍执行 [手机输入六项门禁](mobile-input-gates.md)、[全流程功能表](../../../remake-core/references/process-gates.md)、广告配置编入核验（重塑包 remake-ads 板块） 和 [独立包复查](../../../remake-core/references/delivery-and-handoff.md)。Ego Lite 检查、手机用户确认和最终包检查分别留证，不能用新清单取消已有指纹/原始事件要求。

浏览器报告保存 `mode=browser_touch_simulation` 与 `physical_device=false`，手机报告按实际设备和来源填写。测试设备、真实广告、后台版本接受、送审与发布分别记录；测试通过不自动授权发布。本文只规定下一款游戏的默认流程，已结项游戏保留原包和用户结项记录。


## 累积故障逐项核对

在本流程之前读取 [累积问题清单与拦截](../../../remake-core/references/known-issue-checklist.md)，用固定ID生成当前游戏清单，双向核实际按钮绑定和所有领取入口。每个入口检查可领/请求中/已领外观、取消/失败/超时、重开/刷新/重复回调；余额、领取记录、按钮/红点分别断言。最小检查实际执行源与当前Native并接真实打包器，不只读既有pass报告。`check_known_issues.py --stage pre_scan` 缺项/过期/失败阻止新测试ZIP；物理手机和IAA项目仍按实际结果保留待验，不凭此脚本冒称真机通过。

## Windows迁移分支

Windows统一使用Google Chrome（谷歌浏览器），按桌面总控的新机就绪（重塑包 desktop-agent-orchestrator 板块）检测/准备。迁移包中的手机触控Skill与chrome-mobile-testing提供Chrome操作和依赖，不运行macOS安装脚本。手机环境须在引擎启动前设置，原始touch/引擎命中/业务状态与模拟边界均留证；缺工具标待验并继续其余已授权工作。


运动、横竖屏适配及相关反馈，另按 [手机连续状态与帧率检查](mobile-motion-state-review.md) 复核实际存在的状态迁移、时间单位、输入退出和末级效果；仍分别记录编译包、真实 Cocos、可信触摸与手机证据。
