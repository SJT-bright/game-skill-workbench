# 首轮试玩前的操作测速、倍速匹配与连续游玩

用户于 2026-11-12 要求，以后每款游戏先测操作速度，再匹配合适的倍速做连续游玩检测，并在首轮交给用户试玩前完成。英化在第 3 阶段执行，统一检查在首次交试玩前执行；第 5 阶段按依赖核对并沿用有效记录。只维护 Skill 时更新流程，游戏制作由对应任务执行。

## 先建立本作的操作和原速基准

在当前实际构建及隔离测试空间，识别本作的核心操作、状态变化和完成条件。按现有浏览器规则操作，结构化自动化使用官方 Ego TaskSpace 和真实触控链。校准实际显示位置、原始触控到达和业务结果后，测有效操作速度。

优化批量读取、连续执行和产品已有的输入排队。分别记录短时峰值、持续操作吞吐量、输入到达数和实际完成动作数，并检查按下、松手、取消及后续输入。接收一次触控、分数增加、角色开始移动都只是中间状态，完成结果须从实际玩法读回。状态读取策略用于机制连续性检测，原速可见操作用于判断玩家能否看清、反应及控制。

用优化后的操作方式跑原速完整代表路线，作为本作比较基准。路线按游戏实际定义，限时游戏覆盖本局至计时结束，关卡游戏覆盖代表关卡的目标、结束及下一次开始，无尽游戏覆盖已说明的连续区间和前中后段变化，回合制或消除游戏记录有效回合、落子、消除及目标进展。覆盖选择沿用本轮关卡和功能计划。

## 匹配操作速度与游戏倍速

从原速逐档提高候选倍速，在吞吐或覆盖下降处细测，选择仍能可靠完成本作路线且有输入余量的最快稳定档。按本机、本游戏和当前操作链实测，分别记录请求倍率与实际倍率。操作速度以完整连续区间的持续值为依据，短时峰值供诊断。

加速在内部宿主或测试会话中注入，保留正常小时间步，增加执行频次，并保留本引擎实际运动、碰撞、组件更新、调度、动作、场景切换与销毁顺序。按当前引擎核对时间步上限、重复计时器和物理子步。局部缩放某个 Scheduler、放大单帧 dt 或单改倒计时，可能造成各系统不同步或跨过碰撞窗口，须校准完整生产运行链。等待操作期间游戏时钟持续推进。

有统一游戏推进时钟的运行链，实际倍率用同一单调时钟下的游戏推进时间除以真实墙钟时间计算。纯回合制按有效回合、落子、动画完成及目标进展除以真实用时比较吞吐，并标明游戏时间指标的适用性。记录输入和页面切换开销、时钟限幅、积压以及外部等待。外部服务端、真实广告和网络回调继续按真实时间执行，加速观测保留其实际等待及真实返回结果。用实际动作、交互机会、目标进展、胜败和后续操作比较原速与候选档；覆盖指标和可接受偏差按本作机制确定并说明依据。

1.8 倍、95% 覆盖和 60 秒是 Rubber Monster 的一次实测案例。每款游戏独立选档和制定路线。若本作或宿主的实测可用上限为 1 倍，记录限制与对照结果，并按该速度完成连续游玩；测量或加速实现失败时继续定位具体工具、时钟或输入问题。

## 用完整连续游玩确认选档

短样本用于少量代表档筛选及拐点附近细测。已有明确的吞吐拐点和完整稳定结果后结束校准；新失败或相关依赖变化再补对应节点。最终在选定档位实际完成本作完整代表局、关卡或已定义的连续区间。随后通过真实结束页面免费重开或进入下一次游玩，并继续操作，核对状态重置与有效进展；连续轮次沿用现有重开、关卡和业务链覆盖要求。随机内容记录初始种子与后续随机流是否延续，状态重载与自然重开分别留证。

正常路线检查持续操作可推进且能到达预期结果，失败路线检查真实错误动作的后果，按本作适用状态衔接暂停、恢复和免费重开。保留原速完整主流程与必要的可见运动、输入反应窗口检查。已发现帧率、连点或碰撞边界问题时，按对应故障定点补验。

加速中发现误杀、卡住、输入积压、间距异常、无法结束或重开失效，先定位游戏与运行器，再修复并复验受影响路线。倒计时结束、开局成功或一次计分只证明相应节点到达，连续游玩结论须有全程实际操作和结果。局内广告复活、真实广告、网络及平台回访按各自现行规则执行，本流程的核心玩法与免费重开记录分别标明观察范围。

## 记录、复用与首轮交接

原始观测和汇总保存在项目已有 QA 目录，可使用 `docs/qa/continuous-play/`。沿用现有逐项记录及生产依赖，无需复制游戏案例的专用路径、节点名或运行器。汇总须能回溯以下实测内容。

- 候选身份、核心玩法、输入与计时依赖，实际宿主、设备视口、操作通道、运行器和时钟实现。
- 原速基准、测速优化前后的持续吞吐量、各候选档原始观测、请求和实际倍速、游戏时间及真实用时。
- 实际完成的动作或目标进展、原速与倍速的覆盖比较、选档理由、完整路线结果、错误和自然免费重开后的进展。
- 当前构建与原始证据的内容指纹、观察边界、计时钩子恢复以及测试空间和服务的收尾结果。

英化第 3 阶段在现有阶段计时中分别记录操作测速、倍速匹配和完整连续游玩节点。在正式交接前，AI 读取本作原始观测，核对本轮候选依赖、原速和选定档的完整路线以及重开后的实际进展，再打开用户试玩 H5。存在未测、失败或相关依赖失配时，报告具体节点并继续补齐。首轮链接回复说明本作采用的实测倍速、连续游玩范围、结果与实际用时。

同机、同操作链、同玩法和时钟依赖的有效记录按原增量规则沿用。换机、输入通道、玩法或时钟依赖变化时重新校准对应节点，覆盖变化涉及的路线。纯美工和无关功能变化按真实依赖复用，第 5 阶段读取已有覆盖并补缺；已交付游戏的局部维护按本轮授权和影响处理。
