# 《优化建议报告》模板（逻辑检查 review 模式；用户 2026-10-23 给的 Mahjong 报告格式）

> 写给做游戏的人，能直接照着改。只检查、不修改。每条都要有证据类型；"待验证"不计入必须修的数量。

## 0. 概况

- 游戏：名称、类型、版本/包名；原件 sha256：`<sha256>`（只在副本上测试，原件未改）
- 测试环境：Web 导出、预览端口、浏览器、两种比例（390×844、375×667）、日期
- 结论一句话：必须修 A 档 N 条，建议改 B 档 N 条，可以更好 C 档 N 条

## 1. 上传前必须解决（A 档）

### A01 标题（一句话说清会怎样）
- 证据类型：浏览器实际复现 / 故障测试 / 隔离复现 / 静态确认 / 待验证
- 位置：`assets/scripts/xxx.ts:123`
- 复现步骤：1. … 2. … 3. …（附截图/录屏编号）
- 影响：玩家会遇到什么（卡死、丢进度、重复发奖…）
- 修复建议：具体改法（对应规则 L-xxx）
- 验收标准：改完怎样算好（可以照着测）

（A02、A03…同上）

## 2. 建议改（B 档）

### B01 …（同样字段）

## 3. 可以更好（C 档）

### C01 …（可简写：位置、建议）

## 4. 修复批次

- 第 1 批（先修，影响进度和卡死）：A01、A02…
- 第 2 批：A0x、B0x…
- 第 3 批：C 档

## 5. 已验证正常的部分（避免误改）

- 例：胜利结算只发一次奖励（F02，浏览器实测，截图 shots/f02.png）
- 例：商店余额不足不扣钱（F14）

## 6. 测试边界

- 没测到的和原因（如：没有真机、没有平台 SDK、广告只用模拟器）
- 流程 F01–F20 里 untested / n/a 的列出来

## 7. 实例沉淀回归 R01–R09

逐项列适用机制、pass/fail/untested/n/a、证据层、实际观察、证据链接与当前绑定。完整记录写 flows.json 的 regressions，字段由 logic_regressions.py 定义。说明夹具预置的状态、真实触控范围、离线重演范围和运行配置路径/数量；不以旧测试数量替代当前版本验证。

## 8. 复现材料

- 原件 sha256、测试副本路径
- 测试脚本（故障测试服务、隔离复现脚本）路径
- 截图、dump、日志目录
- `docs/logic/logic-check.json`（静态扫描和流程结果）

## 9. AI逐入口广告模拟（F11/R04）

按[自动检测规则](../../cocos-game-to-english/references/automated-ad-simulation.md)填入本作实际结果。每个入口至少有看完、取消、失败、失败后重试记录；原超时/迟到/重复矩阵继续保留，未测不写pass。无广告时说明实际盘点范围和n/a理由。

|---|---|---|---|---|---|---|---|

证据绑定当前候选；模拟结果与最终上传包的模拟残留检查分别记录，不把模拟completed当作发奖生效或真实广告播放通过。
