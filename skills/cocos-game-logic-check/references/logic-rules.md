# 逻辑规则 L-*（用户 2026-10-23，两个板块＋验收评审通用）

来源：用户给的两份真实验收报告（Double Jump Duo 的 REPORT.md、Mahjong 的《优化建议报告》）。每条写：规则 / 对应流程（`logic_check.py` 的 F01–F20）/ 怎么查 / 怎么修 / 验收标准。自己做的游戏（重塑、英化）**全部照做**；审查别人的游戏按这些规则评，写进报告。

## 一、出路和标准按钮功能

标准游戏的按钮就该这样，缺了就是 A 档问题（用户 2026-10-23 原话："关卡内能够退出，设置能返回，失败页面有 Home 和重新开始，复活广告在下面单独一个"）。

| 页面 | 必须有 | 说明 |
|---|---|---|
| 关卡内（HUD） | 暂停或设置键 → 能 Continue、Restart、Home | 关卡里任何时候都能退出到首页，不用先输掉 |
| 设置 | Close/Back 回到打开它的页面；关卡里打开的设置里有 Home | 关闭后原页面能继续操作 |
| 失败页 | **Home ＋ Retry**（两个固定键）；复活广告（Revive/Continue with ad）**单独一个放在下面**，不顶替 Home/Retry | Double Jump：失败页只有 Retry 没有 Home |
| 胜利页 | **Home ＋ Next**；双倍奖励广告单独一个 | 末关的 Next 见第六节 |
| 弹窗（商店、皮肤、礼盒、奖励，以及明确保留的兼容功能） | Close 回原页面 | 关闭后底下页面的触摸恢复 |

- **L-EXIT**（F04 F05 F07 F09 F17 F20）：每个页面都有出路；两种比例下按钮都看得到、点得到。查：盘点按钮去向表，真实触摸逐个点。
- **L-BUTTON-FIXED**（F05 F06）：按钮位置和含义固定，**不随机交换**（Mahjong 失败弹窗 Retry/Continue/Close 12–15% 概率换位置，玩家会点错）。查：扫描 `Math.random` 附近改按钮位置的代码。修：去掉随机换位；需要测试不同布局用 A/B 配置，同一个玩家始终一样。
- **L-PLATFORM**（F15）：平台按钮（加桌面、侧边栏回访，以及当前明确要求的兼容功能）点了要有反馈：成功/失败提示，或者平台不支持时隐藏。没有点了没反应的按钮。默认模块不含排名、七日签到、更多游戏、分享；依据[融合政策](../../cocos-game-to-english/references/fusion-policy.md)核当前范围。review 只报告不修改，纯修复不借此删除明确保留的业务。

## 二、一局状态：暂停、离开、重开

- **L-PAUSE**（F03 F19）：暂停要真的停住：物理（`PhysicsSystem2D.instance.enabled = false` 或停步进）、计时器、生成器、动画、相机跟随；继续/重开时恢复。只改一个 `paused` 标记不算（Double Jump：暂停后角色还在掉）。切后台/失焦自动暂停，回来不跳过计时。
- **L-EXIT 清理**（F04 F20）：离开一局（Home、Retry、Next、失败、胜利）统一走一个清理函数：销毁本局节点（角色、绳索、道具、特效）、注销触摸、`unscheduleAllCallbacks`/`clearTimeout`、停止 Tween、重置相机和物理、清掉选中态。查：回首页再开局 3 次（两种比例各一遍），每次触摸有效、没有残留。
- **L-ROUND**（F02 F06）：结算只发生一次；Retry 回到起点，扣费和奖励一致。

## 三、异步回调要带局次

- **L-ASYNC / L-AD**（F11 F12）：每次开局生成新的局次 token（`roundId++`）；广告、加载、平台回调、延迟回调回来时先比对 token，不是本局的**直接忽略**（Double Jump：上一局的广告回调落到新一局，复活了新一局）。
- 广告每个入口跑完 6 种结果：完成、取消、失败、超时、迟到回调、重复回调——不重复发奖、不串局、不叠两个广告。
- **广告超时要安全恢复**（Mahjong A05）：超时后恢复按钮可点、提示"Ad not available"，但**不能简单把锁解开**导致可以连点叠加奖励；超时之后的迟到回调按 token 忽略或只发一次。
- **最后一秒竞争**（Mahjong A04）：玩家点了复活/加时广告的那一刻，失败计时要先冻结；广告结果出来再判定，结果唯一。
- **L-LOAD**（F01）：分包/资源/场景加载失败（404、503、不回调）要出现看得见的错误和 **Retry**，重试发新请求并忽略旧请求的迟到回调；加载有超时。只 `console.error` 就是卡死在 Loading（Mahjong A02）。

## 四、输入

- **L-INPUT-CANCEL / L-DRAG-EFFECT**（F13/R07）：两比例真实拾取→拖出原节点→合法落点，必须发生棋盘/位置/计数的正确变化。Cocos节点越界可能把正常松手改为 `TOUCH_CANCEL`，须核原始事件（如 `getEventCode()`），不能把正常落点一律回弹，也不能让真正系统取消提交。显示拖影偏移不改变落点；非法落点不变更、第二指不接管，下一次手势可用。具体观测见[实际互动与音频输出](../../cocos-tiktok-package-check/references/drag-audio-postconditions.md)。
- **L-HIT**：命中检测取**最上层**的一个就停止遍历（Mahjong B01：重叠的牌一次选中两张）；被盖住的不能点。
- **L-RULE-ONE**：同一个动作只有一套判定（Mahjong A03：拖动吸附和点选消除两套规则，结果不同）。拖动、点击、自动吸附最后都调用同一个判定函数。

## 五、进度和存档

- **L-SAVE**（F10）：当前关、最高关、货币、皮肤、道具、**声音/音乐开关和音量**都要保存，**启动时读回并应用**（Mahjong A01：存了最高关，刷新后从第 1 关开始；声音设置不保存）。后加载完成的音频也要按保存的设置播放/静音。
- **L-AUDIO-OUTPUT**（F10/R09）：声音设置必须影响实际输出；两类分别核0/中/满档、开/关、失败隔离与重试、关闭设置/前后台恢复。保留增益后PCM/录音与原始日志；音量值、播放标记不能替代有声。
- 存档读回要**校验**：坏 JSON、负数、超过关卡数、类型不对 → 用默认值并保留能用的部分，不崩；写入用 try/catch，写失败提示并保留旧数据。
- 存了不读、读了不存的键都是问题（扫描列出）。

## 六、关卡和模式

- **L-CONFIG**（F02 F08）：关卡配置完整：没有空槽、`null`、空对象，关卡数和配置条数一致，每关都能加载（Double Jump 第 85 关空槽）。离线脚本把每关都加载一遍。
- **L-LEVELS**（F08 F16）：最后一关之后要有全通关页（或明确的循环/无尽），**Next 不能反复重开最后一关**（Mahjong B02）。教程比第一关简单、能完成、能跳过。
- **L-MODE**（F18）：叫 Daily/每日/签到的，必须真的按日期：日期种子、每天一份存档、跨日重置、同一天不重复领；做不到就改名（Mahjong：Daily Challenge 就是普通关卡）。
- **L-LOOP**：没有无上限的同步循环（`while(true)`、`for(;;)`）：洗牌、生成、找可消除对要有次数上限和兜底（Mahjong：自动洗牌 `while(true)` 可能卡死主线程）。

## 七、经济和奖励

- **L-ECON**（F14）：奖励和任务**不绕过购买规则**（Double Jump：主页任务直接给了要花金币买的东西）；余额不足不扣钱、购买只扣一次、未拥有不能装备；奖励只发一次，数字变化和动画一致。

## 八、镜头和画面

- **L-CAMERA**：镜头跟随角色的所有可能方向（Double Jump：只能向右跟，向左走出画面）；镜头移动到的地方都有背景，不出现黑边/空白（背景铺满或加边界）。查：真实操作往每个方向走到底，截图。

## 十、实际缺陷回归（2026-10-23）

每次检查同时按[learned-regressions.md](learned-regressions.md)走R01–R08：L-CYCLIC循环列表反向多圈；L-SAVE-RECOVERY坏/部分旧存档真正恢复；L-LOAD-RETRY旧请求挂起后的新底层下载；L-CONSUMER先有有效消费者再消耗；L-BUTTON-EFFECT按页面和状态核业务反馈；L-POINTER主指归属与取消；L-RUNTIME-DATA实际运行配置与测试绑定。标准出口L-EXIT同时检查暂停重开和失败Home。详细判据只维护于该页，脚本缺项自动拦截build；静态疑点仍须读源码判定。
