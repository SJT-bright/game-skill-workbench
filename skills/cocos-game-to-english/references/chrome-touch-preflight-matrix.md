# Chrome iPhone 触摸预检矩阵

**浏览器用途规则（用户 2026-10-27 最新更正）**：Agent 代测使用 Ego 浏览器的 **Google Chrome iPhone touch** 模式，先按 `ego-browser` 绑定自有测试空间并取得当前 CDP 端点，再用 `chrome_touch.py --cdp-url <当前Ego-CDP端点>` 执行；固定 viewport/DPR/UA/has_touch，`input_transport=playwright_cdp_touch`。代测不启动本机独立 Google Chrome，不使用 `--user-approved-chrome --channel chrome`，也不因 Ego 不可用自动切换本机 Chrome。仅在完全交给用户亲自试玩时，使用本地固定手机尺寸预览并打开本机 Google Chrome。代测服务使用 `--no-browser`，不通过 `--keep` 提前触发本机浏览器；交接用户时再按试玩流程打开。Ego 测试结束由 Agent 关闭自有空间并核实；不接管其他会话。此规则替代此前“代测默认独立 Chrome”的规定，Codex 内置浏览器仍不作触摸通过证据。

适用：把本地预览交给用户前、玩法设计首次可玩确认、按钮/美术/逻辑修改后、Native ZIP 回解本地启动后。执行器固定为Ego 浏览器的 Google Chrome iPhone touch + `chrome_touch.py --cdp-url <当前Ego-CDP端点>`；Codex 内置浏览器禁止作为 Agent 触摸测试器或通过证据来源。

## 预检原则

AI 先完成可由浏览器模拟稳定复现的触摸和异步入口，用户再补充物理手机、TikTok 容器、账号地区、系统手势、真实广告和平台能力。预检通过只表示浏览器触摸链和当前业务结果满足矩阵，不表示平台或真机通过。

每次预检绑定：构建版本/ZIP SHA、`device=iphone_15`、viewport 393×852、DPR 3、Chrome 版本、`input_transport=playwright_cdp_touch`、实际触摸事件和业务前后状态。需要短屏风险时增加 `iphone_se` 运行；不以旧坐标或 Codex 鼠标点击复用证据。

## 固定案例

按当前页面实际存在的入口执行；不存在的入口记录 not_applicable 及源码依据。

1. 冷启动：首页首个可见按钮中心触摸，确认页面或玩法真的变化。
2. 每个可见按钮：中心点击、偏心点击、按钮边缘点击；确认一次业务结果，不只看 pressed 状态。
3. 弹窗：打开、关闭、关闭后重新打开；确认同次松手不穿透到底层。
4. 触摸取消：按下后滑出按钮再抬起，确认不提交；再次新触摸仍可用。
5. 连点：快速两次或请求中再次触摸，确认不重复打开、不重复发奖、不永久 busy。
6. 拖动：`touchStart → touchMove* → touchEnd`，确认对象移动；触摸中 `touchCancel` 后确认旧触点不提交、新触点可用。
7. 返回/重试/暂停：打开后返回、暂停后恢复、失败后 Retry、结算后 Home/Next；每次均从真实当前页面操作。
8. 状态条件：零库存/不可用、可领取/已领取、请求中、失败、取消、超时；必须显示当前状态或可操作的恢复路径。
9. 激励广告入口：未点击前 SDK 调用数为 0；点击后进入等待；取消/失败/超时不发额外奖励且按钮恢复；完成回调只兑现一次；迟到回调不改已离开页面。
10. 加载异步入口：资源慢到、失败 Retry、关闭弹窗、返回页面后旧回调不得覆盖新页面。
11. 设置/声音：开关、加减、关闭后重新打开，确认数值真的变化并保存到当前测试存档。
12. 前后台短检：触摸按下后页面隐藏/显示，旧触点不提交，新触摸可以正常操作；只在工具能产生可核实事件时标通过。

## 发现问题时

保留首条异常、触摸事件、按钮/节点命中、前后业务值和当前页面；区分输入未到、命中错误、遮罩拦截、业务守卫拒绝、SDK 不支持、回调丢失和奖励消费者失败。先在 Chrome 触摸层复现并修复，再用同一版本同一矩阵复测；不能用 Codex 内置浏览器的鼠标点击替代。

平台能力不存在时必须给玩家可见反馈，并记录为 platform_capability_unavailable；这不等于按钮无响应，也不能用“本地模拟成功”冒充真实广告或 TikTok 成功。只有没有业务提示、触摸事件已到、守卫和平台能力满足仍无结果，才记为按钮故障。

## 交付边界

矩阵完成后才交用户本地预览链接。链接是用户体验窗口，不是 Agent 的测试证据；用户不需要自己再做一次已经由 AI 完成的浏览器触摸短检。用户只需在物理手机/平台环境补测 Chrome 无法覆盖的范围。
