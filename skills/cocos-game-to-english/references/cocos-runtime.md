# Cocos 构建与运行

新建工程或调整模块边界时按[工程与国际TikTok职责](architecture-and-platform.md)确定实际依赖/路径；首版性能基线和卡顿/资源变更按[性能与迭代](performance-and-iteration.md)记录当前设备、场景与方法。沿用已有工程结构，不新增其他平台构建，也不把抽象接口当实际SDK或引擎验收。

原工程声明是首选版本。Dashboard 已安装/登录与工程可运行是两件事；先核实本机编辑器，避免重复让用户安装。2.x 工程常有 project.json 和 Game.fire；3.x 工程通常有 package.json、game.scene、TS 与资源 bundle。需要更新版本时保留原工程，在副本完成迁移。

## 先验证 Native 启动到首关

（本地版 2026-10-19 复盘合入；2026-10-21 用户确认：不用 TikTok 开发者工具，测试在浏览器里做）接入已有源码、迁移引擎，或改平台桥接/入口/加载链时，**在批量生图和铺关之前**由组装线做这组最小检查。这是阶段 1 的"少量技术检查"，不等锁定后的测试，也不提前出交付 ZIP。新建游戏在第一个可玩骨架出来时做。只改图片等不影响启动的修改，沿用上次结果。

0. **两种导出都要成功**：同一份源码分别导出 Web（web-mobile）和 TikTok 小游戏（Native）两份，构建无报错；Native 导出跑一次 `verify_native_zip.py` 查结构（根目录 game.js/game.json/project.config.json、App ID、包大小）。下面两条在**浏览器**里用 Web 导出跑（独立 Google Chrome iPhone 触摸模式用 `chrome_touch.py --user-approved-chrome --channel chrome`），**不找、不问 TikTok 开发者工具**；电脑上已经装好能直接打开时才顺手用。Native 包在真实 TikTok 里能不能跑不在本 Skill 范围（不做真机测试），这不算"受阻"。
1. **正常链**：用独立测试存档冷启动，到首页能点，再实际点进去玩完第一关，确认完成状态和存档读回。不能用内部"直接通关"函数代替操作。
2. **失败链**：让一个首页必需的资源失败或不返回，确认不会误报"启动成功"、能看到提示和 Retry；恢复资源后点 Retry 真的回到可操作的首页。不自动无限重试，不清用户存档。

**"启动完成"由首页确认**：引擎回调、主场景加载完、资源请求返回、加载动画结束，都不单独代表成功。首页必需资源（含设计要求的声音）就绪、按钮建好能点、加载遮罩移除、真的画出来了，才算 ready。失败/超时/销毁不能发 ready；旧尝试的迟到回调不能完成新尝试；重试不重复初始化已经在跑的引擎。

旧平台代码先查实际运行时的平台字段、缺失常量和 SDK 方法是否真的存在。不能用 `browserType == 某旧常量` 判断平台：两个都缺失时 `null == undefined` 为 true，会误判。不要把另一个 Cocos 大版本的入口/适配器直接搬过来当修复。编译通过、ZIP 结构对、模块用例通过，都代替不了上面的正常链。

启动链的强制写法见[启动契约](startup-contract.md)；上面的基线检查之外，可选接口缺失、图片不回调、声音失败这几种故障也要在浏览器里跑（见该页第二节）。

## 命令行陷阱

- Cocos 2.4 使用 `--path PROJECT --build 'platform=web-mobile;debug=true;...'`；实际目标和启动场景仍须从日志与产物核实。
- Cocos 3.8 使用 `--project PROJECT --build 'platform=web-mobile;debug=true;buildPath=PATH;...'`。复杂选项可用官方 configPath 配置文件。不要默认 JSON 字符串在所有补丁版都按 JSON 解析：以实际日志的 platform/buildPath 和输出文件为准。
- 3.8 官方成功退出码是 **36**；32 为参数错误、34 为构建失败。成功码仍须结合产物、资源和实际运行判断。
- 不要把 Web 导出覆盖 Native 导出；每次构建指明独立输出目录。系统信息服务网络报错与资源构建错误分别核对，不称日志完全无错误。

官方资料（实际使用时按版本重核）：
- [3.8 命令行发布](https://docs.cocos.com/creator/3.8/manual/en/editor/publish/publish-in-command-line.html)
- [2.4 命令行发布](https://docs.cocos.com/creator/2.4/manual/en/publish/publish-in-command-line.html)

## 运行证据

真实 Cocos Web 导出通过 HTTP 加载，避免 file:// 资源限制。桌面横屏导致竖屏游戏看不全时可以在导出之外加竖屏容器，但不重新实现游戏 UI、不改变游戏节点。启动服务保留到用户试玩完成。

竖屏容器只是体验方式；固定比例 iframe 即使放进窄屏也没有测试手机全屏的相机/Canvas/输入比例。按 [手机输入门禁](mobile-input-gates.md) 另开真正全屏 Cocos 测试，记录 frame/Canvas/DPR，执行包内 Native 原始事件转换和实际触控。2.x/3.x 的输入方法按真实安装版核实；死亡或暂停之后检查原始触点仍能到达按钮，浏览器结果不扩大为手机结果。

检查动态 Label、图文、字体、Spine、图集和 bundle 全部成功加载。视觉验收看原版/英文版对应页面；交互验收使用实际鼠标/触控，允许用运行状态定位按钮和读剩余时间，但不要仅调用内部通关函数声称手动通关。需要自动化补充时记录真实点击与调试辅助各自范围。

改动审计应包含：源码 SHA 差异、所有图片/meta 保持或明确文字变化、场景非文字字段/几何、关卡配置。纯文本差异优先精准替换序列化字符串，避免把整个 prefab 重新格式化后宣称只有文字差异。

本地预览服务停了与编辑器未安装分开诊断：先确认当前版本与服务目录，恢复对应 HTTP 入口，不默认要求重装 Dashboard/Creator 或换 Windows。纯图片反馈修复可按 [原画风与反馈修复](artwork-and-feedback.md) 做局部差异与实际背景组合检查。

## 编译导出包与预览入口

只有已导出Native/Web包时先记录基线指纹、模块定位和canonical补丁/整合入口，不假称可编辑Creator工程。后续修复必须进入当前整合链；历史一次性生成器可能覆盖新修复，未核对不得重放。精确锚点及预期命中次数、已应用识别和隔离候选先验证，重建逐文件对照，再提升current；不要手工改测试断言使新包过关。

预览启动记录服务目录、端口/进程归属、实际Runtime指纹、比例/DPR与输入坐标；先确认页面加载的是本版字节，旧标签页必要时刷新。QA与用户试玩实例分别归属，不停兄弟游戏服务、不清用户存档。物理renderer/RenderFlow参与世界坐标或物理更新时不为加速关闭；加速协议先与原引擎轨迹/业务结果对照。
