## 独立解压与版本一致

出包前确认 [Native 启动到首关](cocos-runtime.md#先验证-native-启动到首关)的结果对应当前版本：启动相关代码或资源改过就重跑，没改过就沿用；不拿别的 Web 或旧 Native 的试玩当证明。最终 Native 和回解后的 ZIP 全字节一致。

校验最终上传 ZIP 的 CRC、路径安全、全量 SHA，解压到含空格的独立目录，与实际 Native 全字节核对。内部同版 Web 从无关 cwd 启动，核对权限、参数引用和资源 HTTP 字节；源码、Web、Native 来自同一最终版本。只有用户另要源码试玩总包时，才核对其内 Native 与单独 ZIP 同字节，并从总包解压后的启动器实际试玩。构建记录、模拟记录和本版 UI 证据分别标记。

先按 [全流程覆盖与交付检查](process-gates.md) 核对本版功能，尤其是两个主页入口的 SDK/奖励/实际消费；不能用 ZIP 结构正确代替功能完整。按 [全英文及 UI 重构](english-ui-rebuild.md) 对同版源/Web/Native及回解 ZIP 重跑中文候选检索，核全部文字图片/帧、真实页面状态与全 UI 生图绑定；`UI-01`/`ART-01` 未完成仍按原门禁阻断，不能仅凭英文目录名或静态零命中签收。构建工具显式指定项目、配置模式、版本与输出位置；打包前读回实际配置路径，防止复用脚本时带入旧游戏或旧应用。最终提供文件前确认路径存在且 SHA 对应已验版本，重命名以内容识别，旧记录路径不能直接照抄。

缺 game.json 时先查对方传的是源码/网页总包、套了父目录，还是构建漏文件。修正输出和根目录结构，用正确平台构建重打；不能在 Web ZIP 里补个空 game.json 冒充 Native。

### 用户另要 Cocos 源码

交付的是对应已确认构建的可编辑工程，不能用当前同名目录或早期源码总包冒充。先对照该构建的净源码文件清单及整体指纹，核 `project.json`、`assets`、`settings`、原 `.meta`/UUID、构建模板和工程所需声明/扩展；排除 `library`、`temp`、`local`、生成输出、QA、凭据及系统垃圾。源码 ZIP 与 Native 上传 ZIP 明确区分，不因源码归档触发重新出平台包或全量玩法验收。

若工作目录缺文件，先记录缺失项；从同版保留工程、原始生成资产或历史归档中按既有 SHA 恢复到独立交付副本。不得重生图、重新指定 UUID、仅靠文件名选近似图，或用可运行 fallback 隐藏缺失。恢复后须与已确认净源码指纹一致；不能证明时如实标明哪个部分未能对应，不宣称原字节同版。

说明放在工程目录之外，列准确 Creator 版本、导入目录、启动场景、公开配置位置及必要的本游戏构建适配。不要附带接受失败的历史打包旁路。将最终源码 ZIP 独立解压至含空格目录，核 CRC、安全路径、文件清单及全文件 SHA，再确认工程净指纹不变。只整理源码、报告或 Skill 时说明游戏未修改；不擅自启动、重建或永久保留测试浏览器。

已安装并可用的 Cocos 不要求重装；本地服务停了就恢复对应游戏服务，不把它说成编辑器没装好。macOS 已验证的流程无需另装 Windows；仅在确有平台专属依赖时说明原因。必要软件缺失才提供已核对的官方下载入口，说明是打开工程所需还是试玩所需，不让用户自行猜版本。参考 [Cocos 运行](cocos-runtime.md)。

## 验证状态

生图后须按 [全量视觉巡检](full-visual-review.md) 保留全部可见图像/显示位置覆盖、实际原件与页面状态、缺陷修复及复查。`ART-01`和`UI-03/05/06`需要实际GUI，未查看、未到达或已发现问题未修复时不填通过；不能拿生成图、资源路径、源坐标或静态零命中代替此阶段。纯图片变化复核受影响组合及中文，几何/层级变化补实际命中与功能。

按证据报告源码/英文、Agent 美术与功能检查、用户反馈（如有）、公开配置、Cocos/离线检查、DevTool/Mock、真实手机、IAA、后台上传和发布；有待办只列实际缺项及负责方。“填完 ID”“已创建应用”“可选择上传的格式”和“真实广告播放/发布完成”不能合并成一个完成结论。

交付前执行 [手机输入门禁](mobile-input-gates.md) 的 **code 模式**（`audit_mobile_input.py --stage code`，绑定最终源码指纹与 ZIP SHA），再加 Google Chrome iPhone touch 两种比例的真实触摸检查。本 Skill 不做真机测试，不问用户有没有手机，也不因为没有真机记录而停止出包；汇报写"浏览器模拟已通过"，不称手机验收通过。用户之后自己在手机上发现问题时，以手机现象为准重新定位。

已有 App ID、公开 Client Key 和广告位时，不登录或打开 TikTok 后台，直接完成已授权的工程、接口、构建与本地打包；后台账号/组织访问权限不是这些工作的前提。只有用户明确要求后台操作时才进入对应流程。实际变现资格/认证由发行组织办理；不要求个人开发者先开企业才能处理源码，也不承诺个人账号已具备变现权限。后台未核实不等于配置无效或广告失败原因。手机扫码按当前官方工具流程记录；没有设备或用户明确跳过真机时，完成已授权的扫码前代码、配置、构建及可做检查，保留真实手机/奖励/IAA待验，不能伪造通过。

本 Skill 出包时同时交付同版本地试玩链接和一个 TikTok 上传测试 ZIP，附最少必要的验证/待办状态；不包含老板、客户或聊天转发汇报文案。不省略内部英文化、真实试玩、平台接入和核验步骤。
