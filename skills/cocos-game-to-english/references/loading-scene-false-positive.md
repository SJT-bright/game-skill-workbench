# Loading场景正常不等于首页启动完成（2026-10-25）

## 已确认事实与推断边界

只有背景或加载界面、未出现可操作首页，只能证明启动未达到业务就绪；不能据录像直接确定平台 API、资源分包或存档是唯一根因。先核实际入口首错和阶段，检查必要资源/界面初始化的等待、可选任务是否阻塞，以及加载遮罩是否以真实首页就绪为退出条件。将已复现缺陷、源码风险和平台待证原因分别记录。

工具漏检：旧audit_native_startup_renderer可接受场景active、WebGL和errors为空，却未要求HOME可操作和进关触摸有效。静态require闭包、ZIP/CRC、模块桩、Web跳过原生adapter都不能填补此缺口。

## 针对性解决

1. 在入口、adapter、engine之前安装首条异常记录，保存message、stack、阶段、当前尝试ID、资源/请求ID；记录unhandled rejection，首条不被后续错误覆盖。不要输出凭据或完整私有存档。
2. 资源、场景、UIManager.init、存档恢复、可选初始化、Menu显示分阶段记录。必要任务失败有可见原因与手动Retry；音频/广告/统计等可选任务抛错、拒绝、不回调不阻断HOME；不得统一吞掉必要任务错误。
3. 前台连续无进展超时（按startup-contract）；后台暂停，进度前进续期。Retry新请求/代次，释放失败任务，保留有效缓存，旧结果不得切场景。不要强制进度100%或直接隐藏Loading。
4. HOME必须首屏资源就绪、加载遮罩消失、PLAY可操作；实际触摸开始并产生玩法变化后才算完整启动链通过。

## 最后测试阶段的证据

重塑、英化/美化、逻辑修复最后测试必须检查最终Native入口/adapter/engine/scene的真实链，不以Web替代。正常冷启动与慢网有进度对照；必要资源报错/无回调；可选初始化抛错/拒绝/不回调；Menu/UI初始化抛错；原超时回调被扣住；手动Retry后新请求、旧回调隔离、玩法触摸变化。只对本轮相关启动机制执行，不扩成无关全游戏CI，不要求已锁定美术再测。

复用loading-recovery-regression的执行器与可信runner，原始日志/帧和报告绑定最终Native树。实际平台视频出现具体失败，即使历史CI通过，也对该故障局部修复和复验；不让“成品不重跑CI”豁免已知启动故障。

## 工具可执行约束

`audit_native_startup_renderer.py`现调用`startup_business_contract.validate_business`。raw必须含business.home（visible/required_assets_ready/loading_overlay_gone/play_interactable/node_path/at_ms）与business.play（touch.transport=ego_page_cdp、touch.at_ms、level_ready、level_identity、before/after非空且不同、effect_at_ms），顺序HOME≤touch<effect；first_exception非空拒绝。缺字段不得N/A，旧runner需记录真实观测，禁止补常量来适配。

`selftest_native_startup_renderer.py`对真实报告重签raw后删business、保留遮罩、取消玩法变化、藏首异常，必须拒绝；防止只因哈希不匹配而拒绝。`test_startup_business_contract.py`只校准检查器，不是游戏运行证据。完整工具自测必须包含旧检查遗漏对照、最终检查拒绝反例、正常证据通过，分别报告。

轻量出包的audit_upload_startup仍只给静态闭包结论，不声称Native运行通过；2026-10-26起每次新测试包另强制执行[最终启动与恢复门禁](final-package-startup-gate.md)，不因此重跑无关全CI。正式完整启动门禁经audit_startup_contract调用真实renderer验证；现有未提供业务观测的runner会被拒绝，需要按真实观测升级，不能绕过。


### HOME半初始化与平台替身边界

视频只有背景、Loading已消失不能判作同一根因。Cocos可能捕获onLoad/onEnable错误后只打印，外层toggle不抛错且node.active为真；禁止据此ready并撤看门狗。检查本游戏HOME必要组件已初始化、关键按钮可见可操作、必要纹理就绪，并跨真实绘制帧复核；截取启动期引擎错误和首条异常，失败保留阶段、版本及可见恢复出口。反例用“root active但onLoad未完成”，同一检查必须拒绝，正常首页须通过。局部源码节点检查仍非实际渲染证明。

电脑Native host仍替代了TTMinis、文件、图像、存储与调度；原入口/adapter被执行不等于真实手机环境相同。反例只证明该缺陷可发生，不证明它是手机本次唯一根因。手机再失败时先核包版本和首条平台错误，缺日志时交明确标识的诊断候选并说明未定根因，不连续猜修后宣称彻底解决。只补对应启动链测试，不重跑无关CI。

### Native宿主差异不能由浏览器补齐

实际入口须覆盖：`GameGlobal/globalThis/window`分离或缺别名、`tt/wx/TTMinis.game`单独存在、方法与`env`分散、WASM及引擎/adapter导出跨全局；保留真实对象/接收者，只补缺失别名。测试不得走预览专用分支；桥补齐项逐项披露，不能当手机通过。入口先装版本/阶段/首异常栈与rejection记录；必要失败可见，不撤Loading假装成功、不取主Canvas的2D。

共享`audit_upload_startup.py`对已登记入口执行`probe_native_host_boundary.cjs`，同一判据须旧包失败、修复及正常对照通过；正式/轻量writer和最终ZIP共用拒绝。其他引擎按实际宿主补登记，不扩全游戏CI。无手机首错只交标版本的诊断候选，不把可复现风险称为录像唯一根因。

### 首页全按钮无响应：共用就绪锁与伪 DOM（2026-10-26）

HOME已画出但全按钮无响应，先同时记录宿主触摸→引擎命中→回调→共用ready/failed/pending锁及首错，不能直接认定SDK触摸丢失。小游戏有document不等于HTML可显示：启动锁的失败/超时若只用DOM提示和Retry，会留下“可见首页、永久禁用、无可用出口”。此类恢复必须用当前宿主实际renderer与真实输入验证；重试完整初始化，不直接把ready置true。用准确旧包与同一加载失败/无回调反例，检查器须拒绝“失败锁仍在且无可见可用恢复”，正常输入和恢复后输入须通过。Web补齐DOM或跳过adapter的成功只记对应边界；缺手机首错保留诊断候选，不宣称唯一手机根因已解决。

## 启动资源生命周期与失败任务重试清单（2026-10-26）

检查时机：每次最终Native启动检查，按当前包实际存在的机制核以下项目；修改入口、分包、加载UI或用户报告扫码后进不去时，对受影响项补失败→恢复回归。首次只交原版试玩仍按成品Skill最短入口执行，不因此扩为整轮CI。本文是检查判据，不表示静态verifier已能自动识别所有运行故障。

| 检查项 | 提前发现的方法与拒绝条件 | 修复后须确认 |
|---|---|---|
| 切场景时释放加载资源 | 检查 `runScene` 等异步切换与 SpriteFrame/Texture/字体/图片释放的先后；跨旧场景最后一帧和新场景首帧采集首异常。加载节点仍激活/可渲染却先 destroy 资源、出现无效纹理或 `updateUVs` 异常，均不通过。调用切场景返回不能当作旧场景已经退出。 | 先让引用者退出渲染或解除引用，再安全释放；共享资源核其他使用者。正常冷启动和失败页→Retry切换均无失效引用。不能靠永不释放、屏蔽异常或删除绘制逻辑充作正式修复。 |
| 缓存的初始化Promise失败后永久复用 | 清点引擎init/run、场景、UI与资源加载缓存；分别令实际初始化同步抛错、异步拒绝。Retry必须产生新的可观察初始化调用，不能再次await同一已拒绝任务。请求不回调时也要核超时后的状态，不能仅测reject。 | 失败清理与代次绑定；旧任务的catch不能清掉新任务。按引擎重入能力选择安全重试阶段，不能机械对所有init置null。超时重试须隔离仍在执行的旧任务，不能并行重复启动引擎。 |
| 分包/图片任务的失败恢复 | 从真实首页资源表展开请求、分包名、路径与类型；逐项核存在及所需体积。下载报错、不回调、图片decode失败/不回调分别注入外部边界；不得把失败任务或失败图片记入成功缓存。 | 可见可操作Retry产生新请求；保留已完成有效缓存，旧回调/重复终态不能换场景或污染新结果。慢网有进度时不误超时，后台暂停计时。不能用历史游戏的分包数、字节量作通用门槛。 |
| 宿主API与全局对象 | 在实际adapter前核所支持平台的 `tt`、`TTMinis.game`、`GameGlobal/globalThis/window` 分布及实际方法接收者；浏览器预先补全的全局必须记录，不能掩盖原入口缺口。 | 只补确认支持的缺失别名，不覆盖现有真实SDK；按实际入口执行正常宿主与对应缺别名边界。替身执行仅记入口合同，实际adapter/引擎证据另核。 |
| 加载/失败页尺寸与点击区 | SpriteFrame赋值、sizeMode变化可能重置UITransform；以最终渲染尺寸与实际点击区为准，不能只读节点创建时的目标尺寸。 | 正常加载帧、真实失败帧中进度/提示/Retry不裁切且尺寸正确；真实点击一次Retry→首页→开始→玩法变化。不能在失败回调中直接调用start代替点击恢复，也不能仅看失败页截图。加载样式沿用[统一Cocos规则](cocos-loading-screen.md)，不重新评审游戏美术。 |
| 同版与缓存绑定 | 更新本地服务文件不等于浏览器执行了新版本；记录实际入口/业务脚本版本或指纹，并确认本次加载使用它。 | 再核正常与失败恢复，不沿用缓存旧逻辑的测试。更换查询参数或禁用测试缓存不清用户存档；Native运行证据仍绑定最终Native字节。 |

已知缺陷可取得旧包时，同一判据应先命中旧故障，再验证修复与正常对照；无旧材料如实保留缺项，不构造假的历史通过。最少完成业务后置条件：HOME绘制且可操作→真实触摸PLAY→玩法状态变化；恢复路径也到相同终点。首异常保留，即使后续恢复成功也不抹去注入失败记录，另列是否产生新增异常。

证据分别记录：文件/资源闭包、入口/模块替身合同、浏览器兼容层、实际Native adapter与引擎、手机平台扫码。不得把一层提升为另一层，也不得把某个本地可复现风险写成其他游戏或手机录像的唯一根因。游戏私有输入、日志、截图及数值放项目证据，不复制进通用Skill。

### 平台封面无入口回执（Bamboo V57再次反馈，2026-10-26）

手机持续停平台封面且没有游戏诊断，先区分包下载/解析/入口未执行与游戏内部启动失败，不能继续拿同一浏览器通过推定手机根因。入口执行回执应在首个业务/诊断依赖之前建立；此处为登记入口的出包拒绝项：程序在加载依赖之前读取回执，核真实build/stage及原异常name/message/stack，禁止catch后补回执、改写首错或以弹窗出现替代记录；探针缺失、失败或证据缺项拒绝，未适用不能记通过。对诊断依赖缺失、解析异常用实际入口注入，旧版须暴露漏报，修复及正常对照通过。包内代码不能捕获自身解析前或平台未派发的失败，这些必须取平台日志/实际包版本确认；原生提示也非入口已执行的唯一证据。重复扫码失败保持未闭合，不以修复定位盲区关闭手机问题，不连续交猜修包让用户试。最新门禁通过与手机反馈闭合分别核实。

共享静态入口探针按实际协议分流：Bamboo能力桥的SDK命名空间/首错模块反例，仅由已登记的平台模块指纹或实际入口协议写入识别，不能仅因通用文件名相同而要求其他游戏复制私有变量。注释、说明字符串和未执行示例不声明协议。已知旧桥入口即使缺首错回执仍须命中原反例；其他游戏仍执行其真实启动、首错和失败恢复判据，不把专用单元探针未适用写成已验证。

### SDK 事件缺少注销方法的启动兼容（2026-10-27）

对已登记的真实平台桥，注入“注册方法存在、注销方法缺失”，不得因此隐藏可用的注册方法；有完整配对时仍选同一 SDK 接收者。真实 adapter/引擎若要求的注册方法本身缺失，应保留原异常类型、堆栈和阶段，不能造空方法冒充支持。旧版反例、修复版、配对正常对照均须运行；浏览器 shim 不得自动补齐被测缺失方法。

### Native 场景就绪上报与平台封面（2026-10-27）

Native 首屏进入真实可交互 HOME 后，若平台提供 `reportScene`，必须调用 `reportScene({sceneId:9999})`，记录成功、失败或不支持及版本/阶段；异步回调须记录最终阶段并只接受首次终态，入口回执版本与实际构建一致；只在本地标记 `home-ready` 不等于平台已收到上报；官方资料未证明上报会关闭平台封面，不能将其缺失认定为封面卡住的根因。旧入口缺回执、新入口成功与失败/不支持对照均由共享探针或真实 renderer 核验；平台回执失败不能被吞掉，浏览器通过不能替代手机平台回执。
