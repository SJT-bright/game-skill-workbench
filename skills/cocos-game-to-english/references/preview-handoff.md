# 英化的两次正式试玩交接

制作和检查用内部地址。手动检查通过 Computer Use 在 Edge 打开当前候选，结构化脚本在隔离 Ego 会话沿用已有证据。中文原版基线、反馈修订、局部补测和最终回归只报进度。内部地址留给测试，Chrome 集成和系统打开命令留到正式交接。

## 先把同版服务准备好

已准备好的同版服务直接复用。需要新服务时，用英化 `serve_preview.py --directory <Web> --project <工程> --native <同版已处理 Native> --snapshot --idle-minutes 0`。按需加 `--ad-simulator`。该服务保留当前快照供交付回执核对。已有对应的广告记录在最终回归里沿用。英化入口包括旧的 `--open` 调用都会把窗口留在内部，候选和草稿的输出标为内部检测入口。正在重建时以本轮通过的快照为准。

## 英文美工试玩交接

从中文源码英化时，第 3 阶段完成本轮美工、中文专项、同版启动和输入检查，并按[操作测速与倍速连续游玩](../../cocos-game-check/test/references/pretrial-continuous-play.md)完成本作持续操作测速、原速完整基准、匹配倍速的完整连续路线及真实免费重开。交接前 AI 读取原始观测，核对实际动作、完成结果、运行错误和当前候选依赖；缺项时继续处理对应节点。已知卡死或无法操作的问题先处理。用已核准的同版服务和本轮计划执行 `handoff_preview.py --kind art --project <工程> --preview-url <同版服务> --plan <清单计划>`。工具把实际游戏和清单挂到同一预览服务，读回通过后结算第 3 阶段，再在 Chrome 打开同页 H5。同条回复交工具输出的 H5 地址、阶段用时、本作实测倍速及连续游玩范围和结果。

H5 请用户顺路看开工选定的原画风、英文语气与可读性、主次按钮、长数字与符号、遮挡裁切、页面打开和短屏观感。在本轮确有改动的页面逐页列实际入口，把一条路线能看到的状态合并。实际试玩遇到卡死、奖励异常也可随手指出，AI 在后续节点处理相应功能和平台回归。

## 最终测试包交接

以适用回归的有效旧记录加本轮补验核对完整覆盖。写出实际 ZIP 后，对同一 ZIP 运行 `prepare_delivery.py`，使用已准备的同版服务根地址。实际分包和体积、Native 启动及同版入口通过后生成本次交付回执。执行 `handoff_preview.py --kind package --project <工程> --preview-url <同版服务> --plan <清单计划> --delivery-record <本次交付回执>`。它在打开试玩之前自动备齐同版源码包和交接证据包（放在测试包旁边），输出的 `reply_lines` 按顺序列出**测试包、源码包、试玩链接、交接证据包**四样；同一条回复原样给出这四样和阶段用时（用户 2026-11-12，做法和例外见[做完游戏默认交四样](../../remake-core/references/external-package-handoff.md#做完游戏默认交四样用户-2026-11-12)）。源码包或证据包备不齐时这条命令会停下并说明原因，修好重跑；只有用户明确说这次只要测试包时才加 `--skip-team-handoff "<原因>"`。已有同版 H5 窗口时可加 `--no-browser`。接手已有英文版的定点修复可直接完成此节点。

最终 H5 是可选的快查。优先列这轮修过的路径或用户最在意的少数动作，如一次开局、一次领奖、一次重开后的状态，按真实范围选择。AI 核对回归结果，用户试玩用于确认体验和反馈。Chrome 的启动请求和窗口实际显示分别核对，保留仍在使用的同版服务。
