# 收集与皮肤系统

主角/背景皮肤使用[皮肤板块](game-modules.md#四皮肤板块默认要问用户)。新表默认 ordinary-levels：Common/Rare/Epic/Legendary约10/15/20/25个普通关基础收益；旧表未标price_profile时保留legacy-2r。实际综合获取进度按真实关序、收入、扣款和装备模拟，不能用单件价格除基础收益替代。

完整新建模板的final为20款主角，every_10为19+floor(总关数/10)款，背景适用时10款。维护已有游戏按已授权数量、已有广告解锁与加成执行，不因模板扩范围。排行榜及其奖励全部禁用；签到等独立扩展须有明确项目授权。下面第二、三节的广告单位估价只适用于皮肤之外已授权的收集物，皮肤按上述profile生成与审计。

新增收集/皮肤系统先确认本轮授权与模块决定。有关卡与无尽采用对应合同；所有路线均禁止广告跳关。材料里的历史扩展不作为新功能授权。

## 一、稀有度：从低到高

- 4 档：**Common（普通）→ Rare（稀有）→ Epic（史诗）→ Legendary（传说）**，皮肤板块另有 **Limited（限定）**。物品少时可以只用前 3 档。
- 每个收集组（例如"皮肤"一组）里可购买的物品 ≥ 4 件时至少用 3 档，2–3 件时至少 2 档；按显示顺序 `order` 排列时稀有度**只升不降**（限定皮肤不受这条限制：皮肤板块里它排第一）。
- 界面上每件物品都显示稀有度：卡片边框/底色/角标固定颜色——普通 灰白或浅绿、稀有 蓝、史诗 紫、传说 金橙（明亮Q版、柔和立体）；英文标签 `COMMON / RARE / EPIC / LEGENDARY / LIMITED`（限定用彩虹/红金色）。

## 二、1 个广告值多少：R

**R = 中等难度的一关能拿到的金币**（用户定义）。所有价格都用"广告单位"计价，再按 R 换算成金币，保证同一稀有度不管用哪种方式买，难度都相当。

| 稀有度 | 价值（广告单位） | 只看广告 | 只用金币 | 二选一 | 广告 + 金币 |
|---|---|---|---|---|---|
| Common | 1–2 | 1–2 次 | 1R–2R | 1–2 次 或 同值金币 | 1 次 + 约 1R（只用在价值 2 的物品） |
| Rare | 3–4 | 3–4 次 | 3R–4R | 3–4 次 或 同值金币 | 约 2 次 + 约 1–2R |
| Epic | 5–6 | 5–6 次 | 5R–6R | 5–6 次 或 同值金币 | 约 3 次 + 约 2–3R |
| Legendary | 7–8 | 7–8 次 | 7R–8R | 7–8 次 或 同值金币 | 约 4 次 + 约 3–4R |

- **广告次数最多 8 次**（最高等级物品），任何物品都不超过。
- "广告 + 金币"的价值 = 广告次数 + 金币 ÷ R，要落在该档范围里（大约一半广告、一半金币）。
- 同一种方式里，稀有度越高要求越高；同一档里按显示顺序不减少。
- 例：中等关给 50 金币 → R = 50 → 传说"只用金币"350–400，"二选一"8 次或 400 金币。

## 三、五种解锁方式

| `unlock` | 玩家要做什么 | 配置 |
|---|---|---|
| `ads` 只看广告 | 看满 N 次 | `ads>0, coins=0` |
| `coins` 只用金币 | 付 M 金币 | `coins>0, ads=0` |
| `ads_coins` 广告 + 金币 | **先**看满 N 次广告，**再**付 M 金币 | `ads>0, coins>0` |
| `ads_or_coins` 二选一 | 看满 N 次广告，**或者**直接付 M 金币（M = N × R） | `ads>0, coins>0` |
| `level` 限定关获得 | 打过限定关获得：限定皮肤（买不到），或下一张地图（见第四节） | `ads=0, coins=0`，填 `level`（必须是限定关）、`"condition": "clear"` |
| `free` 初始物品 | 默认拥有 | `ads=0, coins=0`，只能排在付费物品前面 |
| `checkin` 七日签到获得（用户选了签到时） | 签到第 6、7 天等获得，不能买 | `ads=0, coins=0`，见[可选玩法](skin-bonus-and-checkin.md#三七日签到) |

- 每个收集组可购买的物品 ≥ 4 件时，`ads`、`coins`、`ads_coins`、`ads_or_coins` **四种都要出现**；每档稀有度尽量混合几种。
- 除初始物品和限定关奖励外，不允许免费、自动解锁、试用转正等绕过路线。`league`永久按当前规则禁用；`checkin`仅在用户明确要求时按 fusion-policy.md 校验。
- **没有"完美通关送皮肤"**（用户 2026-10-22）。通关拿到的皮肤只有限定关的限定皮肤（第四节）。

## 四、限定关奖励和地图解锁

用户 2026-10-22：送皮肤的只有限定关，没有"完美通关送皮肤"。用户 2026-10-23：每 10 关一个限定关。用户 2026-10-24：限定皮肤两种格式都可以——`final` 只在最后一个限定关、`every_10` 每个限定关各送一款；至少 70 关。

**1. 限定关：第 10、20、30…关**（所有通关型游戏都有，见[顶部资源栏和关卡地图](top-bar-and-level-map.md#五限定关每-10-关一个)）
- 限定关就是每章（10 关）最后一关，难度和前后关一样逐关递增，不额外加难；地图节点是华丽的大边框。
- 第一次打过给**大量货币**（至少前 5 关货币的总和）并解锁下一章；**限定皮肤**：`final` 时最后一个限定关送一款（皮肤板块排第一），`every_10` 时每个限定关各送一款（`hero_limited_10`、`hero_limited_20`…，全部排在最前），配置 `"unlock": "level", "level": <这一关>, "condition": "clear"`，`ads` 和 `coins` 都是 0；**商店买不到、看广告解锁不了、不进试用**，画得最精致。
- 有多张地图时，通关限定关同时解锁下一张地图，配置在单独的 `map` 组：`"unlock": "level", "condition": "clear"`，`level` 必须是限定关，第一张地图 `free`。通关后播放解锁动画，地图选择页出现新地图。
- 哪关是限定关、奖励是什么，写在关卡表 `level_plan.json`（`make_level_plan.py --limited-skin`），`audit_level_plan.py` 检查。

**2. 奖励关**：每 10 关一个，位置按种子随机，比这段最简单的关还简单，3 倍货币、看广告 6 倍，见[奖励关](top-bar-and-level-map.md#四奖励关每-10-关一个按种子随机)。

## 五、看广告试用（下一关开始前弹窗，必须有）

- **时机**：上一关结算后，玩家点"下一关"，**在下一关开始之前**弹出"Try it free!"弹窗：皮肤大图 + 稀有度 + "Watch Ad to Try" + "No Thanks"。
- **频率**：前 2 关不弹；之后每 2–3 关弹一次；所有可试用物品都已拥有时不弹。
- **推荐哪个**：玩家还没拥有的可购买物品，优先 Epic/Legendary，每次轮换，不连续推同一件。限定皮肤不提供试用。皮肤有加成，试用弹窗写上加成（"Try it: +30% coins this level!"），试用那一关加成生效。
- **效果**：只在接下来这一关使用；这一关结束后恢复原来装备的皮肤，不算拥有。结算页提示"Like it? Unlock now"，带到该物品的解锁入口。
- **试用看的广告不计入解锁进度。**
- "No Thanks"一出现就能点；广告取消、失败、超时或关掉弹窗，都直接进入下一关，不影响任何东西；广告完整看完才生效（按 AD-02/03/04 检查）。

## 六、解锁流程和界面（固定做法）

- 物品卡片：图片、稀有度标签、要求（金币图标 + 价格；其他收集物的广告图标 + 进度 `2/5`；限定皮肤变暗并显示"Clear Lv.<关数>"）、状态（锁定 / 已拥有 / 使用中）。
- `ads`：每看完一次完整广告进度 +1 并立刻保存，满了自动解锁；取消/出错不加；进度永久保留。
- `coins`：金币够就扣币解锁；不够显示差多少，不扣币。
- `ads_coins`：先看广告，进度满后按钮变"金币解锁"，付款时才扣币；金币不够不扣币、不丢进度。
- `ads_or_coins`：卡片上同时有"看广告 (2/5)"和"金币 M"两个按钮，任选一个完成就解锁；已看的广告进度保留，改用金币时**按全价**付。
- 解锁和"使用/装备"是两步。列表、详情、关闭重开、重启游戏后，进度和状态都一致。

## 六之二、皮肤增益（皮肤板块都有）

每款付费皮肤和背景都有过关货币加成，越稀有越高，只算装备的那个（每组一个）；数值、界面和结算显示见[皮肤板块](game-modules.md#4-加成和界面)，`audit_acquisition_progression.py` 按 skin.v1 查。

## 七、配置文件（唯一数据来源）

游戏运行时读取这个文件，价格和次数不散落在代码里：

```json
{
  "module": "skin.v1",
  "coins_per_ad": 50,
  "coins_per_level": 50,
  "price_steps": [1, 4, 10, 20],
  "items": [
    {"id": "hero_limited", "group": "skin", "order": 1, "rarity": "limited", "limited": true, "unlock": "level", "level": 70, "condition": "clear", "ads": 0, "coins": 0, "bonus": {"type": "coins", "pct": 55}},
    {"id": "hero_01", "group": "skin", "order": 2, "rarity": "common", "unlock": "free", "ads": 0, "coins": 0},
    {"id": "hero_02", "group": "skin", "order": 3, "rarity": "common", "unlock": "coins", "ads": 0, "coins": 100, "bonus": {"type": "coins", "pct": 5}},
    {"id": "map_01", "group": "map", "order": 1, "rarity": "common", "unlock": "free", "ads": 0, "coins": 0},
    {"id": "map_02", "group": "map", "order": 2, "rarity": "rare", "unlock": "level", "level": 10, "condition": "clear", "ads": 0, "coins": 0}
  ]
}
```

- 皮肤和背景的行由 `make_skin_table.py` 生成（上面只列了几行），只填 `name`、`art`；地图组和其他收集物按第二、三节自己加。
- `coins_per_ad` 就是 R（中等难度一关的金币）；`coins_per_level` 是普通一关的金币，用来估算攒钱要几关。
- 默认位置：`assets/resources/config/unlock_table.json`。原游戏把配置写在别处时，组装线把实际数值导出一份到 `docs/economy/unlock_table.json` 并写明来源；改数值两边一起改。
- 检查：`python scripts/audit_acquisition_progression.py --table <配置> --report <报告.json>`（一键预检会自动找上面两个位置并运行；门禁 `ECON-01` 配置、`ECON-02` 试用弹窗和地图解锁的界面流程、`LEVEL-02` 限定关奖励）。

## 八、金币要能赚到

- 有收集系统就要有货币；原来没有时加最简单的来源：每过一关给金币，结算页显示。中等关给的金币就是 R。
- 货币的名字和图标贴合题材（海底→珍珠 Pearls），放在[顶部资源栏](top-bar-and-level-map.md#一顶部资源栏)，数字当场变化；本页说的"金币"指这个游戏的货币。
- 最便宜的金币物品应在**前 5 关**内买得起（脚本会提示）。
- 每关结束看广告×2、首页礼盒是[内置板块](game-modules.md)固定有的，用 `AdRewards.ts` 算，按广告奖励规则检查，不代替解锁次数。

## 九、和其他规则的关系

广告完成判断、发奖一次、取消不奖、保存重试、连点等，仍按[物品获取](item-acquisition.md)和累积清单 `AD-02/03/04`、`CLAIM-01/06/07`、`STATE-01/02/06` 检查。本页只定"怎么设计"。
