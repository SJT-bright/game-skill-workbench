# 领取入口与长屏修复

用于现有游戏的领取无反馈（礼盒、结算×2 等）、广告领取失效或封面黑边/文字碰框反馈。先修当前游戏，复测后再更新可复用方法；用户说运行的是最新版时不能预设旧包或缓存。

## 从实际入口定位

沿玩家操作检查事件绑定 → 加载遮罩/资源回调 → 平台能力判断 → SDK 请求 → 完成结果 → 真实库存/领取状态 → 按钮恢复。视频没出现的页面不当作已经复现。

- 配置里有广告位不代表玩家能触发。逐个检查配置条件、可见按钮和实际奖励消费者；备用或当前数据没有的路径标为未启用，不能按广告 ID 数量声称都有入口。
- 奖励卡/礼盒显示可领取状态时，确认它本身有有效点击绑定，或明确引导到唯一领取按钮；已领取、还不能领都有适当反馈。七日签到已不做（用户 2026-10-23），原游戏的签到按[内置板块](game-modules.md#一先删多做多错)删掉；奖励数字统一由 `AdRewards.ts` 算。
- 用户授权广告道具领取后，检查原 Web 免费直发奖分支、旧按钮回调和里程碑入口。完整观看之外的取消、失败、超时不奖；原通关进度、基础奖励、已有库存消费和明确保留的免费选择分开核对。
- 请求时锁定本次 UI/数据身份并禁止重复点击，只接受严格完成结果；奖励与领取标志最多提交一次。关闭、退出、换局或旧回调失效；取消/失败恢复按钮并给反馈，让玩家能再次尝试。
- 国内 SDK 枚举与全局对象可能在平台预览里残留。调用 wx 等原接口前检查真实平台及方法能力，不仅依赖枚举。通用加载失败只清理本次占位栈和本次遮罩，恢复队列并允许重试；不清空整栈。

领取后的“到账但仍失败/已领但不可用”，按 [领取结果一致性检查](known-issue-checklist.md#领取结果一致性检查) 追查原规则、同一目标、本次奖励、保存反馈、实际使用、相关缓存页面与重开刷新。保留待保存后正常操作同步模型、跨周期改变目标的组合负例；拥有与已穿戴不共用成功判断。

## 英文文案与装饰边框

Cocos 2.x 序列化 Label 可能同时保存 `_string` 与 `_N$string`。翻译预制体时核对实际 importer 使用的字段并保持一致；只改其中一个可能在真实构建中被旧字覆盖。以真实运行文案为准，检查实际导出而不只搜索源码。

为九宫格/金属按钮明确内侧安全矩形，按实际装饰厚度安排标题和副标题。正文采用清楚字体、高对比和有界尺寸；主标题/说明分别定字号与行高，在同类控件中统一。不要把文本框扩到整张图外边缘后仅依赖 SHRINK；缩小到看不清时改换行、短文案或合理扩大按钮。检查正常、按下缩放、已领取和更长状态文案。

## 封面长屏与首触跳变

图片背景的铺满缩放与可交互控件的等比缩放分别处理。需要全屏封面时，背景使用 live Canvas 尺寸的 cover/fill 规则并检查标题/人物安全裁切；控件按安全布局缩放，不随图片被裁掉。尺寸不变不重复重画背景，图片加载结束和 viewport 改变时刷新布局。

首触后出现黑边、位置跳变或下一次点击错位，检查浏览器自动全屏与 Canvas viewport 变化。修 Web launcher 时只改已确认的单个导出段，保留构建/补丁哈希与可重放工具；不要改安装引擎或把 Web 行为直接套到 Native。没有帧间隔或性能记录不能把视口跳变称为性能卡顿根因。

## 回归与证据边界

先执行当前源码及实际编译模块的奖励边界回归，再按 prepackage-mobile-review 和手机触屏 Skill 用 Ego Lite 官方 CLI 操作真实页面。至少核对受影响的两种长屏、可达签到/领取、关闭与重开、余额和领取状态；输入为真实 touch 时保留被动原始事件。按下动画还没结束时，先观察可见按钮是否已准备好再判断无响应。

必要的独立业务状态夹具用于检验稀有结算/条件页面，记录不是自然通关。合成事件、SDK/节点替身和旧版本证据不当作真实手机或本次实际点击。Mac 原生窗口可能切换或缩放，操作前核对当前 URL/窗口与截图，坐标失效后重新定位；错误窗口或被裁切截图排除出通过证据。

真实完整广告、提前关闭、后台回来、原生触点转换、实际设备性能与所有关卡仍按对应证据验收。源码/构建/候选 SHA、Ego Lite 模拟、真实手机、平台上传分别记录。


## 领取状态、广告等待与完整图片标题（2026-10-14复测沉淀）

同一个领取状态必须由显示和点击共用的规范化逻辑读取。真实存档中的数字字符串可能被宽松显示判断视为可领，却被严格点击判断直接拒绝；检查数字、数字字符串、坏项、空数组、非数组和异常读取，保留坏记录而不默认免费可领。没有状态变化的返回要给明确反馈。

实际SDK分支在请求时立即显示可取消的阻塞面板并禁重复点，记录当前UI/数据身份；请求尚未返回与已开始播放等待关闭分开设置有界超时。show Promise resolve不代表完整观看；完整关闭回调才奖。提前回调、cancel、请求拒绝、超时、销毁/换局均单次结束业务请求并恢复退出操作；界面收尾与SDK会话实际结束分别判断，未确认旧会话结束时不允许重叠播放或自动重播。错误只保留有界数字码及白名单阶段，不保存原始负载或凭据。

ScrollView不能为了让按钮响应而整体关闭拖动取消。检查列表空白点击的父节点遍历必须停在边界，拖出领取按钮不触发，滚动后的重用卡片不能吃旧奖励。

原中文字烘焙在翼徽、星星、横幅等装饰图中，局部矩形裁切再叠英文可能留下接缝。优先内置image_gen编辑为一整张透明英文图，保留原画布和UUID；撤除旧裁切/文字覆盖，检查原图、实际图集旋转/alpha及自然结算背景中的合成效果。图集PNG与源PNG不要求文件字节相等，逐像素检查需说明预乘透明色舍入。

本机Creator GUI实测要指明真正打开的项目/场景/实时预览服务。最终源改动后读回编译helper与当前浏览器加载bundle，发现旧Web导出就拒绝并重建。最后代码修改前的完整流程不可直接标成本次最终helper全流程；在最终bundle上重走核心链与修复入口。隔离HTML的SDK模拟仅用于完成/取消/错误/超时边界，不修改游戏控制器、存档或伪造通关；保持普通试玩和上传包不含夹具。鼠标、Device preset、真触摸、手机IAA分别记录，原始手机失败仍需对应包和SDK证据。


## 结算数量、按钮层级与缓存入场（2026-10-14复测沉淀）

图标内的数量Label可能继承背景缩放，源字号不等于实际可读字号。以真正渲染的字高/对比度和完整金额验收；结算金额可放到独立节点，使用清楚系统字体、完整整数/分组数字和有界宽度。装备等级等原信息一并保留，改动限定当前页面，不全局隐藏共用GoodsItem数值。

可见文字须与正确按钮层级绑定。给父Label添加Graphics背景子节点，可能让背景盖住父文字；使用背景/文字兄弟节点明确z顺序和居中，实际点击检查。预制体默认与onEnter动态文字不一致时两者同步；仅凭用户截图不能把唯一原因认作缓存或动画。入场动画结束、进度动画、升级弹窗关闭和缓存再入分别核对按钮可见、opacity、文案、可点与严格奖励状态。清理退出后的旧回调，不能清掉本次必要流程或把claimed/pending恢复为可点。

读取实际安装的Layout行为，不能仅根据节点宽高推断最终摆放。Creator2.4的HORIZONTAL只调整X；其他轴的位置需依据本游戏父布局和实际画面明确设置，不能预设统一移动方向。GRID高度、边距、文案和底部按钮范围一起检查。掉落数组没有真实上限时，不人为截断奖励列表来解决排版；使用限定视区的真实ScrollView/Mask保留全部数据，缓存由大列表转小列表也核对父节点/滚动层恢复。源/Native几何与替身ScrollView证明不了实际触摸滚动，稀有列表必须单列待手机验证。

最终Source/Web/Native代码冻结后，在真实Creator当前项目/场景的实时预览自然执行本游戏核心流程；有关卡才跑关卡。保存当前实际奖励、相关状态前后、实际领取/返回、取消/失败恢复及页面再次打开的证据。点编辑器Play/Recompile可能重载正在测试的页，重载前记录的流程不能当最终之后的结果；重新从自然入口执行。修改浏览器viewport后还要读实际Canvas矩形，未随之适配的旧画布不能当该新尺寸通过。鼠标、设备预设、真实触摸和手机IAA分别记录，普通包不含SDK夹具。Finder能重建.DS_Store，打包只取真实输出文件，独立解压逐SHA核验。

## 可见按钮的实际绑定与同页独立奖励

奖励方法边界通过后，继续核对实际场景/预制体中可见按钮的clickEvents目标节点、脚本UUID、handler与广告用途，并验证当前实际编译包的同一条链。新增严格方法没有替换旧绑定时，玩家仍可能触发直接奖励/重开；只调用新增方法的测试不会发现。运行时创建的按钮也要检查实际创建回调，不能只搜索方法名。

已出现绑定绕过时，保留只有该绑定不同的最近失败构建和正常对照；本项目检查须让旧实际包失败、新实际包通过，并在创建ZIP前执行。引擎场景无法解码应明确失败，不能悄悄改读源码。此项证明静态路由与方法消费者，真实触屏仍由 Ego Lite 复测。

同页多个奖励分别持有资格与持久状态；一种已领不应无意锁死另一种。用户授权新增广告奖励时保留原免费和赠礼规则，完整结果后先确认保存再显示成功；保存失败保留重试，重复/旧页回调不能重复奖。实际装饰按钮的有色区域与透明边距一起检查，节点外框足够不等于多行文字能放进图案。

## 保存确认失败与异步入口恢复

奖励状态检查必须使用实际保存层和实际业务消费者：既测写入前失败，也测写入已被接受但读回抛错/返回对象/键顺序变化。多种货币、背包或解锁、资格标记和次数同属一次奖励时，检查它们是否一起落盘；不能用“第一种货币到账”替代整笔成功。重试同一已完成视频的保存时不再请求广告，余额、库存和次数只改变一次。已确认入账却无法确认回执时，不盲目恢复旧值覆盖后续存档；凭证与缓存恢复一起检查。凭证只有内存时明确离页/重启边界，不声称持久恢复。

异步 UI 检查分别覆盖直接打开、正在加载时排队、互斥等待、重复打开同页、加载失败、关闭时丢弃队列。完成、最终收尾和失败回调逐项记录次数与时机；失败不能冒充成功，排队不能提前完成或丢掉收尾。只有存在一次性接触/物件加载的游戏才检查该入口：加载失败不能永久消耗入口；重试不在持续接触中自动循环，旧对象回池或场景更换后迟到结果不得改新对象。具体物件、奖励金额和关卡属于项目。

保存/渲染/SDK 替身各自标明。测试保存流程时尽量保留实际 profile/序列化层，避免把中间保存器替换成空函数后漏掉分步提交。保持原失败版本、修复版及正常对照，新增用例进入真实产包入口。对后台委派的超时任务也检查实际改动文件；残留半成品须剔除或完整验收，代码冻结后再构建，不能把超时当作没有写文件。
