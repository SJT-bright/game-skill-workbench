# 旧游戏侧栏局部整改（2026-11-10）

## 触发与范围

“用最新版 Skill 整改侧栏”“整改侧边栏”“按最新版处理侧栏”等同义请求，统一执行去游戏名、首页侧栏布局、个人主页回访和桌面快捷方式四项。当前用户另有范围时以其要求为准。已交付、其他人提供或被退回的旧游戏均适用，包括被工具标记为 `legacy` 的工程。此任务走 `handoff` 接手或 `returned` 返工，先读取当前安装的英化入口及本页。

四项分别查现状，已满足且有有效证据的项直接沿用。缺陷回到该项修复，继续到已授权的交付完成。使用原游戏画风、经济数额及存档契约；固定入口文档的首次制作 5B 规则不覆盖这条旧游戏维护路线。

## 定基线并计时

核上一次实际交付的源码、Native ZIP 和对应预览身份，恢复已有逐项记录。按[一次通过、按改动复验](../../remake-core/references/incremental-checks.md)建立本轮局部计划，包含真实改动和共享使用者。若缺少资料，先在项目中寻找已有交付与记录，再定位具体缺口。

使用[阶段与节点计时](phase-timing.md)，本轮 route 取 `returned` 或 `handoff`。命名节点依次为“基线与范围”“去游戏名”“侧栏布局”“个人主页回访”“桌面快捷方式”“局部补验与交付”。每个节点报告完成或沿用、实耗与下一步；阶段结束附实际用时及说明。证据核对的耗时单列，沿用的旧测试保留原执行时间。

## 四项制作与修复

### 去游戏名

1. 把原中文名、英文名和实际别名登记到 `docs/copy/glossary.json` 的 `game_name`，核对历史 `game_name_ok`，移除与本次明确去名冲突的例外。逐项定位首页、加载、设置、结算、弹窗及相关贴图中的可见名称。运行时创建的名称从对应 UI 创建代码修复。
2. 本触发语已授权旧工程去名，使用包内工具，`<skills>` 为当前安装包的 Skill 根目录。

```sh
python3 <skills>/remake-core/scripts/fix_game_name.py --project <工程> --force
```

3. 按工具输出的 `docs/art/game_name_fix.json` 制作无字主角、道具或图案，沿用原画风，保留原标题节点的位置与占位尺寸，等比替换其中图案。先加载[美工 Skill](../../remake-art/SKILL.md)，出图提示词使用包内 `prompt_name_guard.py`。同名同尺寸新图准备好后应用。

```sh
python3 <skills>/remake-core/scripts/fix_game_name.py --project <工程> --force --apply-images <新图目录>
```

4. 看 `remaining_hits` 与实际受影响画面。`legacy` 默认跳过以及退出码 0 均不能单独证明去名完成。已有图片识字记录缺失、过期或漏掉名称时，直接查看相关原图、图集或 Spine 切片和使用页，补准这些图的记录再修。检查相关资源引用，确认图案确实进入当前版本。项目与平台标识依原工程保留，玩家可见名称按本项清除。

### 侧栏布局

按[手机按钮尺寸与首页布局](../../remake-art/references/mobile-button-size-and-home-layout.md)处理本轮侧边功能区，沿用已确认尺寸基准，首次调整记录真实基准与目标。依原有真实功能分配左右位置、间距与安全区，保持主视觉、PLAY 和入口可见可点；图案与点击区对齐，处理遮挡、裁切、越框和残留旧层。空间不足直接在侧栏及必要邻接区域重排，未涉及区域沿用原布局。迁移原按钮或改变容器结构时，先按[统一坐标与绘制职责](../../remake-art/references/production-prevention.md#接入前统一坐标与绘制职责2026-11-03)处理旧容器剩余子项与图文价格组合，并接入原页面层级。新增或重建控件在设计时执行[新增界面制作](../../remake-art/references/new-feature-ui.md)。

### 个人主页回访与桌面快捷方式

执行[现行直跳与自动查奖](../../remake-core/references/tiktok-home-growth.md)和[旧游戏两入口定点修复](../../cocos-game-check/package/references/upload-compat-and-entry-fix.md#二个人主页回访和桌面快捷方式)。两个入口独立、始终显示，第一次点按即调用对应导航，已领取仍可用。移除跳转前说明、旧面板、toast、GO、CHECK REWARD 及旧事件绑定。入口用途由同画风语义图标表达。

对应来源冷启动或热返回后，钱包就绪即查询对应资格，严格 `canReceiveReward === true` 且奖励与已领取状态持久保存成功才算到账。重复点击、回调和重开只发一次。普通切回前台保持零查询、零提示。沿用本游戏原奖励种类、数额和存档键。

已采用平台包的工程使用本包标准件并核对实际按钮接线；旧游戏自写入口按当前契约定点修原链路。保留原工程策略标记，通过上述 `--force` 执行授权去名，避免重新 `init` 或整体 `adopt` 引出无关迁移。

## 局部验证与交付

先读增量计划，再按下面的变化选择已有检查器与真实入口。

| 本轮变化 | 执行范围 |
|---|---|
| 名称文字、原标题图或侧栏布局 | 核这些节点的实际显示、相关切片、可见与点击位置；共享资源变化按真实使用者覆盖 |
| 回访或桌面入口代码 | 分别核对应导航、冷启动及热返回查奖、真实到账、持久化去重、普通前台安静及失败可重试；有效未改项沿用 |
| 重新构建 | 核当前导出身份与改动接入，只补缺失或真实失效节点 |
| 交付 ZIP | 按现行写包与交付入口，读取实际最终 ZIP 做本次分包、体积及适用 CLI 核对，核准同版预览 |

未变化且已通过的美工、中文、音效、玩法、关卡和平台记录直接沿用。缺证时恢复或补该节点，范围不明时补准依赖。保留原记录；禁止因版本号变化、接手、重新构建或一处改动重跑全量。新截图限于实际需要的变化状态，复用同一浏览器批次。

用户已指定美工改完即出包的部分，按[返工视觉授权](../../remake-core/references/returned-art-delivery.md)处理，沿用其免复验范围。功能与奖励变化保留相应技术验证。最终交付测试 ZIP 与同版[双栏试玩 H5](playtest-h5.md)，左侧实际游戏、右侧本轮局部清单；内部测试按[浏览器规则](preview-handoff.md)执行。完成后报告四项各自“已修复 / 已满足沿用 / 具体待处理”、实际执行与沿用范围和阶段实耗。
