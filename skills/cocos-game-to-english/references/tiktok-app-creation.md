# 独立 TikTok 小游戏应用创建与配置

仅用于用户明确要求为当前游戏创建独立 TikTok 应用、或执行后台配置/查询的情况。已有 App ID、公开 Client Key、广告位时直接完成本地接入、修复、构建和测试，不登录或打开后台，也不要求用户开权限。“接入广告”“应用ID自行解决”以及本Skill默认IAA工作不触发后台流程；缺值先查用户已给配置及已授权预设。用户已明确授权同一目标的后台创建与配置时直接继续，不因换浏览器或重试重复索取相同授权；上传、送审、发布和组织管理按各自授权处理。

按 [本地体验审查](local-review-and-test-ids.md) 由 Agent 自主审查并优化英文画面与按钮，实际运行可查看和关闭的广告预览窗口；用户反馈如有则处理，不以用户在 Ego 审 UI 或审美确认作为平台工作的前提。用户已明确授权创建应用时按该授权推进；已有标识直接回填本地接入，不为此创建应用或打开后台。已创建的应用或已填标识重审时保留并核实，不重复创建或清空。

依据：[Prepare Your Developer Account](https://developers.tiktok.com/docs/en/perpare-your-developer-account)，2026-10-11 复核；以及当日原生 Chrome CUA 实际创建、应用列表和 IAA 页读回。页面标签和权限可能变化，以当前后台为准。本参考不保存某个项目的真实标识或账号资料。

## 进入正确账号，先查重

优先使用已登录的开发者后台；没有可用 CLI/API 时用允许的浏览器控制工具。默认用 Ego Lite 官方 CLI，在本会话自己开的 TaskSpace 核对开发者账号、组织名和应用管理权限（登录状态在 profile 里，新开空间不用重新登录；空间被占时新开一个，不等）；除非用户指定，不查看或选择 profile。Cocos Dashboard 登录、TikTok 网页登录和 DevTool CLI 登录是独立状态。

进入 Developer Portal → Manage apps，检查当前游戏名、组织归属和 App ID。已存在目标应用时进入该应用，不重复创建；同名但归属不明时先核实。记录创建前列表，以便处理提交后超时或连接中断。

已登录网页而 CLI 尚未登录时，能在允许的浏览器完成已授权步骤就继续，不强迫用户另走 CLI 登录。后台提示当前账号无应用操作权限，是目标应用/组织权限问题；再次登录同一账号或手动输入已有 App ID 不能把外部应用导入本组织。读取实际提示和归属，再按用户授权使用有权应用、取得权限或新建独立应用。

用户只要求新游戏应用时使用已确认的组织，不擅自新建组织、邀请成员或提交企业认证。没有可确认组织时，先完成工程工作并取得所需组织信息；不编造企业名称。

## 创建并读回结果

1. 点击 Connect an app，Ownership 选择 Organization，选择已确认的组织；核对选中值含正确组织名/ID，不能把搜索框里输入的文字当成已选择。
2. 进入应用资料，填写当前游戏的英文 App name，App type 选 **Mini game**。后台提示类型以后不能更改，提交前核对它未被选成 Mini drama 或 Other。
3. 在授权范围内提交创建。若实际步骤涉及新协议、敏感权限或其他需要确认的操作，遵循当前工具确认规则；普通创建步骤不另外增加审批。
4. 等待结果，核对实际应用详情页的名字和状态，再回应用列表读回 App ID、归属。URL 中的编号只作辅助证据，不能单凭点击成功或跳转即宣布创建成功。
5. 进入该应用 Basic information → Credentials，只展开 **Client key**。不展开、复制或保存 Client secret。保存这一个应用的公开配置，不擅自从另一个游戏借用标识；若用户明确指定复用测试组，在独立测试副本整组配置，不能写回本次新建的独立应用工程。

如果提交结果未知，恢复连接后先查应用列表和详情，确认未创建才重试。避免连续点击创建导致重复应用。

## 检查 IAA，回填可用配置

进入本应用 Monetization → **In-App Ads (IAAs)**；默认可能在 IAP 标签，不能把 IAP 的限制当成已检查 IAA。

若页面要求 `Complete business verification to configure IAAs`，记录实际提示：应用可已创建，但组织尚不能配置广告位。由最终发行组织办理认证；用户只是源码开发交付方时，不要求其个人另办企业。继续交付已知公开标识和待配置广告接口。

若本应用具备广告配置权限、且用户已授权广告接入，按当前后台流程创建奖励视频广告位，核对类型、所属应用及 Active/已启用状态，再填写 Rewarded Placement ID。需要签署变现协议或提供主体资料时，先明确具体材料和步骤，不猜填或代作声明。填 ID 不保证广告一定播放，仍需真实 SDK 与手机验证。

公开配置只包含：

```json
{
  "appId": "",
  "clientKey": "",
  "rewardedPlacementId": ""
}
```

把实际取得的值写入本游戏配置；未知值保持为空。默认完整 Native 构建在写源码和输出前拒绝缺配置；显式待配置构建允许同步已取得的标识并生成候选，缺广告位时不发奖。此拒绝不隐藏 [本地体验审查](local-review-and-test-ids.md) 中的广告预览窗口。不能只改交接 JSON 而让源码或 Native 仍带旧值。

配置更新后，重新用实际 Cocos 工程导出，核对源码、Native 根 project.config.json、构建脚本内公开标识与交付配置一致。独立审计新包、旧包保持；如果只改配置，用差异记录证明其他素材、场景、关卡和玩法未变。按 [Native 与 IAA](tiktok-native-iaa.md) 继续离线检查、DevTool 和手机联调。

## 浏览器控制故障的续接

账号已经登录而工具连接失败时，区分登录与控制通道，不让用户反复登录。读取具体报错，确认当前窗口/个人资料；在工具允许的范围内恢复本会话自己的 Ego Lite TaskSpace，恢复不了或被占就新开一个（不等待，不接管别人的空间）；用户指定备用浏览器时再沿其工具文档操作。不要绕过工具拒绝访问的应用，也不要读取浏览器凭据或用其他自动化接口替代禁止的路径。

本次原生 CUA 曾在跨调用点击时报“用户改变应用”；有效做法是在同一调用先读取完整新 AX 状态，再从最新观察取得元素索引并操作。必要时使用文档支持的 disableDiffing，不能靠旧索引。组织下拉选项未进入 AX 时，可在已观察到选项后用键盘选择并核对选中值；不凭搜索框文字或未经观察的坐标提交。此方法是故障时可尝试的路径，不要求每次创建都重置浏览器。

有重复的采集、扩展或路由失败且无可用允许路径时，保存具体错误、未完成状态和续接位置；不把登录成功说成连接恢复。截图和简单文字识别遵循当前环境规则，保留实际读取证据。

动态页面出现 insertBefore/节点被移除等错误，且确认是当前页面自动翻译介入时，可在授权工具中恢复该页原语言、重新读 DOM/AX 后续接；不得因此全局改浏览器偏好或清除登录。工具拒绝访问时遵循其限制，不换通道绕过；连接失败、页面渲染错误、未登录和无应用权限分别记录。

## 交接与证据

记录应用名、组织、App ID、公开配置来源、创建前后列表/详情、IAA 状态、修改文件与新包校验；截图避免暴露 Secret、私人资料或无关账号。项目实际值与状态留在项目记录，技能只保存可复用方法。

记录实际状态：应用是否已创建，公开配置是否回填，激励广告位是否可用，Native 是否已构建，DevTool/手机/真实广告是否验证，是否上传或发布。企业认证、广告权限、真实播放与正式发布仍待完成时，明确写出当前卡点及负责方，不用“广告已接通”概括仅完成的接口或应用创建。

创建后继续 [测试 ID 配置及最终审查](local-review-and-test-ids.md)，不要把取得 App ID/Client Key 作为广告接入任务的完成点。
