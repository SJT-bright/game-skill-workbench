# 引导拖动、暂停恢复与奖励按钮反馈（2026-10-25）

适用于有拖动/摇杆引导、相机跟随、暂停弹窗或广告前置按钮的游戏。按实际机制检查；局部修复只查受影响链路，不扩为全游戏 CI。

- 广告未加载、平台能力缺失、条件不足时，可见按钮必须给准确可读的原因和可退出路径。禁止只有 `isLoad()` 守卫然后静默返回；也不能为让按钮“有反应”绕过广告直接发奖。失败、取消、已完成分别核对 pending、按钮恢复和资源前后值。
- “拖动移动”必须实际按住、移动、松手，读回玩家坐标和相机/地图坐标，确认有限数值和实际变化。同时观察引导仍在时和结束后；截图、首关出现、摇杆有监听都不能替代移动结果。中心按下的零向量、touchcancel、暂停/失焦须释放旧触点，不把无效方向写入玩家或相机。
- 在开局异步加载/移动过渡尚未结束、稳定玩法中分别暂停并恢复。若暂停会停掉创建玩家的回调/动作，恢复须继续同一流程并真正进入玩法；不能只把 paused 改 false。重复前后台/设置操作保持同一暂停层，不层层叠加。自动后台暂停与用户主动暂停分开记录，返回只恢复由后台暂停的状态，不擅自关闭用户设置。
- 恢复后整组输入无效时，按[缺失终止事件短检](button-state-check.md#无响应故障的最短定位)核旧触点归属释放与新触点实际业务；暂停弹窗关闭不等于输入已恢复。
- 诊断先记录首条异常、round/start 阶段、玩家是否创建、暂停来源、弹窗数量与输入状态。短暂 focus/visibility 抖动不应反复弹出设置；不能为修本地自动化关闭真正后台的暂停保护。工具自身带来的前后台事件单列，不冒充用户端唯一根因。
- 修改前保留旧候选，用同一判据证明旧版静默拒绝/弹窗叠层等故障；修复后用真实输入复验拖动、镜头、暂停继续、关闭奖励弹窗。把方法级反例与实际 UI 记录分开。首轮试玩仅做首页和开始不等于这些路径已经验证；用户报告问题后必须查到对应业务效果。

TankAce 010 案例：WISH 的广告未加载分支无提示；设置未去重；前后台暂停可能中断开局地图动作。修复维护树与负例见本机项目 `工作工程/TankAce-010-repair-20261025/`。案例路径仅为来源线索，其他游戏不得复制其数值、奖励或专用代码。

## 提示呈现去重

手机端测试顺序与运行身份见[手机端优先与复发定位](testing-scope-and-stop.md#手机端优先与复发定位)。

仅在本轮新增/修改引导呈现，或实际报告重复提示时检查受影响提示及共享调用方。没有该机制就不适用，不为检查新增Toast、引导或采集系统。只有常驻提示时核实际单次呈现；出现与消退两阶段采样仅用于确有临时提示层的状态。已有同版有效证据沿用，不在打包阶段重新审查已批准美术。

- 同一条引导同一时刻只保留一个可见呈现者；共享呈现入口按完整文案或稳定语义 key 去重，并在切页/退出时释放归属，不能只删一个Toast调用点。对本轮涉及的重复派发、重进及常驻层/临时层同时投递，用实际可见内容（含图片字）确认唯一呈现。不同用途反馈、重复按钮词和数值不得误报；无重复投递风险的普通提示不强行新增状态系统。
- 在提示出现后、最短临时层消退前，以及临时层消退后，分别保存同帧截图、可见节点、透明度和构建指纹。采样窗口按实际提示寿命配置，不能只等布局稳定后截一张图；隐藏节点不计数，缺提示或缺早期采样不能通过。
- 用 [check_hint_presentations.py](../scripts/check_hint_presentations.py) 核项目采集；修复已有重复故障时，以同一判据检查可取得的旧版、修复版及正常对照；旧版缺失如实记录，新功能不要求制造一个真实历史故障。只回归受影响提示和共享调用方，不扩全 CI。采集为 `real_cocos_hint_presentations`，每 case 含 `appearance`/`settled` 两个 sample、项目 timing 窗口、预期提示 key、真实消息节点及截图 SHA；`settled_expected` 默认 `present`（保留），纯临时提示正常消失用 `absent`。两次采集须绑定同一构建、页面和提示 key；截图相对路径以采集JSON所在目录为准。隐藏节点不参与可见几何或重复计数，缺有效早期采样仍拒绝；字段见脚本。脚本只核输入结构、记录一致性及截图文件哈希，不认证采集器身份、截图内容、触摸真实性或项目清单完整性，不能独立宣称游戏通过。只在稳定态采样会漏掉短时重复；具体游戏、复现路径、时长和回归结果留项目证据，不写成通用固定值。
