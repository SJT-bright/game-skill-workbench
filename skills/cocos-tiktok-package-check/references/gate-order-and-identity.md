# 检查顺序与受检对象一致性

修订：`2026-10-26.package-gate-v1`。本页落实到现有轻量writer和启动/交付检查代码，不新增全游戏检查或审批，也不降低每包最终Native启动与恢复要求。

## 哪些失败必须在长测前拒绝

`build_checked_zip.py`依次执行：

1. Native目录、全新ZIP输出名、全新报告路径及明确目标App ID。
2. 当前根配置与目标App ID一致、文件/体积/启动依赖、实际业务资源清单、已知贴图/图集等资源检查。
3. 本轮有交互/声音故障证据时验证已有trace；不能只交文件检查通过。故障适用性仍须依据本轮问题记录，不凭资源后缀猜测。
4. 当前Native真实启动和加载恢复门禁，使用既有可信运行器。
5. 生成临时ZIP，读回核实际包与Native全量字节和资源，全部通过才发布新文件。

目标App错误、明显缺资源、错误输出名或已占用路径不应先启动浏览器/真实引擎长测。`native_problems`已经执行共享启动依赖审计，writer不在它后面立即重复相同审计；最终ZIP回读仍完整执行，不能拿Native预检代替最终包检查。

## 通过结论只绑定被检查的那一份

- 启动门禁在执行前后核Native树、启动合同、renderer报告和恢复索引相同；再次验证引用的原始证据哈希。发生变化即拒绝，不能把前半段旧观察与后半段新文件拼成通过。
- 资源清单在启动运行期间变化，writer拒绝且不发布ZIP。需要修改就作为新一轮输入，不刷新旧观察的哈希。
- 最终交付核对在启动材料校验之后，再核原Native与最终ZIP的路径/字节相同；发生变化不写交付回执。
- 已存在交付回执路径立即拒绝，保留原件，不在完整文件检查后才发现写不进去。
- null或非路径类型等畸形证据返回具体拒绝原因，不能让调用异常被误认为游戏运行失败。

这些是检查期间的一致性限制，不代表操作系统全局文件锁。发布后若文件又被外部改动，须重新核实际交付文件；不能宣称所有外部修改永远不可能发生。

## 真实耗时与停止

writer报告及摘要记录`check_timings`：`static_preflight_seconds`、`startup_runtime_seconds`、`archive_validation_seconds`和`total_seconds`（发布前检查总耗时）。先根据当前日志判断慢在静态分析、可信运行器还是压包回读，再优化对应阶段。

本次不缓存跨版本通过结论，不增加第二次相同启动运行。脚本复用仅限已有进程内纯解析或当次CRC验证的字节，仍受实际输入与检查器版本约束。必要项通过、无新改动/失败/疑点即停止，不额外录屏、跑关或重开美术验收。

## 资源与已报告问题的后续补强（2026-10-26.package-gate-v2）

本页原先仅能验证已填资源列表、并依赖执行者主动传业务trace的两处缺口，现由[实际资源反查与问题复验门禁](resource-and-reported-issues.md)接入两个writer和最终交付：派生全部受支持的有限资源域，未知请求拒绝；固定工程问题历史，定点证据未通过或过期拒绝。有效证据只核相关生产文件，不重跑运行器或全量CI。

任意动态JS仍需受支持的资源协议；新增反馈仍需执行者先登记，程序不自动理解聊天。已批准美术不重新审，WebP等能力风险仍沿已有专项合同闭合，不以静态清单冒充实际解码成功。

回归：`scripts/test_gate_order_and_identity.py`。包含错误输入先拒绝、运行中换候选/证据拒绝、正常调用只执行一次启动运行、原件/回执保留及真实耗时字段。

固定目录运行器须在登记项中声明`native_binding: {"kind":"fixed_project_path","relative_path":"实际项目内目录"}`，共享执行器在启动前确认传入Native就是实际服务目录。路径错误、目录缺失或候选不同先拒绝，不把固定目录的观察绑定到别处。真正按`--native`服务的运行器沿原合同，不因这个修复追加固定目录限制。该身份检查不替代原引擎、输入、恢复和证据校验。

资源审计指纹只绑定当前生产源码/数据匹配的资源 profile 和实际参与拒绝判断的 Native-file anchors。其他项目并发登记不能改变本包签名；当前 profile、资源清单、业务字节或问题证据变化仍须拒包。以隔离登记表验证“无关新增不变、相关改动仍拒绝”，不通过关掉发布前复核解决误报。
