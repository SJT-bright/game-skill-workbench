# 主包超限：定位、修复与最小拒包合同

适用：上传报 Main package size check failed，或修改 Cocos bundle/普通分包及启动入口。2026-10-24 从实际拒包复盘沉淀；平台限额变化时查官方规则，不靠历史数字猜测。

## 判因

1. 锁定用户实际上传 ZIP 的 SHA，与交付记录比较；文件改名不改变字节。读取 ZIP 条目的未压缩 file_size，不能用 ZIP 压缩后体积、磁盘占用或目录显示大小代替。
2. 主包=全部文件减去 game.json 小写 subpackages 中实际声明且存在的 root 目录。分别统计总包、主包、普通分包、独立分包，列主包最大的五个文件。
3. Cocos isBundle=true 不等于小游戏分包。Cocos 2.4 resources.meta 的 compressionType 中目标 bytedance 未设 subpackage，会将 assets/resources 留在主包。只创建 subpackages 文件夹或仅改 game.json 也不是完整修复。
4. 实际故障示例：旧 ZIP 24,764,732 字节，未压缩主包 26,326,649 字节=25.11 MiB，其中 resources 23,715,800。CRC和SHA均正确仍上传失败：旧自定义writer漏查体积。私人原包、账号、路径和截图留项目，不随 Skill 分发。

## 源头修复

优先在源码设置目标小游戏普通分包，再由匹配版本 Cocos 重构独立输出。确认 subpackages/resources、game.json 声明、settings bundle列表、ccRequire以及config/import/native路径一致。不要把大资源设成独立分包来逃主包限制；普通分包计总量，独立分包另有4MB限制。不要降低清晰度、删引擎或盲删运行时资源凑数。

若维护材料只有Native，允许可重复的定点迁移脚本，但必须同步所有生产加载路径；不能只移动目录。父目录拼接、大小写、缺失pack等按现有路径/启动依赖检查拒绝。不得从另一个构建偷补文件后冒称与原输入一致。

## 分包后的启动检查

先追踪实际 game.js→main.js→loadBundle→scene→业务Main顺序。默认Native可能在业务Main之前加载resources；此时只在Main里加Retry不能覆盖早期分包失败。

只在涉及加载/分包改动时执行以下受影响链：

- 正常冷启动到真实首屏、PLAY和一次实际棋盘输入。
- 外部资源失败→错误与Retry可见→解除故障→一次可信触摸Retry→确有新请求→首屏及玩法可操作；从最终ZIP独立回解再验证。
- 原始请求、进度、回调失败证据先排除输入未命中，再诊断缓存。一次本地案例曾因Canvas根未居中而使Retry出屏，Label与Graphics同根还改写点击尺寸；用固定根hitbox和独立渲染子节点，并实际读回几何/输入结果。
- 若修改watchdog，定点模块回归覆盖无回调、原timer不触发、同值进度不续命、递增进度续时、后台不计时和旧回调隔离。不固定总加载时长；不要只延长超时或添加永远成功的SDK空实现。

浏览器映射原Native资源不等于真实小游戏adapter/tt.loadSubpackage；明确运行器、运输差异、未覆盖SDK和物理设备。缺工具不得伪造运行通过。

## 强制且有限的拒包条件

所有writer共用生产 native_problems/verify_native_zip 判据：主包≤4,000,000、总包≤30,000,000、独立分包各≤4,000,000未压缩字节。写临时ZIP前检查输入，最终ZIP再核条目与原Native全量SHA，失败不发布ZIP。普通分包大于4MB而总量合法应通过，避免错误限制造成过度拆包。

成品维护用 build_checked_zip.py；完整制作用原适用writer。禁止项目自制candidate合同绕过体积/启动闭包检查。发现旧脚本漏检，保留故障原件并停用输出入口。

校准用 test_package_checks.py：压缩后极小但主包超限、总量超限、独立分包超限必须拒绝且不调用archive writer；合法大普通分包必须通过。真实旧包同检查器拒绝、最终包通过，证据留项目。

## 停止扩测

每次出包做文件身份、体积、启动闭包、资源引用、最终字节一致检查。仅对改动影响的路径做运行回归；同版已验证结果不重复演示。只有新改动、失败或具体疑点才增加检查。文档更新不触发游戏构建；分包维护不自动重做玩法、美术或完整奖励CI。存储等额外故障只有实际复现后才定点修复与回归，不能把本案例的全部旁支扩成每包必测清单。

通过这些条件只能阻止已知同类错误，不能承诺未知平台环境永无故障；平台接受状态以真实上传回执为准。
