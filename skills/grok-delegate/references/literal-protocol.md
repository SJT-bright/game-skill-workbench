# 原文搬取协议

这是调用格式，不代替主 Agent 对任务是否适合委派的判断。文本有稳定解析规则时，直接使用解析器。

contract.json 示例：

```json
{
  "fields": ["名称", "日期"],
  "items": [
    {"id": "card-001", "source": "/绝对路径/cards.txt", "start_line": 1, "end_line": 3}
  ]
}
```

source 必须为已授权读取的 UTF-8 文本，行号从 1 开始且包含末行。items 由主 Agent/工具建立，不由 Grok 决定是否相关。每个范围是一条局部独立记录，保留原字段与紧邻说明；不要切掉否定或限制条件。80 行/12000 字符是脚本为了限制局部搬取设定的工程上限，不代表科学安全阈值；短记录同样可能复杂。

要求文件可写：“逐字搬取每条记录中明确标注的名称、日期。名称和日期无法直接对应、存在多个候选或未写明时返回 null；不判断最新版本。”

模型回复：

```json
{"items":[{"id":"card-001","fields":{"名称":{"value":"灯塔","quote":"名称：灯塔"},"日期":{"value":null,"quote":null}}}]}
```

必须包含每个 ID 和所有字段；每个非空 value 是对应 quote 的子串，quote 是该 ID 局部记录的子串。检查严格保留字形、符号、数字与日期写法，不自动做 Unicode/单位/相对日期标准化。脚本不验证语义对应，也不证明不存在未纳入 contract 的材料。

- raw.json/result.txt：原始模型输出，不直接进入交付。
- checked-result.json：覆盖和逐字证据检查通过，仍等待主 Agent 审查。
- receipt.json：源文件哈希、状态、需复核的 null、用量和耗时。

主 Agent 将要采用的每个字段与原文对应关系核对，检查 null 是否漏取、输入范围是否完整。一次引用子串检查通过不能自动签收。失败保留回执，局部格式问题可代码修正；需要语义判断则由主 Agent 完成，不把原提示再付费跑一遍。

图片转录使用另一技能，其回执证明实际读取但不保证识别正确，不能用文本子串检查代替看原图。

## 额外完整性检查（2026-09-22）

拒绝 JSON 重复键、NaN/Infinity、未知 contract 字段及非法行范围。同一源文件在一个批次只读取一份输入快照；回执里的 contract 由实际已加载范围生成，不重新读取可能已变化的 contract。调用结束后复核源文件哈希。

对于能按“字段名：值”识别的完整字段段落，检查整个值而不只是子串。例如 `编号：0012` 不接受 `12`，`状态：未完成` 不接受 `完成`，`金额：12万元` 不接受 `12`。可以排除句末中文句号，不能丢单位、否定或限定语。同一字段出现多次时不选最后一个，交回主 Agent；缺少字段标签的引文不能为这种字段作证。复杂、非标准字段关系仍要由主 Agent 判断，不能将这个格式检查当成语义校验器。

null 继续列入待核对，不能当成“原文不存在”的证明。回归测试可离线运行，不调用 Grok：

```sh
# 历史自测依赖旧机回执；未迁移，生产脚本与现行规则已包含。
```
