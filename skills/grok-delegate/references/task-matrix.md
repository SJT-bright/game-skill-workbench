# 质量优先的三类边界

类型：综合页。2026-09-22 更新，取代此前 21 类宽泛候选矩阵。依据见 [来源页](sources.md)、[调研结论](quality-boundaries.md)。不声称 Grok 是弱模型；这是用户限定的任务分工。

## A · Grok 仅可做原样搬取/清晰转录

以下均须主 Agent 先限定材料与范围，并能逐项核验。存在文本层/DOM/API/解析器时优先工具。

| 子任务 | 允许的最窄操作 | 立刻转主 Agent 的边界 |
|---|---|---|
| 清晰截图/扫描页 | 抄写指定区域的印刷文字，保留原标点与行顺序 | 模糊、手写、公式、文字重叠、需要补词 |
| 图片内标签 | 抄按钮名、页标题、明确状态文字 | 判断按钮是否可用、体验是否合格 |
| 简单表格 | 在行列已明确、无合并的局部表格抄单元格 | 跨页表头、合并单元格、脚注、公式和单位推算 |
| 独立资料卡 | 搬取明确标注的姓名/编号/标题/原日期 | 同名消歧、缺失补全、选择哪个日期有效 |
| 已选原文 | 原样抄主 Agent 指定段落/范围 | 自行找重点、删“无关”段落、判断是否支持论点 |
| 明示标签 | 复制记录中已经写明的“类型/状态” | 看内容推断分类、把相似标签归并 |
| 显式任务表 | 复制“负责人/截止时间”字段原值 | 从聊天判断承诺、谁负责、哪个安排最新 |
| 媒体画面文字 | 抄固定帧中清晰字幕/标题 | 自动听写、断句润色、剧情解释或人物情绪判断 |

“允许”不等于“必须派发”。纯文本搬取大多可被工具完成；真正有价值的 Grok 候选主要是文字无法直接提取、但清晰且可验证的图片输入，以及少量格式不统一的局部字段搬取。

## B · 交给确定性工具

| 子任务 | 首选方式 |
|---|---|
| PDF/Word/PPT/网页现成文字 | 文本层、OOXML、DOM、可用读取工具 |
| 查某个明确字符串/引文 | rg、精确搜索、行号与上下文输出 |
| 字数、频次、金额合计、排序 | Python/SQL/表格公式 |
| 完全相同文件或文本去重 | 哈希、精确比较 |
| 文件清单、尺寸、时长、分辨率 | 文件系统、媒体探针 |
| CSV/JSON/字幕格式转换 | 解析器和序列化器 |
| 指定一对一替换、占位填充 | 字符串/模板工具，检查占位符 |
| 已知 schema 的合法性 | schema validator、类型检查 |
| 代码符号清单/实际差异 | AST、rg、git diff |
| 截图/文档渲染、裁片 | 专用渲染工具，裁片不冒充视觉验收 |

## C · 不自动委派 Grok，由主 Agent 完成

| 看起来简单的任务 | 实际需要的判断 |
|---|---|
| 总结/归纳/提炼重点 | 信息取舍、否定和例外、隐含关系、完整性 |
| 评论主题/情绪/需求分类 | 语义理解、标签边界和多重含义 |
| 语义去重/聚类/实体合并 | 同一性与差异是否影响结论 |
| 相似资料筛选/相关性排序 | 哪些证据会影响答案，漏掉的反例是否重要 |
| 找支持结论的引用 | 事实蕴含、范围、条件与反证；不同于找指定原句 |
| 普通/专业翻译、改写、润色 | 含义、语气、术语、歧义、隐含承诺 |
| 字幕断句/口头语删除/清稿 | 说话含义和节奏可能改变 |
| 会议结论/需求条目生成 | 区分讨论、假设、否决和真正决定 |
| Wiki 摘要、概念/实体关联 | 跨来源知识判断与冲突管理 |
| 搜索词扩展、研究方向 | 影响检索覆盖与问题解释 |
| 日志归纳/报错解释 | 合并信息可能掩盖时序、版本与根因 |
| 代码讲解、diff 总结、代码审查 | 程序语义、上下文、边界条件与实际行为 |
| 测试设计/预期结果/样例生成 | 覆盖缺陷、规格、正确结果的独立依据 |
| 图表趋势/数据解释 | 轴、单位、比例与因果，不能由读字替代 |
| 排版/审美/构图/角色一致性 | 需要实际视觉判断；主 Agent 直接查看原图 |
| 教案、剧情、分镜、需求方案 | 教学、创意、技术和目标取舍 |
| 回答封闭式 FAQ | 仍可能要解释条件或合并条款；不归入纯复制 |
| 最终回答和验收 | 由主 Agent 保留完整上下文负责 |

## 一票否决条件

需要压缩、选择、推断、补全、解释、改写、跨段指代、跨资料合并、排序重要性、给建议或技术判断；没有可行的逐项核验路径；核验与重做一样费力；复杂 OCR 或缺少原文。任一成立则留给主 Agent，不能用“后面会检查”给语义任务开例外。

## 2026-09-23 字段核对路由澄清

“填写后检查姓名/学号/日期是否显示正确”是局部清晰读字，主动看图前先调用 Grok；主 Agent 再逐字比较。它不属于整体审美验收，不能因为处于交付收尾而跳过。整体布局/审美仍留主 Agent。Grok 的识别提示不预填预期答案。
