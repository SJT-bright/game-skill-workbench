# 共通首页与声音：设计、实现及检测

这是全 UI 设计中的独立环节：先完成共通部件的主题设计与实际接线，再进入视觉、功能及触屏检测；测试包前逐项复查。新制作的每款游戏都提供本页的音乐、音效及两个平台入口。英化时（英化入口第 2、3 项）：**两类声音开关和十格音量也要有**（原来没有就加，图标和面板按原游戏画风），**原声音文件保留不换**；两个平台入口也要补。用户指定局部维护时只处理当前范围，不追溯重做其他已结项游戏；未涉范围有依据地保留，不借通用规则扩大玩法或外部操作授权。

共通的是功能和状态语义。材质、构图、字体、图标轮廓与位置分别贴合本游戏，不能复制另一款的背景、木板、坐标、音乐或广告奖励。具体曲目、音色、单次音效时长与游戏事件保留项目约定；全局两类声音控制属于通用要求。

## 检测之前先完成设计

在本游戏 UI 清单中单列首页平台入口与声音弹窗，记录入口、用途、资源、实际 Button/处理器和状态。使用内置 image_gen 为其设计贴合主题的背景/面板、图标与控件层级；声音展开页应是完成的设置界面，不能复用未设计的单色测试面板。局部重做弹窗不等于重画游戏世界背景。

声音页只有 **BACKGROUND MUSIC / MUSIC** 与 **SOUND EFFECTS / SFX** 两大类，可纵排或横排，另保留关闭/返回。每类同时显示用途、独立开关、实时百分比、十格音量与减/加按钮；0% 时十格全空，100% 时十格全满。动态值与开关文字绑定实际设置，不能烘焙固定百分比。两类有清楚分区及足够点击面积，关闭与正文不抢层级。

玩家界面不放 TEST SOUND、PREVIEW、音效库、单音试听、诊断状态或调试入口。不同开局、失败、点击等音效仍由真实游戏事件播放；开发核验在隔离工具/报告中完成，不把测试清单搬进玩家页面或上传包。

首页的两个平台入口与声音入口一并设计：

- **Add to Home Screen** 使用清楚的小房子图标，文字/引导说明添加平台快捷方式及实际规则；不能仅写 HOME 而与本局返回主页混淆。
- **Profile Revisit** 使用可辨认的个人主页/头像与回访含义图标，例如主页轮廓配返回箭头；不能伪装成普通返回、添加快捷方式或账号登录。

小房子和个人主页图像须在真实 Cocos 页面显示并可命中。可共享本游戏同套新生成组件，不规定固定材质、左右位置或屏幕方向。声音、主页及两个入口的真实功能不能只凭图标替换宣称完成。

**两个入口下面的说明字默认放在底板上（v7.8，U11 (b)）**：入口按钮下方或旁边的说明字（例如 HOME SCREEN +50、PROFILE +50）不直接压在首页背景上，否则 `art_check.py` 的「位置穿模」一行会报 `busy_text_background`（Holly's Hay Hop v2 的 PROFILE 字被栅栏柱穿过）。平台包的 `HomeGrowthEntries.js` 只放两个入口按钮，不画这段字，所以由本游戏自己做，两种做法任选：
- 字和入口按钮一起生成成一整张图（剪刀达人 v30、Nanas 的 REVISIT 就是这样，本来就不会报）；
- 照 Holly's Hay Hop v3 的写法（`assets/scripts/main/view/HomePresentation.ts`）：在入口节点下、说明字 `EntryCaption` 之前先加一个同级节点 `EntryCaptionPlate`（和字同一个位置），用 `cc.Graphics` 画一块 172×42 的圆角底板 `roundRect(-86,-21,172,42,21)`（填充 (246,236,214,240)、描边 (139,94,60)、线宽 3），颜色按原游戏画风换。Cocos 2.4 一个节点只画一个渲染组件，底板必须是单独的节点；先加的兄弟节点先画，底板才在字下面（做成字的子节点会盖住字）。英化游戏首页原按钮不动，只给新加的这两个入口的字加底板。

## 设置页通用设计：两个标签页「功能」和「声音」（用户 2026-10-21，两个板块都用）

设置是一个弹窗（游戏中打开时面板≤屏幕 60%），标题牌"Settings"，顶部两个标签按钮 **General**（功能页）和 **Sound**（声音页），默认打开 General，右上角关闭按钮（样式随本游戏整套按钮，不规定颜色和形状）。入口：首页四周的齿轮小图标；游戏中从暂停页进入。两个页面都是完成的设计（行底板、图标、游戏字体，画法照启动包），不能是空白面板、大白板或纯色底板（`audit_page_richness.py` 查）。

**声音页（Sound）＝ 原来说的"声音页面"**，只有两大类，每类一行：

| 行 | 内容 |
|---|---|
| **Music**（背景音乐） | 音符图标、名称、开关（ON/OFF）、减号、十格音量条、加号、百分比（如 70%） |
| **Sound Effects**（音效） | 喇叭图标、名称、开关、减号、十格音量条、加号、百分比 |

默认音乐 70%、音效 100%（项目另有约定按约定）。行为按下面"两类声音的统一行为"。

**功能页（General）**，每行：图标＋名称＋右侧按钮或开关：

| 行 | 什么时候有 | 点了做什么 |
|---|---|---|
| **Vibration** 震动 | 游戏有震动时 | 开关，保存 |
| **How to Play** 玩法说明 | 必有 | 打开小型玩法卡片，或重新播放首关教程（首关互动教程（重塑包 remake-onboarding 板块，英化包不含）） |
不放：**版本号**（v1.0.3、Version 1.0.0、"游戏名 • v1.3.0" 都不行；用户 10-13 跳跃鸟"为什么在游戏里展示这个版本呢"、10-26 水果逃亡"这些东西应该是明令禁止的呀"、10-26 音乐切块"版本号也删掉"；`audit_page_richness.py` 的 `dev_info_text` 拦）、Credits/制作人员/鸣谢页面及入口、原作名和改编说明、字体授权说明、承载制作说明的 About 页、AI/GPT 分工与改编过程说明、语言切换（只有英文）、清除存档/重置进度（会误删玩家进度）、开发用的测试/调试/试听入口、FPS 面板和碰撞调试框、"LOCAL PREVIEW"这类字。从游戏中打开设置时，回首页、重玩放在暂停页，不放进设置页。

英化：原游戏的设置只有声音开关或者没有设置的，按本节补成两个标签页（图标和底板按原画风）；原来已经有、内容也够的只英化，缺的行补上。检查时 dump_ui 分别读两个标签：功能页写 `"purpose": "settings"`，声音页写 `"purpose": "settings_sound"`。

## 两类声音的统一行为

**实际输出默认验收（R09）**：接入后交试玩前按[实际互动与音频输出](../../cocos-game-check/package-check/references/drag-audio-postconditions.md)主动核实际输出与失败恢复；设置值、素材响度和播放标记不算有声。局部维护只复查受影响链。

音乐与音效各有独立全局开关和音量。音量只取 **0%、10%、20%……100%**，每次减/加一格（10%），到边界不越界；连续点击也不能产生负值、超过 100% 或浮点百分比。两类操作互不修改，开关关闭后持久保留该类上次非零音量，重新开启恢复；关闭期间百分比必须为0%、十格无填充（不能仅调暗有色填充），ON/OFF按有效静音状态显示；内部另存上次非零档位供开启恢复，不能把记忆档位当有效音量。0% 保持真实静音，不显示虚假有声。旧版连续音量按项目明确的最近格等迁移策略归一，不清空游戏进度或原静音选择。

**声音状态交叉检查（2026-10-26）**：音乐、音效各从真实入口执行中档→OFF→关闭重开/刷新→ON、减到0→ON、OFF时减/加/点格、边界连点；逐步同时核开关、百分比、亮格、有效增益和保存值，两类互不修改。OFF时减保持0，加从0到10%并开启，点格开启选中档；0后ON恢复上次非零档（无记录用默认）。扣住音频加载回调后静音，再放行旧回调；后台/广告恢复不得重新出声。原故障版须被同一判据检出，再验修复版；显示/状态检查与实际PCM试听分别记录，不能互相代替。

设置作用于实际音乐/音效总线或全部对应播放源，并按游戏/应用隔离持久保存。音乐循环、场景切换、开始/重开、暂停页及返回设置页使用同一设置；不得每开一个弹窗叠一层背景音乐，也不能关闭声音页就恢复旧音量。保存失败时当前界面与实际声音保持一致，并明确重试或会话有效范围，不能假报已永久保存。

首个真实玩家手势按运行环境解锁音频。暂停、广告开始、后台/失焦按当前平台和游戏规则暂停或压低声音；恢复时结合开关、音量和暂停/广告状态，只恢复允许播放的声音。广告关闭不能把用户关掉的音乐打开，声音页关闭不能意外恢复暂停中的本局。短音效不因切场销毁而漏掉，也不能把过时动作排队到恢复后连播。

已有合格音乐/音效优先复用；新制作缺音乐或必要事件音效时，按下方[音效库规则](#音乐与音效来源从正规音效库下载禁止ai合成)从正规音效库下载补齐，不能以“原来无音频”跳过两类设置。具体配乐风格、音效时长/音色和事件数量按本游戏设计，不把某款游戏的曲目、毫秒数或试听列表变成通用模板。

## 音乐与音效来源：从正规音效库下载，禁止AI合成

**禁止**用代码合成（Web Audio、振荡器、程序生成波形）、AI生成音频或拼凑电子音来做音乐和音效——这类声音"AI味"重、廉价感强。需要新音乐/音效时，一律从正规音效库下载真实录制或专业制作的素材。原游戏已有且合格的音频可以保留。

**怎么做：用配套 Skill `game-audio-library`**（下载、质检、自动选择、加工、播放代码、授权记录全包，Windows/macOS、Cocos 2.4/3.x 通用）。默认**自动选择**，一条命令：`python <game-audio-library>/scripts/audio_pipeline.py --project <工程>`。具体步骤、需求表、接入表和验收清单都在它的 SKILL.md，不在这里重复。

- **新制作 / 重塑**：按它的流程做全套；它提供 `GameAudioManager` 模板；接入后仍须执行下面的状态交叉检查与实际输出检查，不能因使用模板直接记通过。
- **英化**：声音文件不换、不跑下载流水线（AUDIO-02 英化不检查）；声音设置用原游戏已有且合格的管理代码，没有就照[英化固定入口·音量](../../cocos-game-to-english/references/fixed-entries.md#设置音效与-bgm-音量)写一个最小的（`GameAudioManager` 模板在重塑包 game-audio-library 里，英化包不带），接到原声音文件上，做到两类开关和十格音量（AUDIO-01 英化必查）。
- **英化游戏原来已有音频**：原声音照样保留，在 `docs/audio/sources.md` 每个文件记一行并写"原游戏自带"（知道授权的写上），`scripts/audit_audio_sources.py --project <工程> --board localize` 就算有来源、通过。这是英化口径；重塑游戏（重塑包）不许用底子原游戏自带的声音，启动包自带的声音要按启动包记录写上音效库来源，和英化不同。工程已有合格的音频管理代码时沿用，只补两类开关和十格音量。
- **授权硬规则**：只用可商用素材；禁止 NC（非商用）、ND（禁止改编）、"仅个人使用"、来源不明，CC-BY-SA 默认不用，禁止从游戏、视频、音乐平台扒录。音频模块自动把每个文件的来源写进 `docs/audio/credits.csv`；需要署名的写进 `docs/audio/CREDITS.txt`，仅作项目授权与交接记录，不因此生成 Credits/关于/制作人员界面；确有强制玩家可见署名义务时按许可证选用无 Credits 页的合规展示方式，无法满足时更换素材。
- **门禁**：打包前跑 `scripts/audit_audio_sources.py --project <工程> --binding <review.json> --out <报告>`（AUDIO-02），每个音频文件都要有合格记录。
- **下载不了时**：不改用合成声音；先换可访问的正规来源或复用合格本地素材，继续其他工作。全部受阻时把缺什么、候选链接和恢复条件写进 `docs/audio/sources.md`（标"待下载"，门禁会拦住），只有确实需要用户登录或提供文件时才说明具体操作。

## 平台入口的统一行为

保持 [主页回访功能](../../remake-core/references/tiktok-home-growth.md) 的真实 SDK 路径：快捷方式与个人主页回访分别检查能力、引导、返回资格、领取及持久状态。导航动作、资格待验证、可领、请求中、已领和错误状态分别表达；入口领取后按原任务规则保留，不互相冒充完成。没有 SDK 的普通试玩使用可关闭说明，不伪造添加、回访、登录或奖励成功。

奖励仍接当前游戏真实库存与消费，领取及下一次规则按已授权配置。声音设置不需要登录开发者后台；共通首页也不新增账号认证流程。广告入口沿用现有严格视频、取消/失败与保存门禁，不能借共通设计把免费动作变成广告。

## 接入现有检测与测试包门禁

在现有功能表和稳定检查 ID 中附逐项证据，不新增一套兼容性字段或用文档代替运行检查：

| 现有检查 | 当前范围需核对的共通部件 |
| --- | --- |
| `ART-01`、`UI-05/06` | image_gen 选用原件、实际绑定、声音背景与两类层级、首页语义图标；两种适合游戏方向的比例、遮罩/层序、开启关闭与动态状态实际组合 |
| `UI-01`、`UI-03` | 英文用途、ON/OFF/百分比与实际状态一致；没有玩家测试/试听列表；十格、减/加、关闭及两个主页入口无遮挡/误导，边缘真实可点 |
| `AUDIO-01` | 音乐与音效独立开关；0–100% 全部十一档和边界；十格/百分比/实际增益一致；首手势、真实事件播放、持久化/重开及场景、暂停、广告、前后台恢复，实际试听另记证据 |
| 现有主页/奖励检查 | 两图标的真实入口与 SDK 方法、取消/错误/已领、资格与持久奖励、真实消费者；普通浏览器无假资格/奖励 |

先在实际 Web 中操作两个开关及减/加，逐档读回数值和播放设置；分别关闭一类，确认另一类保持。离页、重开声音页、实际刷新后核设置，再走暂停→声音页→返回、正常切场及可测试的广告/后台恢复。实际听感、声音是否可闻与代码/音频上下文检查分别记录；非零 PCM 或播放成功日志不等于已听见。无法完成的分支据实待验。

两个主页入口逐个实际点击、关闭和重开，核可见语义、真实路由、能力不足与已有状态。生图后按 [全量视觉巡检](full-visual-review.md) 查看素材及当前实际组合，发现问题直接修复复查，不等待用户逐图确认。

在 [打包前检查](../../cocos-game-check/test/references/prepackage-mobile-review.md) 与实际打包入口复核本版源码、Web/Native 绑定和上述当前范围结果；遗漏、失败或旧证据不得生成新的通过结论或绕过既有门禁。GUI、浏览器音频检查、物理手机、真实 IAA 与平台接受仍分别记录。本页不追溯改变旧包的验收事实，不放宽已有源码/Native 回归、指纹或 ZIP 门禁。

## 共通复活与教程辅助入口

每款游戏按 [看广告复活与小型教程的位置审查](../../remake-ads/references/rewarded-revive-and-help-layout.md) 检查已有广告复活、补齐缺少机制；使用用户广告位，复活图像与免费 TRY AGAIN 分清。How to play 用角落辅助入口和小型内容卡片，并核当前页、比例、安全区和主动作。这里只统一审查与语义，不统一复活次数、保护秒数、材质或坐标。
