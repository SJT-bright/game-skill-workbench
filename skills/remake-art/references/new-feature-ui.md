# 新增界面在制作时走美工 Skill

固定短词（含原本已是英文的 SCORE、Claim）和奖励数字在第一次制作时按[整组文字资产](production-prevention.md#数值栏的词数字与符号整组制作)完成：固定词用完整词图，动态金额和符号用同套生成位图字形，保留真实数值绑定；Claim 可透明、单行、小号，不能退回普通深色字体。原有长正文例外保留；不等最终出包检查再补文字美工。

新增或修改实际拦截输入的弹窗/加载层行为时，按[实例归属](../../remake-core/references/modal-input-ownership.md)沿用原管理器、输入/暂停令牌，明确底板与触摸拦截的职责。首件的原操作中并入连续打开和关闭重开；同一机制共用代表件和有效证据，异步机制才补慢加载。只换图片、文字或普通侧栏时复用行为证据，不额外跑生命周期或扩大美工范围。

广告六标准类同样执行本流程：先运行同包ad-boost的 `scripts/art/skill_link.py prepare` 读取本作实际画风与本Skill；六类新增页面和状态进入原page registry与visual/capture计划，首件和受影响范围用原工具检查。共享门禁不读取一份新的全量美术回执，见[六类制作联动](../../remake-core/references/ad-standard-six.md)。

功能新增了玩家可见的页面、弹窗、子面板、按钮或 HUD 控件，或为新功能换了一整块面板，即在设计时走本流程。包括英化的固定入口和推荐广告板块、试玩反馈新增、交付后加功能，以及直接执行广告、经济或皮肤板块。功能工作已经获准时，其新增界面的制作一并进行。只改现有界面上的一处图，沿用原局部改图规则；对已交付美术的复验按本轮授权处理。

1. **定原画风和页面范围。** 从原游戏真实画面和已有资产选同类参照：面板边框、标题、主次按钮、字体、数字和奖励图标。英化以原游戏为准；重塑以已定启动包画风为准。功能逻辑先说明入口、关掉后去哪、金额来源和实际状态；美工为每个新增界面先定状态、视觉层级、留白及原资源复用计划。运行时临时面板、默认系统字体和通用按钮样式可用于调试；正式设计依本 Skill。
2. **按实际显示位置制作。** 用[美术禁区与必做项](saul-art-rules.md)和[页面设计](page-richness.md)按用途决定是否需要底板，再定装饰、标题、主次操作和相关状态。只显示图标＋数值的 HUD 按[底板决策](text-backplate-review.md#资源显示先判定是否需要底板)默认透明，不把弹窗或按钮模板套到资源显示上。能用原游戏同款素材就直接用；确需生图时带原素材和实际区域。固定短词按图文字规则做，动态金额及适用符号用同套字形并绑定真实数值，说明长句用合适的可换行字体。按[制作预防](production-prevention.md)先测最窄视口和最长内容，锁定槽位、字图来源、比例和绘制顺序。比如新增结算奖励时，可用原画风标题、奖励图标和数字、同套主操作；广告结算的 Claim 仍是一行可点的文字，按[广告的结算页规则](../../remake-ads/SKILL.md#结算页设计用户-2026-10-27)留够点击区域。
3. **接入完成后共用一次检查。** 复用现有页面登记，新增界面给稳定 ID；有 `docs/logic/pages.json` 的用 [page_registry.py](../../remake-core/references/page-registry.md) 派生 `docs/art/screens.json`，旧工程更新原有效清单。制作时先看代表原图、最大 CSS 用途与最长文案预算，不为样件另构建或另采。全部本批素材、配方、布局和接线齐全后冻结同版，复用现有采集计划；结构化采集继续用既有 Ego Lite 隔离运行器，可见点检通过 Computer Use 操作 Edge，两种目标视口各进入实际状态一次，查看截图和同帧节点。按[制作与检查联动](production-check-link.md#首件与完整检查沿用同一判定)登记适用的 `visual-slots.json` 项，唯一正式首件使用本次完整采集里的最窄或内容最多的代表数据；首件与其余适用检查共用该轮，不提前正式核完再铺量、收尾又核一次。没有图文槽时使用该新增页面的真实采集结果。新增页覆盖能改变画面的状态（如长数值、取消提示、关闭按钮位置），相同画面按现行合并规则沿用。查看原画风匹配及文字越界、重叠、比例、可见与可点击；同版有有效结果就沿用。
4. **定点修复并交接。** 用当前阶段计时记录写明「新增美工 / 页面名 / 定样、接入或复核」、参考来源、已核的实际状态及下一节点。问题回到该页和受影响的共享控件解决，补验同一范围后继续完成同版试玩；局部结果进入现有证据和 H5，写包阶段核现有交付项。既有且未受影响的画面沿用有效证据。
