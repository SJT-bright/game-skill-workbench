# 美工制作预防：把历史问题转成生产要求

Saul 2026-11-03：已有美工检查中能提前避免的问题，应在生成和接入阶段解决。依据 [美术禁区与必做项](saul-art-rules.md) T01–T14、[全量视觉巡检](full-visual-review.md)、[图集完整性](atlas-slice-integrity.md)及[动态画面](dynamic-visual-review.md)。本页安排预防动作，不替代这些来源的标准，也不新增检查阈值。

## 制作开始时怎么用

1. 按本轮资产类型选下表适用项，先确定本游戏的实际方案，再调用生图。不能只写“遵守美工 Skill”或把整份禁令原样塞进所有提示词。文字、比例、留白、风格和状态等必须填成这张图的具体要求。
2. 在已有美术清单、提示词或生成记录里保存：用途与页面/节点、原图或已认可样板、准确英文、目标可见尺寸与源图分辨率、内容内区与安全边、透明/不透明、状态变体、动态值预留位置、适用的 T 编号和采用的做法。按资产需要填写，不为单张图新建一套审批表。布局和代码约束交给接图者，不能指望生图模型处理点击层级。
3. 英化照原游戏，重塑照已确定的美术方向；用户已改或认可的部分优先。仅做当前授权范围，不因总表提到教程、皮肤或背景轮换而给英化新增系统、替换好好的背景。当前入口的具体规则优先，例如结算 Claim 是 ×2 下方可点小字；官方加载页使用标准件，不交给生图工具重画；首页尺寸沿用固定基准，不每轮翻倍。
4. 按已有代表样流程先确认高风险组合，再批量制作。能测量的空间与比例先计算；模型生成的字形、透明边缘和人物结构仍由 Codex 自己看原件。发现共性问题先改模板或共享组件，不带着已知问题继续铺量。每轮试玩前仍按现有美工流程验收。

## 历史问题对应的制作动作

| 来源 | 历史问题 | 生成与设计前就落实 | 接入时落实与仍需观察的结果 |
|---|---|---|---|
| T01 文字与数字 | 系统字冒充图片字、字小、透明边过大、0 难认、字距错乱、标题越框 | 分清完整标题/固定短词、完整按钮、位图数字、TTF 长说明。定稿英文；数字生成同高度/粗细的 0–9 和实际需要的符号，0 不加斜线、字腔清楚；单词不拆字母生图。按最长合理数字串预留槽宽，按可见字芯而非画布规划字号；标题与标题牌一体构图，描边留在安全内区。正文用真字体，不能把此项扩为全部文字图片化 | 数字裁掉多余透明边但保留完整描边，按真实字宽设置 advance、baseline、间距；词/数字/货币图标分别绑定，数据不画死。等比缩放，按现有字芯标准量最终显示；试最长值和条件倒计时，不以源图够大代替小屏可读 |
| T02 按钮 | 色块盖旧字、按钮拉扁、普通字叠底、同组风格不一、禁用状态发黑 | 固定按钮底和字整体生成，改词就重做整张；尺寸按英文和图标共同占位。共享同一原图/样板、配色、圆角与材质；正常、按下、禁用、已领状态提前设计，禁用降低强调仍保持字可读，不能用近黑乘色糊整钮。广告按钮含清楚的视频语义，图标与文案不冲突 | 文字与整体按钮等比；九宫格只用于适合伸缩的无字底板。可见图案、点击区与状态一致，按下动画最大范围也留空。特殊 Claim 小字遵循英化入口，不被“都要按钮底板”覆盖 |
| T03 配色与对比 | 亮底白字、深色粗字、深色数据条、过艳、背景抢信息 | 先选字面/主题色边与实际背景的组合，保证明度区分；不生成深色字芯、厚重深色铭牌和数字纯色色条。背景在信息区低细节，物件与背景分层，保留原画风而不默认加亮、加艳。状态变体一起规划 | 不能用整屏降亮度或深色遮盖补救局部对比；按真实最亮/最暗背景看字，弹窗遮罩明暗按场景判断，不恢复已撤销的固定亮度阈值 |
| T04 质感 | 纯色平涂、多余白底、角花堆叠、每钮一个颜色 | 物件有受光面、暗面与细边；面板有轻量题材材质且文字内区干净。按钮与面板装饰克制，不加原画风没有的高光/反光/多层饰边；透明物件不另垫白底，使用同组配色 | 不再叠代码色块、边角贴片“补精致”；与已认可样板并排看，正常层次不能被压缩抹掉 |
| T05 首页与封面 | 主角被挡、中间空、功能键太小/扎堆、背景和页面混用 | 先按现有授权布局保留主角/玩法主体、标题、主动作、功能入口和胶囊安全区的位置，再画背景与 UI。需新设计时按玩法组织，沿用固定按钮尺寸基准和功能键数量规则；入口删改后按授权收拢空位。官方加载页走现有标准件 | 锚定游戏视口而非宽窗口；透明画布不算按钮可见尺寸。英化原首页按钮保留规则优先，不借此擅自挪动；主角运动范围、长短屏与宽窗口仍看实际组合 |
| T06 弹窗 | 面板空洞、奖励区空、按钮出框、关闭键小、后景穿进面板 | 按实际内容量定面板，先分标题、说明、插图/奖励、动作、关闭区；用最长名称、最多奖励和空态规划。装饰不侵入内框；动态奖励图标和数量预留真实数据位置。成功/失败/复活等已有状态都列入资产需求，保留必要退出入口 | 先绑定数据与资源再显示面板；关闭键在正确上层、遮罩拦底层输入。世界特效与 UI 层分开；关闭恢复原状态。奖励是否每次正确出现必须运行确认 |
| T07 布局 | 越界、提示挡操作、动画扩大热区、刘海遮挡、露白黑边 | 同时规划标题/图标/数字/装饰和动画最大范围，按短屏与长屏安全区布局。为临时提示单独留区；背景按覆盖两种比例构图，重要主体留在共同可见区，边缘允许裁切；不给背景绘制无用途边框 | 背景等比 cover，UI 在游戏视口内布局；点击区按可见控件定义，不直接沿用大片透明动画图的外框。提示设寿命及页面退出清理；不隐藏必要信息来避重叠；布局算好后再显示 |
| T08 图片质量与切图 | 低清、假透明、邻图残片、断边、九宫格变形 | 按最终显示尺寸预留源像素（沿用现有 Sprite 2 倍、背景 1.5 倍等适用标准），不拿小图放大。单体优先独立透明图；确需图集则先定每格主体范围和安全间距，主体、描边、阴影全部留在自身格内；棋盘格不能当透明 | 源图完整后再打包；打包器留 padding/extrude，维护 trim/offset/rotated/原始尺寸及别名，不手猜均分框。保留未裁原图，不靠再次缩框隐藏残边；确认真实 alpha、实际 SpriteFrame 和压缩后画面，切片角色按素材用途声明 |
| T09 图标 | 单色线框、文字代替功能图标、金币后多底板、方向反了 | 先定功能语义和图案：加桌面小房子、回访头像与箭头、方向键指向对应方向；彩色且与本游戏同画法。金币、爱心等物品独立透明图，不额外垫圆块/方块/胶囊；功能图标原有底座按原样，不能拿它给所有物品垫底 | 绑定图标与真实动作，避免资源表顺序错位；动态数量角标另留位，不让透明留白制造过大的点击区 |
| T10 角色与场景 | 肢体错乱、脚悬空/陷地、半透明道路、重开白场景 | 生成前明确视角、姿态、肢体结构、脚底接触点及与场景尺度；道路/地面按需要不透明，角色与背景分层。完整角色不裁脚；模型接触点和枢轴在组装前确定 | 导入后按脚底/枢轴对齐实际地面，不能只移动截图里的位置；场景重建资源就绪再呈现。肢体质量、接触与重开完整性必须看图/运行，英化不据此擅改物理玩法 |
| T11 风格与覆盖 | 半新半旧、后加面板风格漂移、装备不换图 | 开始制作时按本轮范围列页面、条件弹窗和同类资源的用途映射；所有批次携带同一原版或选定样板。新增广告面板也用同组规则。重塑全替换与英化保留原画风分别执行，背景轮换或新皮肤仅按授权需求做 | 将新图绑定到所有受影响引用，包含动态加载与条件状态；装备表映射到局内实际资源。实际导出核对版本和 SpriteFrame，资源存在不能证明已用上 |
| T12 动画与特效 | 闪黑闪白、页面跳位、底板跟按钮动、粒子烘焙成死图 | 静态背景、角色、UI、粒子分别规划，动态图层不画死到背景；滚动背景制作可连续衔接的边缘。预先确定入场起始状态、缩放范围和每个属性的唯一控制者 | 预加载图片/字体，资源与数据/布局就绪后显示；切换就绪后再移除旧画面，失败时走现有官方重试流程。静态底板不随点击重建；取消离页旧回调，清理刮奖残留；仍需录屏查帧，物理与节奏按授权玩法，不因美术规则擅改 |
| T13 出图流程 | 角色画错、糊图填空、整页效果图代替真实资产 | 先拆为真实需要的资产、确定完整轮廓与参考；使用生图工具制作，缺主体或尺寸不合则重生成完整素材；不以模糊放大垫边填空。记录原图、生成来源与后处理关系 | 每张原件先看字形/结构/透明边，代表样在真页面确认再批量；整页概念图只作方向，不能当实际组合已通过 |
| T14 开发信息与交付 | 版本号、Credits、调试文字混进游戏、用户看到旧版 | 生图文案只用准确批准文本，不加版本、署名、Credits、水印或模型自作主张的小字；正常玩家页面从设计中排除调试面板。试玩广告模拟按现有明确标注的专用流程保留，不伪装真实广告 | 使用正式 UI 模板，调试信息留开发工具；明确排除废旧层和占位字但保留业务节点。交付同一已查导出，修改传播到所有受影响共享位置；不把这次规则更新当成历史游戏已修复 |

## 给生图工具的具体内容

每次提示词按本图填：用途及画风参考 →准确内容与大小写→可见主体宽高比/目标显示尺寸→文字、图标、装饰的空间→字面与背景的对比→完整轮廓和透明方式→本图相关的禁区。无字图明确不画文字；数字图明确字符集与基线；面板图明确哪些内区留给运行时内容，不能同时要求“空面板”和“把奖励数字画进去”。背景图不套单体图的透明边规则；角色图不套按钮的扁长形状规则。

布局、热区、图集坐标、资源预加载等写入接图要求，不能写进提示词后就当代码已实现。现有 ad-boost 提示词入口会按资产类型附加一部分通用预防规则，但具体尺寸、文案、参考和分区仍由该资产需求确定；提示词存在不证明成图符合要求。

## 验证边界

源头预防能消除错误的生产方法，生成模型仍可能错字、画错结构，运行时也可能出现状态或适配问题。因此保留原件确认、代表样组合确认和每轮试玩前检查。通过格式检查只能证明文件可读，不能证明返工率已经下降；这需要后续真实制作结果。
