# Saul 的美术禁区与必做项（跨游戏总表，必须遵循）

来源：2026-10-30 对本机 Kiro 和 Codex 全部对话的美工调查。Saul 讲美术的原话和他贴的截图逐条读过，按类合并。每条后面括号里是游戏名和日期。

**怎么用**：
- 做美术之前通读一遍。美术关逐条对照。
- "怎么查"写了检查码的，`art_check.py` 会拦；写"看图"的，在截图总览图上逐条看（`visual_verdict`），出现就写进 `open_issues`，不能写 pass。
- Saul 前后说法不一样时，以日期最新的为准，见第三节"口径变化"。
- 重塑和英化都适用。英化保持原游戏画风，但第一节里"等级、关卡号、分数、货币"和"不显示版本号、Credits"两条英化也必做（Saul 2026-10-30）。
- Saul 说"不按美工 Skill 做"或要求加速时，第一节仍要做。Meteor Blaster 10-29 跳过美工 Skill，10-30 被评"现在太劣质了，每个方块都是纯色的"。

## 一、每款游戏都有、都要设计的东西

不论题材，下面这些每款游戏都有。美术阶段逐个出设计，不能用程序字、纯色块或系统默认样式凑。

| 元素 | 必须是 |
|---|---|
| 等级、关卡号、分数、货币、奖励数、价格、倒计时 | 词（LEVEL、货币名）用生成的图片字；数字用生成的 0-9 位图字；货币配图标；放大到一眼能看清。**不能**是"LEVEL 1 • +10 PEARLS"那样一整行白色普通字，也不能压在纯色色条上 |
| 顶部资源栏 | 题材货币图标＋位图数字；底板用生成的图或不要底板；图标、数字、底板当一组检查；货币栏、等级栏、体力栏同高、同一套底槽，数字完整落在槽里不溢出；体力补充入口放在体力值旁，只在体力不足时出现；右上角留给 TikTok 胶囊 |
| 按钮（主按钮、图标按钮、关闭、返回、开关、加减） | 一整套按画风生成，字和底一起生成在一张图里；不能是纯色亮色底配普通字；功能入口是图标＋按钮底，不能只写一个词 |
| 结算页（过关、失败、复活） | 标题图片字、关卡号、奖励区（图标＋位图数字，每次都显示）、×2 按钮（最大最醒目，普通领取小一号）、弹出和数字增长动效，不留大片空白；不展示玩家看不懂的内部统计（x/y、0/0） |
| 弹窗（设置、暂停、领奖、加桌面、主页回访、试用、教程） | 生成的面板、标题牌、插图、整套按钮，不用纯色背景的方框；遮罩挡住后面的页面；面板就是边界，元素不出框 |
| 首页 | logo 标题、清楚可见的主角或玩法画面、题材场景、待机动画；功能键集中、够大，PLAY 下方合计不超过 5 个，主角左右各至少 1 个；不加排行榜；不放看不清的小字标语；不同游戏的排布有变化 |
| 局内 | 题材背景（细节不多，但不能纯色），关卡型游戏按关卡段轮换多张；物件有明暗层次；每个模式都有暂停或设置 |
| 道具、技能 | 立体道具插画和名字一起生成成一张图；剩余次数角标用位图数字；第一次出现时有图文教程卡（英文讲用途，配使用后的效果图） |
| 加载页、重试页 | 用 Cocos 官方加载动画样式（Saul 10-22："加载页面全都换成cocos的加载动画"），不用纯色底加系统字的自制页；游戏内的资源加载页也一样；RETRY 是正式的图片按钮 |
| 平台入口 | 加桌面用小房子图标，主页回访用头像＋回访箭头，按本游戏画风画，始终显示 |

## 二、分类规则

### T01 文字与数字（出现最多，AI 最常错）

| 规则 | Saul 原话 | 怎么查 |
|---|---|---|
| 等级、关卡号、分数、货币、奖励、价格用生成的位图数字，旁边的词用图片字，货币配图标；重点数字要放大、显眼 | "同时把这部分的等级的文字本身和等级的数字以及货币进行美化"（人鱼逃脱，10-30）；"重点的问题比如分数，体力，货币数，关卡数，都要明显一点，同时这一类的关卡的文字都要美化一下"（企鹅雪道，10-30）；"金币和等级，第几关了？这个为什么用普通的文字呢？"（猫咪毛球，10-21）；"你所有的数字的这种，都需要用图片去生成这种的文字。比如说货币的数量，比如说体力值，每关的关卡数量，关卡数，都需要这样去生成。这spec里面没有写吗？"（Milo's Bubble Cove，10-24）；"这里面的分数的那个文字 shots score 都需要图片生成的文字做出来。"（Milo's Bubble Cove，10-24）；"然后这里面的这些文字都也美化一下"（Mosslight Ferry，10-21，截图里 POOL 3、0 DEW · 0 HINT TOKENS、5 / 72 lights 全是系统字）；"金币按钮需要给它有一个图标的设计，图案的设计"（Meadow Match，10-22，截图里 50 COINS 写在纯色块上） | `font_number`（纯数字）、**`font_value_label`**（字和数字写在一个 Label 里，本补丁新增，登记成运行时文字也不豁免） |
| 生成的图片数字紧裁透明边，按裁掉透明边后的字芯量大小；数字完整落在槽框里，不溢出到边框和背景 | "2比5文字怎么这么小，生成出来的文字怎么这么小。"（Milo's Bubble Cove，10-24，修复时按字芯约 22 CSS px 定下限）；"图中的这个第二张图数字都传出去了，覆盖到背景了"（Milo's Bubble Cove，10-24） | 看图（`small_text` 只量 Label 字号，量不到图片里的字芯） |
| 固定的词生成成一整张单词图，不能一个字母一个字母生成再拼 | "Energy不是每一个字母都生成，而是说生成一个一体化的 Energy这样一个英文单词贴在上面"（气球快跑，10-22） | `audit_bitmap_letter_fonts.py`、`font_text` |
| 卡片下的标签、价格不能小到看不清 | "这里面的字都太小了，根本看不清呀"（TankAce，10-26，截图里皮肤卡下的 Level 1、LOCKED 10 只有几像素高） | `small_text`；图片字的实际大小看图 |
| 固定的字（标题、按钮字、页签、状态字）用生成的图片字；只换"游戏字体"不算 | "图二的美工需要重做，结合最新的美工skill去做，现在这部分应该是美工skill严格禁止的"（热气球旅行，10-24） | `font_text`、`typed_title`、`system_font` |
| 字的填充不用深色；深色只用在描边和阴影 | "文字都要重新优化呀，这里面的文字不要这种深色的体"（Ember Circuit，10-23）；"不要这种身体的深色体的文字"（BobbysBeat，10-28） | `dark_bold_text`、`dark_picture_text` |
| 不用细字和太小的字 | "那么细怎么看得清？"（猫咪毛球，10-21）；"上面的字有放大一下"（MetalMaster，10-25）；"不要那有那种看不清的小字"（Meadow Match，10-21，首页三行灰色系统字标语）；"道具这部分的文字放大一些，对用户不太友好"（StarPop，10-26），18 分钟后又说"文字也太小了" | `plain_text`、`small_text` |
| 不用普通字加黑描边冒充设计字；描边和字一起生成，用比底色深一档的主题色 | "你的这个黑色描边的字体有点丑"（火柴人密室逃脱，10-12） | 看图第 1 项 |
| 字形好认：数字不过粗，0 不带斜线 | "一二三四五六七八九十它都分不清，就是它太粗了"（跳跃鸟，10-13）；斜线 0 被看成禁行图标（热气球旅行，10-24，截图） | 看图 |
| 字距均匀、不错位、不叠字；只在某些状态才出现的字（体力栏下的倒计时等）也要查 | "这上面的文字都错位了"（冲鸭小巴，10-17）；"这两个部分怎么回事啊，把这部分检测也放进给我测试包的时候"（停车英化，10-27，体力倒计时字距没查到） | `glyph_overlap`、`negative_spacing`、`font_advance`、`font_advance_rendered` |
| 页面标题、结算标题、弹窗标题一律高对比，用生成的花体图片字，和背后的标题牌一起设计成一体、占满标题牌；不把单色字直接压在花纹底上 | "同时以后的标题页面都需要用对比度高的"（团子快回家，10-17）；"标题类型的文字都要用图片的花体字去生成那个标题的部分，这个也要写进skill"（快递拆拆乐，10-17）；"你整个标题和背后的框都重新设计成为融合一体的那种"（快递拆拆乐，10-17） | `low_contrast`、`typed_title` |
| "LEVEL" 和后面的数字用同一套画风的字；"所有的这个都被禁掉了，不要直接用单纯的文字" | "包括那个文字不要用深色的颜色。然后也用文字，用图片生成的方式……不要直接用单纯的文字。"（最强推球，10-22） | `font_value_label`、`font_text`、`font_number` |

### T02 按钮

| 规则 | Saul 原话 | 怎么查 |
|---|---|---|
| 按钮的底和字一起生成成一张图；不能纯色矩形加白色普通字，也不能"背景板加文字覆盖"；按钮风格跟标题 logo 一致 | "关键的按钮都是连同文字和背景一起在图片中生成的，重做所有的按钮"（黑洞吞噬，10-17）；"不要采用这种背景板加文字覆盖的形式，我要是一次性生成对应的按钮图"（Too Lit，10-22）；"所有的按钮结合它的这个标题，这个标题的这些风格……去设计"（气球快跑，10-22）；"看广告的按钮需要是图片重新生成一下的，现在这个太粗糙了"（Ember Circuit，10-23）；"不要这种一坨背景，然后上面放一些文字，而是说连同背景和文字都是花体的"（团子快回家，10-18，道具按钮）；"以后不要出现这种纯色的很亮眼的按钮搭配没有使用图片生成的文字的搭配，在第一轮的美工skill里面要沉淀下来进行约束"（Meadow Match，10-23） | `spliced_button`、`bare_button`、`flat_button` |
| 2D：一层轻渐变、一道深一档的边、一层软投影；不加高光条、反光点、闪光、多层描边；不艳丽 | "你的按钮都需要是2d的，不要3d这种"（冲鸭小巴，10-16）；"同时按钮的美工都太艳丽了"（10-28） | 看图第 5 项 |
| 同一页、同一组按钮同一套底板和字；后加的按钮照原有样式做 | "图一这两部分的ui美工设计需要和上面的相同啊"（Happy Cup，10-23）；"把新按钮字换成原版泡泡字风格"（Ingrids，10-28） | `off_style_button`、`mixed_caption_style` |
| 按钮等比显示，不压扁不拉伸 | "你现在所有的这个按钮怎么都是扁着的？"（火锅大逃亡，10-19）；"并且这个按钮是被压扁的"（丛林荡藤，10-30） | `squashed_text`、`squashed_picture` |
| 两端磨圆，不做尖角 | "为什么边边是尖的呢？这种的很廉价"（农场水渠，10-22） | 看图 |
| 看广告按钮是能吸引点击的图片按钮：视频图标、奖励物图形、奖励数；按钮整体不死板 | "看广告，一定需要做个图片能吸引人点击的看广告按钮"（极限滑雪，10-16）；"这些按钮都有点太死板了……尤其是让看广告的这个按钮更吸引人一些，让人有点击的欲望"（埃及宝石，10-15）；"看视频没有让人点击的欲望"（快递拆拆乐，10-17） | `font_value_label`；其余看图 |
| 可点的东西必须有按钮底板 | "Home按钮需要有类似于一个按钮吧，就不要，不只是一个文字"（火柴人密室逃脱，10-12） | `bare_button` |
| 改按钮上的字要重新生成整张按钮图；禁止拿色块盖住旧字再叠新字。一处发现后全局排查同类按钮 | 欢乐刮水果 10-24 两次：试用弹窗和结算 ×2 按钮中间都被一块平涂黄色矩形盖住、上面叠系统字，"这部分也要修复" | `spliced_button`；色块盖字看图 |
| 可消耗的道具、技能按钮显示剩余数量角标；不可用时变暗，可用时才变亮 | "下面的按钮有多少个数量，现在没有显示出来，这个部分美工需要进行设置"（10-23）；"上面需要标记数量"（像素矿工，10-25）；"技能需要能用的时候才变亮"（像素矿工，10-26）；"然后次数的那个数字也要符合我们的美工设计"（甜点消消乐，10-26） | 看图（数量角标的数字仍归 `font_number`） |
| 结算页看广告 ×2 是最大、最醒目的主按钮，普通领取做成小一号的次按钮 | "把快乐汉堡店结算页面的广告二倍奖励改成最明显的主按钮，普通领取按钮小一点"（快乐汉堡店，10-28） | 看图 |

### T03 配色与对比

| 规则 | Saul 原话 | 怎么查 |
|---|---|---|
| 数据后面不铺任何颜色的纯色方块（米白、深蓝、蓝色都不行）；要底板就用生成的图 | "数据后面有纯色背景的在skill也要限制住不要再出现，放在第一轮的美工设计这一部分"（冲鸭小巴，10-23）；"这种深颜色的背景，字体然后全都遮盖上了的这种的美工需要在skill里面命令禁止再次出现，放到第一轮美工检查里面"（黑洞吞噬，10-24，每日奖励页的深青实心长条）；"你把金币后面的那个背景的那个蓝色的给它去掉吧"（坦克，10-27）；"不要用这种深颜色的，这个颜色不要再出现这种填充满的深色的背景的颜色，不要再出现我的任何一个游戏里面了，永远地禁止。"（Milo's Bubble Cove，10-24）；Sammy's Citrus Splash 10-25：代码从胶囊图中间切一块深棕纹理，拉伸成所有数字的底板，被要求返工 | **`flat_value_plate`**（本补丁新增，`art_check` 单独一行）；深色的另有 `dark_solid_text_backplate` |
| 亮背景上不放白字；按钮不过亮；整体不过度鲜艳 | "尤其是这个很亮的背景下，这个白色的字很晃眼睛"（冲鸭小巴，10-21）；"按钮的颜色不要这么亮，现在整体太亮了，看不清文字了"（农场水渠，10-22）；"里面这个字和背景低对比度，这个不是在美工skill里面约束过了吗，为什么又再犯了一遍？"（Milo's Bubble Cove，10-24，浅底浅色小字）；"美工过度鲜艳"（10-29 检查要求） | `low_contrast`；整体看图第 3、4 项 |
| 字和底拉开明度对比，但不靠给字加厚重深色铭牌解决；高对比要靠字本身（字芯和描边）；需要底板时用画风统一、中明度、有材质的生成底板 | "我强调的高对比度的文字和背景是需要文字本身，这个深绿色的要被严格的限定进skill，不要出现，最好你在生成的时候就不要生成这个深绿色背景"（Pippa，10-25）；"主页的文字的对比度都高一点，不要和背景融合了"（快递拆拆乐，10-17）；"这个文字要做出一些区分度……文字需要做出同等风格的区分度高对比度文字否则认不出来"（最强推球，10-22）；改成深色铭牌后又被要求重做（最强推球，10-26） | `low_contrast`、`dark_solid_text_backplate`、`flat_value_plate` |
| 不能点的按钮可以变暗，但字要看得清 | "然后点击 Gift之后，它里面的这些文字怎么都是暗着的呀？都是什么问题？去全量地解决一下。"（Milo's Bubble Cove，10-24） | `low_contrast`；看图 |
| 暖色、明亮画风里不用深藏青、近黑的色块（标题牌、按钮、计数牌、说明条、弹窗边框） | "把这个颜色，深色的这个颜色全部给我去掉，不要在这个游戏里面再出现这个颜色的设计了。你为什么要拿这个颜色做设计呢？"（团子快回家，10-17） | `audit_dark_area.py`、`flat_button`；小块看图 |
| 有按钮的页面背景要简单，背景细节不能抢按钮 | "现在背景太复杂了，导致它的这些按钮都看不清了"（团子快回家，10-17） | `busy_background` |
| 玩法区不用大面积很浅的颜色和很浅的字 | "不要这样很浅的这种颜色、字体这种体，就把它变成一条条路"（MabelsBus，10-28） | 看图 |
| 调"太亮、看不清"时只降亮度、加清晰度，不把 UI 简化成扁平框 | "你现在的UI全都也要推翻重新设计，不要简化，要和游戏风格适配，我只是说不要那么亮"（激光宝库，10-22） | 看图 |
| 地面、背景低对比，衬托角色和道具 | "这种格子的地板需要推翻重做"（糟糕发型日，10-23） | `busy_background`；看图 |

### T04 质感与精致度

| 规则 | Saul 原话 | 怎么查 |
|---|---|---|
| 简洁不等于纯色色块：游戏物件和角色要有明暗层次（受光面、暗面、细边），同类物件颜色有变化 | "美工再精致一点，现在太劣质了，每个方块都是纯色的，需要改善"（Meteor Blaster，10-30）；"方块颜色再多一些变化"（同上） | 看图第 3 项 |
| 透明素材下面不垫多余的白底、浅色圆角底 | 剪刀达人 10-22 美工全面测试：透明纸艺素材下面叠着白色圆角矩形 | `plain_block_ratio`；看图 |
| 面板、弹窗、背景、礼盒不用纯色平涂，有贴合题材的材质，但文字周围干净 | "不要这种纯背景纯色背景的，很单调的这种感觉"（行星射击，10-21）；"你这个里面的这个礼盒，它的制作太粗糙了"（懒猫跑酷，10-26） | `plain_block_ratio`、`flat_background`、`monotonous` |

### T09 图标

- 彩色、和画风一致；不用单色线框图标。看图第 2 项。
- HUD 指标（速度、生命、人数）用图标，不用英文标签堆成一张表。
- 设置只用一个齿轮图标，不配字，默认放左上（Ingrid's Snowball Stack 10-26 说"设置的按钮应该在左上角或者右上角"，右上要避开 TikTok 胶囊）。
- 设置图标和其他按钮同一套风格（同样的底、立体感、配色），不用白圆底扁平图标："图三的设置的图标风格也要和我们其他按钮统一"（冲吧柯基，10-24）。
- 功能入口是图标＋按钮底的图片按钮，不能只写一个词："右边的 Gift居然没有它的这个礼物的礼盒的图案。这个问题怎么能这样出现呢？怎么用一个文字表示出来的呢？"（Milo's Bubble Cove，10-24）。
- 加桌面、主页回访入口每款都有，按本游戏画风画成图片图标按钮，不能只是文字："没有个人主页回访和桌面快捷方式啊，都加上"（GimblesGem，10-28）；"怎么能单纯的就是一个文字呢？是和这个游戏风格相同的按钮"（球球乐消除，10-26）；"一个是需要小房子，另外一个是结合它的信息重新设计按钮"（Flower Match，10-16）。

### T10 角色、模型与场景

- 3D 路面不能半透明："这透明的路也要修改"（企鹅雪道，10-29）。
- 3D 模型细节要做精细："建模精细5倍"（企鹅雪道，10-30）。
- 重开一局场景完整重建，不出现大片纯白（冲鸭小巴，10-17）。
- 玩法区画成贴合题材的场景，不是一块浅色面板（MabelsBus，10-28）。
- 不用悬空的纯色几何圈当落点提示；角色脚底贴合平台（跳跃叠层，10-26，截图里平台上方悬着一个黄色空心椭圆）。

### T11 风格统一与换皮完整度

- 一整套风格一次换完再交付，不能半新半旧；逐页查有没有旧图、旧图集碎片、纯色占位、中文图片字。局内道具点开的弹窗也算："在局内点击下面功能键的时候会弹出原来的原游戏的那个窗口。现在需要你把所有的美术全都检索一遍"（Googly Eye Recall，10-23）。
- 用户指出一页的问题后，同一类问题要主动查遍所有页面和共享控件（结算、暂停、复活、设置、提示）一起改，不等用户逐页发现："为什么这些美工都要我等着等着我去发现呢？"（C-0162900b81）。这条和"只改用户指的那一处"不冲突：后者是不推翻已认可的画面，前者是同类缺陷一次修全。
- 关卡型游戏的局内背景要有多张，按关卡轮换："不同的关卡，每五关换一个，或者是每一个关卡就换一个，几个背景轮着换"（气球快跑，10-22）；"反正总共100关，你就生成10个图片，一共11个图片，还有一个是封面就可以了。"（团子快回家，10-18）。
- 皮肤装备后，局内对应的物件外观要真的跟着换："买完皮肤之后，游戏就对应进行对应的变化了"（最强推球，10-26）；"皮肤没有仔细设计好啊。"（Meadow Match，10-22，上一轮只改了收藏卡的边框颜色）。
- 换皮全量替换，底子原图一张都不留："和原来的一点都不可以相同"（BadHairDay，10-19）；"美工没有完成全量的替换啊，都要重做一下美工"（企鹅雪道，10-30）；"原来的贴图还没做干净"（剪刀达人，10-28）。交付前逐张和原版比对哈希。
- 同一类图整套做齐、同一画风："补三张章节标题图"（GimblesGem，10-28）。
- 新加的皮肤、角色沿用原游戏画风，是完整原画，不用几个色块或斑点凑数；最高稀有度明显更精致："全部按照游戏原来的这种风格去设计15款皮肤呀"（Double Jump Duo，10-23）。
- 英化不改画风，只换文字（含图片里的字）；新加的按钮照原版字体风格做。但等级、货币英化也要美化（10-30）。
- 用户自己改过的美术以用户版本为准；用户只指出一处时只改那一处。

### T12 动画与特效

| 规则 | Saul 原话 | 怎么查 |
|---|---|---|
| 点按钮、翻页、调音量、开关弹窗、消除时不闪屏、不空帧 | "这个问题必须沉淀进检查的skill，出现很多次了很多游戏都有"（音乐切块，10-26）；"就是在我点 on 和 off的时候，它会闪屏"（StarPop，10-26）；"第二个页面点击看广告会闪屏"（StarPop，10-26）；"为什么每一次都是第一次点击新页面的时候会出现闪屏"（Lumen，10-27：第一次切页不要马上弹全屏 Loading） | **`art_check` 新增"动态闪屏"一行**：录屏放在 dump 目录的 `frames/`，跑 `audit_frame_glitches.py` |
| 滚动背景连续，不一段一段刷新 | "再去把背景的一一次一刷新给修复了，看看能不能做一个长图"（热气球飘飘，10-30） | 看录屏 |

### T13 出图流程

- UI 底板、按钮、标题、图片字、首页图都用 GPT 生图（Codex 内置 image_gen）按画风生成，不用代码画的纯色控件。
- 生成的角色、物件图要逐张看有没有画错、肢体错乱，错了就重新生成："现在猫咪的模型是错乱的，包括第二个图也很多错乱的，现在重新生成图"（喵咪小吃铺，10-21）。
- 填补空白要重新生成整张图，不用同一张图模糊放大去填："不要有这种模糊的遮挡，并且统一美术风格"（切水果，10-29）。

### T14 玩家看不到的开发信息

- 版本号、Credits、原作名、AI 署名、字体授权、FPS 面板、碰撞调试框都不出现在玩家画面上："为什么在游戏里展示这个版本呢"（跳跃鸟，10-13）；"这些东西应该是明令禁止的呀"（水果逃亡，10-26）；"删除credit这部分然后，版本号也删掉"（音乐切块，10-26）。诊断标记也一样："又出现老毛病了，又出现什么V9了，这啥意思啊？"（10-16）；"为什么上面文字还有v11 sdk miss"（10-15）。"然后第二个图片不要显示版本号。"（冲吧柯基，10-24，设置页写着 CORGI RUSH • English Edition / Original artwork and music retained / v1.0.0）。FPS、Draw Call 面板也一样（甜点消消乐 10-26 截图）。测试按钮和模拟广告也算："这里点击上面的按钮就获得了，也没看广告啊这个绝对的问题"（Meadow Match，10-26）；排行榜上的 "SIMULATED · Computer rivals" 也是（Meadow Match 10-23 截图）。**`dev_info_text`**（本补丁新增）拦这些，也拦 English Edition、Simulated、Test Ad、模拟广告；设置页规格里原来的"版本号 必有"已删。
- 改完要在 Saul 实际打开的那个预览或包上复查，同一页的同类问题一起改："还是存在啊，这个问题怎么回事，检查之后还是存在说明检查的不到位"（Meadow Match，10-24；原因是 AI 查的是候选版，Saul 打开的是旧预览，而且只换了他点名的按钮，同页的系统字没动）。
- 只改显示问题时，只截图确认那一处："我只需要很简单的改一个显示问题，你就去把游戏内都跑了一遍"（剪刀达人，10-30）。
- 美术自检查出的问题直接修，不要只交一份报告（停车英化，10-24："以后这样的报告不要给我……遇到问题就去解决"）。
- 沉淀进 Skill 的规则要通用；单款游戏的个性化改动留在项目里，或改写成所有游戏都适用的检查（潜水艇，10-15："或者是你把个性化修改转化成能够通用的，所有游戏都能共通的进行检查的这样一个清单"）。本页就是按这条写的。
- 每次漏检都要把查法写进美工 Skill，并用没修的旧版回测，确认新查法能抓出来（剪刀达人 10-24、10-25 两次原话一样："对照skill查看为什么利用美工skill制作和美工检查的时候没有发现出来这个问题……用你沉淀好的模拟的美工skill去验证检测你没处理版本的画面"）。
- Saul 给了具体数值就照做，不打折："这个些功能键的大小都要是目前的两倍大小"（像素矿工，10-23），当时 AI 只从 84 放到 110（约 1.3 倍）。改完在回复里写明前后数值。

## 四、还没有脚本的项

下面几项现在只能看图，交付前必须人工看：
- 弹窗和页面的明暗（Saul 10-31，不做数值门禁）：明暗跟游戏风格走，整体不要太亮；不要暗沉、没有设计图案的背景（一张黑遮罩加一个空底板、纯色块都不行）；按钮和图标要么是新生成的图，要么沿用原游戏的图案。
- 复活、结算页上下的黑边。
- 物件有没有明暗层次，按钮有没有多余高光。
- 角色、旗子有没有陷进地里或悬空。
- 首页主角看不看得见、待机动画和背景动不动（看录屏）。
- 图集里的切图残片：独立 PNG 已由 `check_native_sprite_sources.py` 按实际显示的帧查；但打进图集的切片，`audit_atlas_slices.py` 只查 `icon_`、`node_`、`btn_`、`digit_` 开头的，图片字、局内棋子、投射物、障碍的切片不查（Ingrid's Snowball Stack 10-26 连续三轮漏的就是这几类）。
- 图片里的字芯大小：`small_text` 只量 Label 字号，生成的图片数字留边太大、字芯很小时量不出来（Milo's Bubble Cove 10-24）。
- 从别的图切一小块拉伸成的数字底板：`flat_value_plate` 只认占位图和 4px 以下的小贴图，切块拉伸的要看图（Sammy's Citrus Splash 10-25）。
