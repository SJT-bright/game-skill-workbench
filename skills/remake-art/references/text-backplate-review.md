# 文字本身的对比度与深色实心底块短检

对比度只按负向判：字芯不能是深色/近黑，描边要沿字形走、不能连成实心块，也不能细到发丝一样看不清；具体字色、描边色按启动包画风。禁止深绿色以及其他深色实心文字背板/数字值槽，包括极小单字底砖；生成图烘焙、Graphics、Sprite、CSS 等做法同样适用，不以颜色比例或对比度达标豁免。

1. **生成前约束**：提示词明确“真实透明字形；字芯不用深色/近黑，不用发丝细描边；无深绿/深青/近黑实心底块、矩形字砖、数字值槽”。生成后检查 Alpha 和图集切片，拒绝假透明、相邻碎片、底块；不把“高对比度”写成“浅字配深底”。
2. **组装后逐字看**：同帧整页＋文字局部，覆盖最短值、多位值、分隔符和数值更新后状态；追踪共用字形、Graphics 填充与实际 Sprite。手机尺寸切换后重载，使用相机投影校准字框与截图。`ui_dump.js` 记录 Graphics 填充色，`art_check.py` 的独立“文字与数字后深色实心底块”行通过才交候选；整屏深色占比、Label 颜色、节点名、已有对比底图豁免都不能代替本项。
3. **局部判据**：`check_text_backplates.py` 在实际文字周围找低亮度近似纯色连通块及连续内部面积，同时要求对应独立 UI 填充/文字贴图；自然场景暗部不当作 UI 底板，细描边须沿字形而非连成实心块。脚本是定位辅助，仍须主 Agent 看实际合成图；截图缺失、相机坐标未校准、生成贴图 Alpha 不明时不得记已验。
4. **先反例后固化**：精简候选先放项目；同一方法须检出未修版真实截图和运行节点，再修共用来源，以两种手机比例复查同屏与数值更新；沿字形的描边、自然背景、非深色的纹理胶囊作正常对照。修复后再次检出残块或字变弱就继续修，不靠删报告或降标准放行。

## 文字身后太花（v7.8，`busy_text_background`）

没有底板的字（Label、位图字；按钮上的字和自带字图的不算）要放在安静的背景上。量法：把字按 24 像素高缩放，取字框外半个字高的一圈当背景样本，字框里和样本颜色相近的像素算背景、其余算字墨，数这些背景像素要多少种颜色（每通道 16 级）才盖住 90%。超过 13 种就报「加底板或挪位置」。

门槛怎么定的（W88，10-30，真截图）：安静的 3～11 种（Holly v3 PROFILE 加底板后 4、Meteor 250 在胶囊上 3、Nanas 地图 6、丛林荡藤 BEST 6、Maya 复活说明 8、Holly SHORTCUT 5～11）；太花的 16～119 种（Holly v1/v2 PROFILE 压栅栏 16～30、泡泡六角龙结算分数压彩球 28、水果逃亡章节行压厨房 119）。13 在两组中间。
