# 文字本身的对比度与深色实心底块短检

对比度只按负向判：字芯不能是深色/近黑，描边要沿字形走、不能连成实心块，也不能细到发丝一样看不清；具体字色、描边色按启动包画风。禁止深绿色以及其他深色实心文字背板/数字值槽，包括极小单字底砖；生成图烘焙、Graphics、Sprite、CSS 等做法同样适用，不以颜色比例或对比度达标豁免。

## 资源显示先判定是否需要底板

用于本轮新增、替换或重做的资源 HUD、分数/进度、奖励图标＋数量。先区分“显示数据”和“执行动作”：透明热区也可以响应点击，不为可点击的数据组自动加按钮底。正常按钮、物品卡片、进度条轨道和弹窗面板按各自用途设计，不受“所有 UI 都无底板”这种扩张解释影响。

- **图标和数字已清楚时不加底板。** 资源图标本身透明，数字/词图使用同套字芯、沿字形的描边和轻投影，保留图文间距；已有视觉归组不需要再套一块长方形、胶囊或单字砖。只替换文字时，不能顺手添加原版没有的数值容器。
- **确实看不清时先修字形和位置。** 在本轮已有的最窄视口、最长数值及实际经过的明暗/繁杂背景中判断；先调整字面与轮廓、间距、位置或背后局部构图。只有这些仍不足、或本轮明确保留原版中具有分区用途的承载板时，才沿原画风设计必要底板。不得把“高对比度”直接翻译成浅字配深底，也不默认把深蓝板改成另一种纯色板。
- **是否生成过不是免检理由。** PNG 中大块近似纯色填充，与 Graphics、Sprite 染色和 CSS 色块同属规则范围；只加圆角、细边或阴影仍是色块。正常场景、物件自身明暗和字形轮廓不当作底板。原游戏风格保留要求与当前明确禁区冲突时，只处理冲突点，不扩大重做。
- **生成和接图使用同一决定。** 在现有素材单/提示词里写清“无底板”或“需要的承载板及用途”，不新增签收文件。无底板的图明确真透明、只含指定图标/完整词/字形，无方块、色条、胶囊、外框或面板。使用支持透明输出的工具时同步设置真实透明参数，例如 `image_gen` 的 `transparent_background: true`；文字写“透明”本身不能证明 Alpha 正确。动态数字仍独立读取数值，不把当前金额烘焙进固定 HUD 图。
- **接入不补回底板。** 保留声明的透明性；不因贴图边界、数据归组或对比度兜底添加 Sprite/Graphics/CSS 填充，也不误删真实按钮的点击区。已有背板确需移除时只停用对应视觉层，保留数据和事件节点。首件在已有页面采集内核对最终组合；必要时仅暂隐该背板定位来源，取完恢复。后续只核受影响实例，不因此重拍所有页面或录屏。

生成无底板资源的提示词示例（把图案、字符和风格换成本作内容）：`transparent currency icon, isolated complete object, match the original game reference, no tile, no panel, no capsule, no banner, no rectangular background; generated digit glyphs have their own contour, no filled cell behind any glyph`。原图若带不需要的底板，参考其图标与字形风格，不照抄底板。图标、数字按独立资产/字库制作，按真实数值组装。

## 现有探针的覆盖边界

`check_text_backplates.py` 的低亮度阈值不是这条美术禁令的边界；中等亮度蓝板仍可能违反纯色底板规则。`flat_value_plate` 目前主要根据运行节点识别 Graphics 和默认小色块，`icon_plate` 不把带数值的整组资源容器算作独立图标底板。它们“未报错”不能证明普通 PNG 背板符合设计。首件沿用已有合成图核对来源、Alpha 和是否多出填充面；不能将探针通过写成这类背景已经全覆盖，也不能因为这一局限增加全游戏检查。

## 原有局部检查

1. **生成前约束**：提示词明确“真实透明字形；字芯不用深色/近黑，不用发丝细描边；无深绿/深青/近黑实心底块、矩形字砖、数字值槽”。生成后检查 Alpha 和图集切片，拒绝假透明、相邻碎片、底块；不把“高对比度”写成“浅字配深底”。
2. **组装后逐字看**：同帧整页＋文字局部，覆盖最短值、多位值、分隔符和数值更新后状态；追踪共用字形、Graphics 填充与实际 Sprite。手机尺寸切换后重载，使用相机投影校准字框与截图。`ui_dump.js` 记录 Graphics 填充色，`art_check.py` 的独立“文字与数字后深色实心底块”行通过才交候选；整屏深色占比、Label 颜色、节点名、已有对比底图豁免都不能代替本项。
3. **局部判据**：`check_text_backplates.py` 在实际文字周围找低亮度近似纯色连通块及连续内部面积，同时要求对应独立 UI 填充/文字贴图；自然场景暗部不当作 UI 底板，细描边须沿字形而非连成实心块。脚本是定位辅助，仍须主 Agent 看实际合成图；截图缺失、相机坐标未校准、生成贴图 Alpha 不明时不得记已验。
4. **先反例后固化**：精简候选先放项目；同一方法须检出未修版真实截图和运行节点，再修共用来源，以两种手机比例复查同屏与数值更新；沿字形的描边、自然背景、非深色的纹理胶囊作正常对照。修复后再次检出残块或字变弱就继续修，不靠删报告或降标准放行。

## 文字身后太花（v7.8，`busy_text_background`）

没有底板的字（Label、位图字；按钮上的字和自带字图的不算）要放在安静的背景上。量法：把字按 24 像素高缩放，取字框外半个字高的一圈当背景样本，字框里和样本颜色相近的像素算背景、其余算字墨，数这些背景像素要多少种颜色（每通道 16 级）才盖住 90%。超过 13 种只提示背景可能太花，先挪位置、调整字形或背后构图；确需衬底时按上面的底板决策，不把告警直接变成加色块的指令。

门槛怎么定的（W88，10-30，真截图）：安静的 3～11 种（Holly v3 PROFILE 加底板后 4、Meteor 250 在胶囊上 3、Nanas 地图 6、丛林荡藤 BEST 6、Maya 复活说明 8、Holly SHORTCUT 5～11）；太花的 16～119 种（Holly v1/v2 PROFILE 压栅栏 16～30、泡泡六角龙结算分数压彩球 28、水果逃亡章节行压厨房 119）。13 在两组中间。
