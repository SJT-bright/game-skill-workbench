# BGM 默认播放：测试包、预览和真机分开判断

适用于首页设计为默认有 BGM 的游戏、BGM 启动/后端改动或已报的默认无声问题。只检查受影响的音频启动节点；不新增全量音量、广告、玩法回归，不录像。已通过且游戏音频、启动和宿主依赖未变时沿用原始记录。

三个结论分别记录：

- **Native 默认请求**：零次用户输入、首帧之后，实际 Native 入口是否向平台播放器请求 BGM。没有调用就不能靠预览宿主替它发起。
- **本地预览播放**：真实播放器是否离开暂停、播放时间是否前进。浏览器 `NotAllowedError` 只证明预览的自动播放被限制，不证明 TikTok 包无声。
- **TikTok 真机输出**：只有同版的真实 TikTok 设备音频证据才能确认。浏览器、模拟平台、引擎 PLAYING、Native 请求成功都不能代签。

制作时保留默认开启和启动播放意图，尊重玩家已经保存的 OFF/零音量。先查环境再改业务；如果原包不改业务、仅修宿主就能恢复预览，不把该预览缺陷写成已证实的 TikTok 线上事故，不要求所有游戏更换生产音频后端。

## 轻量执行

已确认首页有 BGM 的项目，在原来的 `serve_preview.py` 调用增加 `--expect-home-bgm`。英化入口会转发该参数。现有首页 Ego 检查拍完首页后，在**同一页**读音频状态；仅在需要时补一次安全的普通 PLAY 触摸，再采样播放时间。不能点击音乐设置代替普通输入。

2.x 标准 Native 浏览器宿主现在仅对已被 `NotAllowedError` 拒绝、游戏仍想播放的循环音乐做首次普通触摸恢复。暂停、停止、销毁、音量为零、后台或系统中断时不恢复；不重头播已正常运行的音乐，不创建游戏没请求过的曲目。修的是浏览器替代层，Native 文件不变。其他宿主/Web/3.x 未校准时明确未测，不套用此结论。

首页截图旁的 `.audio.json` 保留原始前后采样，输出 `native_auto_request`、`environment`、`tiktok_device` 和错误代码：

| 结果 | 处理 |
| --- | --- |
| 预期有 BGM，但零操作时没有请求 | 拦截本次核准，查默认开关、存档、首帧和启动调用 |
| 普通 PLAY 后真实播放时间仍停住 | 拦截试玩交接，定点查预览拒绝/资源/播放失败 |
| 浏览器拦截，普通输入后恢复 | 预览通过并明确提示环境限制；真机状态仍为未验证 |
| 未找到安全输入、探针不支持或未采样 | 不能声明声音通过；显式要求首页 BGM 时阻止本次核准并补该项 |
| 玩家静音或页面设计无 BGM | 保留选择/设计，说明适用范围，不擅自开启声音 |

未声明首页 BGM 且未观察到默认请求时只提示未覆盖，不把所有游戏一律拦住；AI 确认该页有 BGM 后必须启用 `--expect-home-bgm`。运行器不可用时按既有规则保留未测，不换浏览器或关 autoplay 策略造通过。

该冒烟只核请求与真实播放时间，不替代 R09 的实际音频信号、独立音量和真实平台回归。已报故障用原始坏例、单缺陷变体和修复版定点闭合；通过记录绑定游戏与宿主相关字节，未变化不重复测。交付表述不得用“预览通过”推出“上传 TikTok 保证出声”。

首次确认平台音频、或启动/音频后端/SDK 相关依赖变化时，在原有同版 TikTok 设备点检里只补一条：新玩家正常冷启动、不碰音乐设置，确认首页 BGM 实际播放，记录构建身份及播放/错误回执；退出后停止。正常进入后的默认出声与平台预加载、玩家静音分开。设备证据尚缺时写明未验证；测试包可以用于这次平台点检，但不能被描述为平台声音已经保证。已有同版有效设备证据且依赖未变时直接沿用，不每次改名重跑。
