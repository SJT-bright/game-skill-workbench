# 将人工发现的问题变成机器拒绝条件

适用于游戏检查、维护、修复和出包。新发现的问题在本轮闭环，不等用户再次遇到：

1. 留住未修产物及准确失败输入；同一 runner 加载真实业务/adapter，仅控制存储、网络或 SDK 边界。
2. 写成可执行断言：故障反例必须失败；修复版与正常对照必须通过。受控反例明确写 controlled，不冒称历史包已失败。
3. 通用规则进入共享工具；游戏机制断言留本游戏 runner，通过已校准的 production loader 接入正式 gate。不得用手填 pass、模拟重写业务或模型自信代替执行。
4. 绑定最终 source/Web/Native 与 runner、依赖、原始记录哈希；writer 在 ZIP 前亲自重跑。缺证据、缺协议、旧指纹或失败直接拒包；额外测试量由实际变化面决定。

已自动化的复盘：体积按未压缩字节，不按 ZIP 大小；资源搬迁后检查静态本地引用与真实请求；图集切片边界与图片 SHA；合法数值 0 不作缺键；坏档不静默覆盖；存储异常/回读不一致不发奖或推进内存进度；重复兑现、重开及已有领取状态不丢失。

入口：`make_tiktok_zip.py`、`audit_packed_assets.py`、`run_reward_storage_probe.py`。支持的新生产结构先加真实加载器并用反例校准，不新增宽松打包入口。原有 `audit_native_storage_contract.py` 和加载恢复矩阵继续按实际机制执行；界面图文与可信触摸保留原始证据。自动检查的覆盖范围必须可列出，不声称穷尽未知缺陷。
