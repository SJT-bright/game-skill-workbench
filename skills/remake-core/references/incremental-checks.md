# 一次通过，按改动复验（2026-11-08）

**返工执行门禁（2026-11-10）**。默认先用 [执行范围计划](regression-scope-gate.md) 对实际 Native 做只读规划。两种正式写包入口和直接回归入口都核验计划。缺计划、原包失配、整包通配、范围未归属或不可拆整组时，当前 AI 持续修复依赖、执行器、适配器或真实证据，再生成核准计划续跑。`scope_required` 与 `repair_required` 是任务内修复状态。写包计划不能被执行阶段更换。最终交付核对最终 ZIP、正式回执与同版证据，失配时回到准确节点修复并继续交付。只有用户本轮明确要求全量，才生成独立全量计划。

**恢复流程已接入调度（2026-11-12）**。漏传计划由正式写包入口尝试按现有精确依赖修复，整包通配与未知消费者由当前 AI 补准。共享模块静态输入、真实旧证据基线恢复、混合执行器独立节点及同进程重新规划按[执行门禁的续跑规则](regression-scope-gate.md#调度器与当前-ai-各自继续完成什么2026-11-12)执行。`plan_ready` 和 `resumed` 均未完成交付，继续跟到原入口结果；不在修复分支调用 full，也不把新节点误作全部首次执行。

此规则覆盖英化制作、试听、试玩、美术、文字、玩法、关卡、平台回归和写包。已通过且相关输入未变的项，后续节点只读取原证据，禁止重复执行。换阶段、换聊天、重新构建、改包名、重新发链接、总版本号变化，都不是重测理由。旧文档中“每次必跑”“配置变更全部照跑”“第 5 阶段全量检查”指适用项必须有有效覆盖，不再表示重新执行。

已交付后又被退回，且用户要求改完指定美工出测试包时，按[返工交付与人工快查](returned-art-delivery.md)采用独立用户授权；该范围不启动新的美工复验。技术通过记录与用户授权分开保存。

## 两个入口，同一本记录

- `source`：收到中文源码 ZIP。安全解包到工作副本；读工程 Creator 版本，匹配对应 2.x / 3.x 和已验证的小版本；中文原版给 Chrome 供用户玩一次。原游戏观察所得的检查结论如需复用，也必须有相应输入与真实证据。
- `handoff`：收到别人已完成的源码 ZIP 和 TikTok 测试 ZIP。核准两者身份，优先恢复原检查记录，不重走中文原版试玩、制作和全套验收。缺失某项证据只定位该项；不能因为“别人说测过”伪造通过，也不能因没有记录自动全测。

源包交接携带 `docs/checks/workflow.json`、`check-inputs.json` 和可移植记录目录。导出/导入命令：

```sh
python3 <skills>/remake-core/scripts/check_ledger.py --project <工程> export --bundle <交接记录目录>
python3 <skills>/remake-core/scripts/check_ledger.py --project <接收工程> import --bundle <交接记录目录>
```

导入只恢复原执行时间、结果和证据，不签发当前版本通过。随后按当前文件运行 `plan`。证据缺失先恢复文件或报告具体缺口，禁止退回全量。

## 命名和执行单位

每个节点要有稳定 ID、中文名称、阶段、类别、实际输入、判定器、真实输出和前置证据。节点必须小到能独立执行：`image/claim-button/fit`、`text/notice/wrap`、`audio/button-click/mute`、`gameplay/pause/resume`、`levels/11/finish`。阶段名或“美工通过”不能代替这些节点。

五个阶段保留：盘点与基线；制作与首次验证；Native 试玩前覆盖核对；点对点返工；补缺与写包核对。每阶段内部按图片、文字/字幕、音效、玩法、关卡、平台入口命名。只列本游戏真实存在的节点，不为凑清单添加任务。

在 `docs/checks/workflow.json` 使用 `check-workflow.v1`。`roots` 给出输入根目录；节点 `inputs` 以这些根名及相对路径/glob 描述**全部依赖**；`basis` 写实际资源引用、源码消费者或既有运行证据。`command` 是已有检查器的参数数组；`tool_files` 是判定规则文件；`verdict.file`、`pointer`、`equals: true` 读取检查器实际输出。不得通过写一个 `passed: true` 来代替执行。模板见 [工作流最小示例](../examples/check-workflow.json)。

```sh
python3 <skills>/remake-core/scripts/check_workflow.py --project <工程> plan
python3 <skills>/remake-core/scripts/check_workflow.py --project <工程> run <节点ID>
python3 <skills>/remake-core/scripts/check_workflow.py --project <工程> status
```

`plan` 在开浏览器前完成。`run` 只执行指定节点；前置节点只读取通过记录，不自动再次执行。记录在 `docs/checks/incremental/ledger.sqlite3`，跨进程、重启和聊天恢复有效；同一项正在执行时另一进程不能再开一轮。不要删掉这份记录“从头来过”。

## 什么变化使哪一项失效

只有该项真实依赖的素材、文字、代码、布局、配置、测试条件或判定规则变化，才使该项待复验。共享字体、公共按钮组件或共用加载器有多个消费者时，所有真正依赖它的项都受影响；不能只把“本次改动文件”当作完整依赖。新增、删除和重命名也必须计入。

例：改签到文字，复验签到文字及其排版；共用字体没变时不重看其他页面。加第 11–15 关，检查这些关卡、第 10→11 关连接及受影响的选关页/滑条；第 1–9 关的已通过项沿用。改按钮音效，试听该音效及受影响的音效开关，不重跑 BGM、加载、广告、存档。

`check-inputs.json` 的格式是 `{"schema":"check-inputs.v1","checks":{"检查ID":{"inputs":{"package":["真实依赖路径"],"adapter":["/真实字段"]},"basis":"引用依据"}}}`。运行时使用 Native 文件相对路径；adapter 支持 JSON Pointer。目录 glob 会包含以后新增的匹配文件。

范围不明时脚本返回 `scope_required`，列出未归属变化。AI 继续读取调用关系、资源使用者和旧报告，补准映射再继续；不要把所有项都登记成 `*`，也不要放一个无关的兜底项吞掉新文件。只有现有检查确实无法独立拆开，且整个组合都受影响，才能将它作为一个组合节点；先说明它包含哪些动作。不能把“只修一个按钮”直接转换成“全首页巡查”。

## 浏览器与制作、写包使用相同计划

`runtime_regression.py`、`ad_regression.py` 和正式 writer 自动读取同一 ledger。启动的每种故障、前后台切换场景、广告回调、广告入口状态、布局页面×视口有独立记录。布局 pt/px 必须成对比较，属于同一项；不要把必要的两个条件误算为重复。多个待执行项合在原浏览器批次中完成，不为每条缓存记录新开浏览器。

`--suites` / `--cases` 可用于补缺；完整覆盖＝有效旧记录＋本次新结果。完整清单有未测项时仍标未完成，只补缺项。禁止用缩短的 adapter 清单冒充完整清单。旧包返工如果缺逐项基线，writer 指出缺口，不自动首次运行整套。侧栏和桌面入口依赖未变时沿用，不再强制重跑 `growth_entry`。

只用 Ego Lite。已通过且页面输入未变时不重拍，不反复打开浏览器；新截图仍要有真实构建/状态/视口身份。新服务每次读回入口字节核准同版，首页截图和广告响应按内容与视口复用原证据，不伪造新截图时间。

同一任务开始时，将 `ENGLISH_CHECK_PROJECT` 设为真实工程根，将 `ENGLISH_CHECK_EGO_SESSION` 设为该工程 `docs/checks/incremental/ego-session-<本次任务ID>.json` 的绝对路径，并给本任务的运行时与广告命令传入相同环境。一个批次结束只释放页面操作权，下一节点复用同一空间；节点正在运行时不并发操作同页。任务测试完成后调用 `ego_check_session.finish(browser, session_file)`，通过 Ego 的受支持接口关闭并读回确认。已关闭任务文件不重新开启；新任务使用新的任务 ID。出现控制权或安全停止时保持停止，不能删除停止记录来绕过。

`logic_check.py` 的 F01–F20 与 R01–R09 也按 `logic.F01` / `logic.R09` 保存原观察证据。首次已有真实通过且源码绑定相符时登记原观察（不启动浏览器、不伪造原测试时间）；后续整体源码指纹变化只查询各项 `source` 依赖。改过的项用新的实际观察及逐行 `source_binding`，不能只整体刷新旧 `regression_binding` 来洗白。旧记录没有范围时先按资源和代码使用者补范围，不自动全测。

美术继续使用现有首件合同、采集计划和图像分析缓存。`art_check.py` 遇到仍有效的原完整回执直接沿用；已有记录失效时，先运行 `art_iteration_plan.py`，走 `--first-piece-case`、`--ui-contract` 或精确维护范围，不重启完整美术轮次。首件、像素分析和 Codex 实际看图是不同判定；同一个判定已覆盖则沿用，不能以其中一项冒充另一项。

写包只补没有有效证据的项、核对版本绑定并做包文件核对。最终交付仍按用户单独规定读取实际最终 ZIP，生成本次体积、分包和 TikTok CLI `check` / `build` 回执，并核准同版可用的本地 Native 试玩入口。这是对本次交付文件的核对，不重新运行已通过的画面、音效或玩法验收。

启动合同、正式/轻量写包和交付只调度同一个[正式 Native 启动节点](native-startup-ledger.md)。保留原始实跑证据和本次重判，交付回执逐项记录沿用或重跑原因；拒绝记录没有下载链接。

## 每个节点的汇报

开始、完成、失败、改范围时都在当前聊天报告，至少包含：`阶段｜节点ID＋名称｜正在修什么｜本次执行/沿用｜实耗｜结果｜下一节点`。读取 `status` 和 `stage_timer.py` 的实测时间，不凭模型印象估算。

例如：`阶段 4｜text/checkin/wrap 签到文字｜已修重复字层｜本次只验此页，其他 18 页沿用｜实耗 38 秒｜通过｜下一项 audio/click/mute（预计 20–40 秒，来自同类实测）`。

预估需注明来源、范围和不确定性；没有同类样本就写“尚无可用估计”。超过估计先读工具进度，区分构建、页面路径、环境、产品缺陷和模型重复执行，不靠重启全矩阵解决。共享浏览器批次的墙钟时间只计一次，不把各节点重叠时间相加。

## 失败与修正

检查失败只修对应问题和真实共享依赖。未改输入时禁止自动重复尝试；确认浏览器等环境已恢复时，可记录 `CHECK_RETRY_REASON` 后只重试失败项，原通过项仍沿用。整轮 fatal、缺失原始结果、证据被改、输入在执行期间变化都不能写成通过；旧游戏不能把这些证据错误降级成警告。

正式采用前用同一真实游戏、相同故障/修复、相同条件比较旧版与候选版。分别列首次执行、无变化再请求、局部修改、最终覆盖核对的浏览器启动数、实际执行项数和墙钟时间；注入已知坏例验证没有漏掉受影响项。报告只能给测得的节省，不把教学模拟或脚本计算时间说成整轮游戏制作耗时。
