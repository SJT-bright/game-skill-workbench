# 人工试玩画面清单

发同版试玩时，按下面顺序列出这款游戏本轮涉及的项目，换成实际按钮、关卡或弹窗名：

- **首次英化（第一个英文试玩链接起，到 Saul 说没问题为止）**：本轮实际存在、改动涉及的场景都列，不设 3–5 条上限；一个场景一条，同一条路线走得到的合并成一条。Saul 说“没问题”就算这份清单整体确认，不要求逐条回复。
- **已交付后的返工**：只改一处就列一条，3–5 条以内，是交包后的可选快看（见[返工交付与人工快查](returned-art-delivery.md)）。

已经确认且未受影响的画面不再列。沿用已经确认且未受影响的画面，把观察并入正常试玩。可以直接回复「第几步、点了什么、看到了什么」。未走到的状态记未观察。静态问题一张截图即可说明，手边有图再附。

| 走到哪里 | 人工看什么 |
| --- | --- |
| 刚打开到首页，包含重试 | 看加载标志是否持续可见，有没有卡住后突然跳满、露出旧首页、黑白闪一下、进度结束还在空等。 |
| 首页、选关、点开始 | 留意第一次点进去是否闪黑白、旧画面过早消失、图或按钮闪没、开局 HUD 晚出现。 |
| 开关弹窗和切页 | 看设置、暂停、签到、商店等是否闪一块、错层、遮字、底板跟按钮乱动、关窗留残影。滚动时看背景有没有接缝。 |
| 切换音效、暂停后继续 | 点开关或滑条时看页面是否整体抖动、跳位、突然黑一下。继续后看画面是否回到正确状态。 |
| 打一小段 | 看连续点击、拖动或消除时是否闪屏、残影、掉图、背景错层、粒子变成不动的贴图。角色换动作时留意瞬移或穿过物件。 |
| 胜负、复活、重试、下一关 | 看结算内容有没有被遮住，旧界面退场后是否露空底，下一关是否先出现不完整一帧，奖励数字和动画是否看得清。 |
| 广告返回、切后台再回来、切换场景 | 看是否回错页、长黑屏、旧弹窗或资源残留、图片和文字突然消失又恢复。 |
| 看本轮新增或改过的画面 | 看英文是否贴合、漏译、太挤、切边、重影、变形、糊图、图标含义错误、是否被安全区遮挡、风格是否与原画面一致。 |

现有的启动计时、网络、功能状态、分包及版本核对按各自规则执行。给试玩链接不等人工反馈。首次英化的出包仍在 Saul 说没问题之后（英化入口第 5 阶段原有节点），那句“没问题”就是这份清单的人工确认，记录为“Saul 试玩确认”；没走到的状态记「未观察」，不写成通过。已交付返工按返工规则，不等回复。

**画面问题当轮修复（用户 2026-11-09）**。制作、修复和出包任务中，发现可复现且在当前授权内的遮挡、裁切、重叠、缺图、错层或假按钮，直接修源码或素材、重建并在受影响的正常手机尺寸及操作状态复验，再汇报结果。采集或探针无效时先修测试并重跑。只读评审、超出授权范围或缺少可复现条件时按实际边界记录。

## 首轮人工试玩的局内广告复活

美工完成后第一次交同版试玩时，若游戏有激励广告复活，把本项写进给玩家的清单。写出正常触发失败的关卡或玩法以及实际按钮名。由真人完成走关和操作。

1. 在能辨认周围危险的位置正常失败。点复活广告，中途关闭。观察生命、机会与奖励，按游戏规则再点一次入口。
2. 完成广告，核对回到原局、保留应有进度、生命或复活机会正确，并做一次真实玩法操作。
3. 若马上再次失败，记录复活位置、附近的坑、敌人或机关，以及玩家当时的输入。有必要时在相近位置和安全位置各复测一次。区分正常的再次受伤、复活点位置问题和无法恢复操控。
4. 按版本记录通过、失败或未观察。模拟广告和真机真实广告分别记录。此前发现的问题仍留在问题记录中，方便定点复测。

适用于所有游戏。这项人工结果不作为最终自动验收、出包或交付回执的门禁。通用广告回调和其他广告入口照常检查。

## 录制与证据用途

| 原有位置或能力 | 当前做法 | 什么时候录 |
| --- | --- | --- |
| 美工首页点按钮、开关弹窗、调音量、局内操作四段 | 在同版试玩中看，取消默认录像、逐帧分析和全量总览图 | 偶发且需要定位时只录该动作 |
| 最终 review 的 VIS-01 八类路线，另一个视口补启动、进关 | 并入上方清单，移除视频和 GPT 画面签收条件 | 常规零段 |
| LOAD-03 两视口的冷启、热启、限速及异常回退 | 实际网络与计时、输入和 Retry 用原始 JSON 核验，加载动效现场看 | 需要精确定位已发现的停顿时保留对应短段 |
| 手机预检、结算 NEXT、角色姿态交接 | 正常操作中观察，关键节点和交互可用日志、单张截图或同帧 dump 取证 | 先后顺序、极短闪帧或姿态突变无法说明时定点录 |
| 真机广告、回访或触控的已报问题 | 按实际入口与环境定点复现，日志、步骤和关键图优先 | 手机专有问题需要证明出现顺序时可用一小段 |
| Ego 的 --record、手头已有视频、按帧排障脚本 | 仅在排障时显式调用。优先用已经录到的短片 | 只保留复现动作前后几秒。单帧疑点用足够帧率的原始录像 |
| 首页快照、加载/Retry/复活/遮罩关键截图、布局 dump、资源文字 OCR | 单点证据与资源检查。Ego 内部保活帧流仅用于稳定时序，不保存录像 | 无需录视频 |
| 游戏里的激励视频广告 | 核对广告返回和奖励状态 | 无需录制测试过程 |

低帧率 Ego 连拍无法可靠确认单帧闪烁。能用步骤、日志或单张图说明的问题，直接用这些材料。普通包交付无需真机录像。
