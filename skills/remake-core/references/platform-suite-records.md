# 平台子套件按真实输入复用

此机制用于 Skill 维护自检，不给每款游戏追加测试或录制。

平台汇总入口仍是 `assets/platform-kit/tests/run-all.js`。47个原分支全部保留；Snake旧工程分支的3个子脚本分别留记录，因此整组覆盖49个实际上下文。另有2个默认配置上下文供C5单独入口使用，不能与旧配置混成同一条证据。

每份子记录保存稳定ID、脚本与配置上下文、声明的文件与目录成员、执行器和环境指纹、实际退出码与耗时，以及原始stdout/stderr的路径和哈希。输入不变、记录及原始输出有效才沿用；缺证、输出损坏、依赖变化或执行期间输入变动时执行或拒绝，失败不会被写成通过。多个入口在同一计划里消费相同输入时共享一个生产者。C5串行和隔离队列使用同一适配层。

首次缺少逐项输入和原始记录时，必须补实际观察，不能把旧汇总器的一行PASS改写成新的完整回执。后续只有受影响子套件执行。使用 `--report <回执.json>`、`--cache <当前证据目录>` 明确本次记录位置；跨次沿用通过 `--baselines` 提供带SHA-256的原回执列表。默认命令也有按当前Skill目录区分的本机临时缓存，未连接旧副本或其他项目。无常驻进程。

依赖由 `tests/suite-contracts.json` 声明。目录扫描记录成员集合，局部模块导入沿本地文件展开，缺失导入也记录状态。维护时修改测试/模块的读取、导入或子进程输入，先审新依赖并同步该子项的 `input_patterns`，再运行 `node assets/platform-kit/tests/refresh-suite-contracts.cjs --write` 刷新本轮输入；用不带`--write`的命令核对声明。依赖声明与源文件不符时，检查仍可实际执行，但该结果不能成为后续沿用证据。不能靠刷新哈希替代依赖审查。

更改单个条目只影响相关条目，不能把整份清单或汇总器的状态当成全部子套件失效。最终报告分别列出：顶层命令、实际执行的子套件、沿用项、旧配置上下文和各自实耗。原输出和失败反例保留；缓存不会宣称已通过游戏、真机或平台验收。
