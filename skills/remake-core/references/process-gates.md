# 全流程覆盖与交付检查

**美术检查前移（用户 2026-10-25）**：按[美术验收前移与试玩后锁定](../../remake-art/references/art-before-trial.md)执行：所有美术测试在交用户试玩前完成；用户确认后到测试包交付之间不再美工测试、不重新评判已批准画面。最终画面字段只查运行故障，不夹带美术标准。


**阶段与去重裁定（2026-10-24.scope-v2）**：本页描述要覆盖的结果，不要求重复执行同一轮。按[审查顺序与去重](../../cocos-game-check/test/references/review-execution-plan.md)分配一次证据到不同检查ID；设计/美术在各自阶段完成，最终只复核报告与变更。关卡按计划抽测，不逐关重复共用功能。上传后手机与真实IAA按用户实际授权另列，不成为本 Skill 的默认新阶段。

开工先按[重开与触摸输入](../../cocos-game-check/test/references/replay-and-input-checks.md)"开工就列出本游戏的风险链"列出本游戏的重开/复活/特殊状态链，慢加载、后台、迟到回调按[加载与广告预防](../../cocos-game-check/startup/references/loading-and-ad-prevention.md)提前测。本 Skill 只做浏览器模拟测试，出包即结束，不做上传后的真机测试。

本流程统一面向国际TikTok。完整制作的规格→需求ID→任务/依赖→实际路径/产物→同版验证按[任务与证据](production-plan.md)连接，更新现有文档而不复制结果表；开始、反馈后和包前三个节点读回这条对应。新项目/边界调整使用[工程职责](architecture-and-platform.md)，首版/性能反馈按[性能迭代](../../cocos-game-check/startup/references/performance-and-iteration.md)采相称证据，原catalog/失败门禁不变。

制作采用[本地多应用分工](local-agent-dispatch.md)：主线先定规则/断言和保护文件，再交出固定执行或有界实现；实际GUI采证与最终视觉/业务判断分开，QA和打包者不改产品/门禁。每个通过仍绑定本版原始证据，不能把委派报告当更高验证等级。

本页在开始实施、反馈修复后、最终打包前读取。把“英文界面完成”“应用创建完成”“代码上传成功”当成完整功能完成，会漏掉首页入口或奖励消费。先明确当前阶段；用户明确只要中间交付时，执行其范围，保留其余待办，不额外要求真机或企业认证。

用户明确要求出包时，同一回复交付可打开的本地试玩链接和当前目标的 Native 上传测试 ZIP；只要试玩/审查时不自动打包。内部制作与验证按本次范围执行。两者来自同版本，服务与指纹按 [交付与验证](delivery-and-handoff.md) 核验。英文源/Web/配置/证据保留项目，不额外打源码试玩总包；用户另行索取时再整理。

## 默认由 Agent 自主完成两阶段检查

制作的前两步固定为 全量中文检索（重塑包 remake-copy 板块，英化包不含），然后英化只换带中文字的图、重塑做全 UI 生图重构（见[两个板块](two-boards.md)）。开始先运行中文候选扫描，逐一处理文本/图片/动画和全部页面状态；英化后、新 UI 导入后及最终源/Web/Native/ZIP再次复核，内部键/路径/注释保留具体依据。`UI-01` 必须有候选处置、图片文字和实际运行状态证据，不能以静态零命中签收。

新制作全部 UI 页面、永久及条件控件使用内置 image_gen 生成/编辑并实际接入，含面板、HUD、卡片和关闭/返回等小型图标；不能保留未重构英文原按钮或临时方框作为完成品。重复控件可共享新生成同套组件，实时数字/状态继续读取业务。用户指定局部维护范围时按该范围复核，不重做已结项游戏。Agent 检查实际图片来源、风格、图标/文字层级、透明轮廓、内边距和按下/禁用状态，在两种比例下看完整渲染；按 [美术自审](../../remake-art/references/artwork-and-feedback.md#agent-逐个审查按钮美术) 保存本版全 UI 清单与证据，归入 `ART-01`。图片资源存在、生图成功或几何通过都不等于审美通过。

全 UI 生成/导入后的美术阶段执行一次 [全量视觉巡检与优化](../../remake-art/references/full-visual-review.md)，盘点并查看所有可见素材原件及全部实际显示位置/条件状态，含原有图像、图集格、动画关键姿态与异步替换。逐一核穿插/越框/盖字、透明/裁切、层序/遮罩、清晰度、留白/对比与整体观感，发现问题自动修复并按同状态复查。`ART-01`记录全量覆盖和缺陷/复查，`UI-03/05/06`关联实际GUI。未查看/未到达不写通过；不能以一张总览或生图回执替代。

平台入口另核 [语义图像设计](../../remake-art/references/artwork-and-feedback.md#平台入口的语义图像设计)：小房子、个人主页回访图像、突出实际奖励且标明视频的广告按钮均须在实际 Cocos 中显示；不能只检查生成文件或文字按钮。

在检测之前单独完成 [共通首页与声音设计](../../remake-art/references/common-game-components.md)（英化同样要有两类声音设置和两个主页入口，只是不换声音文件）：每款新制作提供 MUSIC/SFX 两类全局独立开关、0–100% 十格及每次10%的减/加，重新设计主题一致的声音弹窗背景，玩家页不含试听/调试列表；首页房子与个人主页回访图标分别接真实平台功能。检查前先落实资源、Button、状态与持久化，随后在视觉和功能阶段逐项实测；局部维护按当前范围。共通部件缺失不能因其他按钮通过而略过，不增加用户审美确认环节。

美术自审后直接进入功能检查，由 Agent 全面检查本游戏的按钮与条件入口、广告位置与实际处理器、SDK 接口、奖励及保存、正常和取消/错误/超时流程、点击停顿或卡住、动画及两种手机比例。修复后复核受影响流程，再接本页原有手机、真实 IAA 和打包门禁。功能检查发现影响文字、按钮或比例的缺陷仍须修复；只重新检查受影响部分，不重做无关的合格美术。

按实际关卡阶段审查流程合理性：首关教学、正式关卡、通关/失败、下一关和返回各自应显示哪些控件，教学按钮是否在正式关卡消失，返回位置是否符合当前授权，广告奖励是否匹配按钮承诺、取消/失败是否保留原状态。按 首关教程（重塑包 remake-onboarding 板块，英化包不含） 留实际操作和模型结果，不把按钮数量或可点击性当作完整逻辑审查。今后制作、换皮按 不提供广告跳关（重塑包 remake-onboarding 板块，英化包不含） 执行，新输入原源码自带时也一律清理入口、绑定、处理器、广告请求和跳关消费者；免费推进/重试、同局复活及其他奖励分别保持。其他已结项成品不追溯回改，无关局部维护不扩大范围。

制作中途不停下等用户；整套玩法和美术完成后，按[四个阶段](stage-flow.md)交用户试玩验收（阶段 2），用户说"美术玩法通过"并锁定后，才由 Agent 做完整检测（阶段 4），检测期间不再请用户审 UI。用户明确要求体验时提供其可直接操作的普通试玩入口和启动器；主动反馈按实际版本与范围承接。用户当前明确改变顺序或范围时按其要求执行；已有 App/广告配置与同范围授权保留，不重复索取。

按 [打包前本地与手机检查](../../cocos-game-check/test/references/prepackage-mobile-review.md) 执行：真实 Web/Native 目录 → Agent 美术、完整功能与 Ego Lite 触屏检查 → 已授权测试候选 ZIP 的独立复查与交付 → 当前游戏逐项手机清单 → 实际手机/IAA结果及必要修复。用户未回复不阻断已授权本地测试 ZIP；候选绑定版本并明确待验范围，不能标成最终手机验收通过。验收后保持已测字节整理文件时再核对 SHA。

每次扫码候选与最终包都按 [通用问题适用范围与重点](feedback-regressions.md) 生成清单，优先逐广告/奖励入口核对；其余机制只检查实际存在或已授权的功能。按统一编号保留适用性、最小复现、自动/GUI/手机结果和当前指纹；原反馈及个性化改动留项目。已自动化的失败、缺工具或无法读取实际Native时，在创建ZIP之前停止。

按 [复活与小型教程审查](../../remake-ads/references/rewarded-revive-and-help-layout.md) 先审查广告复活，已有则保持并验证、缺少则实施；免费 TRY AGAIN 独立。教程入口及内容卡片的小空间/安全位置也需真实GUI复核。此项是用户明确的通用制作要求，不受下文“不为凑表新增玩法”限制；其他无授权玩法不扩大。

## 三个检查节点

这三个节点覆盖美术与功能两阶段；美术自审不代表广告、输入或真实手机通过，已有美术结果也不能替代功能验证。

1. **开始**：确定原版、当前服务和既有配置；读本表与对应参考。列明缺项、复用模块和本游戏需要接的节点/业务方法，再改源码。以用户当前授权为准，不把表当额外审批流程。
2. **反馈修复后**：实际 Cocos 检查本版主页/弹窗/玩法及受影响状态。定位实际素材、内边距、背景色块和点击区域；修文字/素材或绑定原因，不预设缓存。更新差异与反馈状态，保留已确认版本及配置。
3. **打包前与包内复查**：按表核对接口和真实消费者，缺项补齐或明确待办，再实导 Web/Native；共通首页与声音的设计/逐项 GUI 结果归入现有 AUDIO/UI/ART 与主页检查，不以生图或代码存在代替完成。Agent 完成本地美术、功能与触屏检查后，直接继续已授权测试 ZIP；未回复和真机/IAA待验不构成该本地候选的额外确认门槛，原自动失败门禁不变。独立解压包，核对实际文件与已测构建；确认最终可点击链接仍指向已核验字节，即使文件被改名也以 SHA 和内容识别。手机与真实IAA验收按各自实际证据记录，不能拿早期截图、另一个应用的上传记录或源码测试代替本包证据。

## 只复用稳定的平台部分

复用前审查版本、SDK 前缀、严格结果、取消/超时与监听清理。平台适配器可复用；其他游戏的 UI、库存、具体奖励、固定坐标和配置不可直接套入。新游戏不默认继承某款字体、两种道具、首次/每日规则或测试 ID。

奖励实现详见 [主页回访](tiktok-home-growth.md)，实际画面详见 [原画风与反馈](../../remake-art/references/artwork-and-feedback.md)。业务模拟必须运行本游戏实际方法，覆盖领取及真实消费入口，而非写另一个简化实现去验证自己。没有手机时注明模拟/电脑证据，保留真实平台待验。

构建/打包工具显式接收工程、公开配置、应用模式、版本和输出路径；缺配置在写源码/输出前报错，待配置模式须显式开启。需要更新配置时同步源码与实际构建，候选生成后核对读取的配置路径；不能因工具来自上一游戏而硬编码其标识、广告位或输出名。

## 静态标记漏项检查

在技能根目录执行，或使用脚本绝对路径：

```sh
python3 scripts/audit_platform_markers.py /path/to/current-cocos-project \
  --native-zip /path/to/final-Game-TikTok.zip \
  --report /path/to/new-platform-markers.json
```

默认检查 IAA 和两个主页能力的关键标记，分别报告源码及 ZIP 的匹配文件、缺项；发现缺项返回 2。开始阶段可不提供 ZIP；用户明确只做某中间部分时可用 --features iaa 或 --features growth，并在功能表保留未查部分的状态。不要为了通过扫描写无作用的调用。

这是文本标记检测，会匹配字符串、注释或未使用代码；动态生成接口名也可能漏检。存在只说明需继续审查该处，缺失需要定位真实调用/构建遗漏或补齐实现；不得用它宣称兼容检查、严格布尔资格、闭包生命周期、配置归属或真实奖励通过。平台结构与字节仍用 scripts/verify_native_zip.py 及实际独立解压核验，官方离线与设备检查另列。

## 累积故障逐项核对

在本流程之前读取 [累积问题清单与拦截](known-issue-checklist.md)，用固定ID生成当前游戏清单，双向核实际按钮绑定和所有领取入口。每个入口检查可领/请求中/已领外观、取消/失败/超时、重开/刷新/重复回调；余额、领取记录、按钮/红点分别断言。最小检查实际执行源与当前Native并接真实打包器，不只读既有pass报告。`check_known_issues.py --stage pre_scan` 缺项/过期/失败阻止新测试ZIP；物理手机和IAA项目仍按实际结果保留待验，不凭此脚本冒称真机通过。
