# TikTok制作：需求、任务与证据

新创建、完整换皮或需要跨阶段接棒时使用；局部修复仅更新受影响需求与任务，不补造整套项目文档。所有平台目标均为国际TikTok，工程/公开配置/Runtime与实际交付保持同一目标。

## 一份规格，一条证据链

沿用项目已有PRD或创建入口的creation-spec作为权威，功能表与[固定ID检查](known-issue-checklist.md)引用它。为本轮有用需求分配稳定编号；任务关联需求、产物和实际验证，避免在多份表中重复维护奖励数值或pass结果。进度页只是当前任务、阻塞/恢复条件、下一步和最终版本的摘要，详细证据指向既有报告。

新项目可在已有项目文档目录维护 `tasks.md`，进度较多或需交接时另设 `progress.md`；路径随项目，不要求迁到client/docs结构。任务可裁剪[模板](../assets/production-task-template.md)，至少写清：

| 字段 | 实施约定 |
| --- | --- |
| 输入与需求 | 权威规格路径/版本、需求ID，源/配置/关键输入SHA |
| 范围与依赖 | 本任务产生的可验证结果、前置任务/恢复条件，不顺手扩大功能 |
| 执行与文件 | 主线或执行者、实际读写路径、关键保护文件、工具/资源锁；需委派时链接现有合同 |
| 产物 | 源码/素材/实际构建/报告的准确路径；不能用计划文件名冒充已存在 |
| 完成条件 | 玩家行为与真实业务结果、正常/边界/错误路径、当前阶段所需证据 |
| 结果与版本 | 实际命令/工具、输入版本、结果/原始证据、失败与修复、未执行/受阻及最终产物指纹 |

一项任务应形成可检查的小闭环，可以跨多个必要文件，不按“一个文件就是一个任务”机械拆分。以依赖顺序推进：明确条件→实施→执行验证→记录实际结果→接下一项；用户要完整游戏时内部节点不成为停止点。

任务状态使用待开始/进行中/已完成/受阻；检查结果分别记通过/失败/未执行/受阻，既有catalog继续使用自己的合法状态。任务已完成只表示该范围满足条件，不提升为整款游戏或手机通过。Web、SDK替身、实际Native、物理手机/真实IAA分开记，空工具/账号/设备条件写恢复要求，不拿截图、日志标题或现成pass文件代替执行。

## 英化制作的依赖顺序

首次完整英化和明确补齐六标准广告时使用。功能目录、六类计数表和检查清单的序号不是串行施工顺序。已交付后的局部返工仍只处理本轮改动及真实依赖，不重新执行这张完整路线，也不为升级 Skill 返工已完成游戏。

| 顺序与原阶段 | 本节点先确定什么 | 可以继续的工作及避免的周转 |
|---|---|---|
| 1 · 开工 | 输入、工作副本、引擎路线与原版可操作基线 | 沿用已有真实迁移/启动证据；模块解析或核心入口已坏时先修，避免批量改图后才发现不能开局 |
| 2 · 盘点后、批量制作前 | 原功能、删改项及六类广告的现有/缺失项、真实作用、入口/返回、页面及条件状态 | 通常一次运行 ad_nodes.py plan；有当前清单则复用，未有候选时使用其内置扫描，不默认串跑 diagnose、audit、plan 三遍 |
| 3 · 修改 | 共用存档/发奖事务、暂停输入归属、皮肤/道具/体力接口、数值与最长文案、资源名 | 优先复用已存在的实现；一次汇总所选模块的存档键和配置，再做工程级整合。保留各模块必要轻量校验，不每装一个模块就构建整款游戏 |
| 4 · 修改 | 先按[资源分包前置](resource-package-prepare.md)确定本批图片、字体、声音和新增广告资源的实际 Bundle 归属、加载入口及两类预算，再加载 remake-art，按原画风把原页面和全部新增页面一起定布局、文字内区、字体/数字/符号、图标和状态槽 | 首页把六类入口、平台入口和设置一并安排；同款素材先有统一槽位，再定像素和打包预算，避免画完才扩按钮、改数字或补一个入口 |
| 5 · 修改 | 一小组能覆盖本批共享风险的真实首件，经过实际初始化与最窄比例核对 | 合格原料不因错绑重画；共性问题先修共享组件。它是批量复制的依据，不代表全游戏通过 |
| 6 · 修改 | 按已定接口接逻辑，按已定槽位批量制作原有及广告 UI | 输入稳定且文件/资源不冲突时可并行；美工不必等所有广告代码写完，逻辑也不能用临时界面改变已定槽位。共享底板、字形、数字、图标按同类批次制作，不逐广告模块另做一套 |
| 7 · 英文候选 | 本批源码与资源准备收齐后，首份 Native 只读校准主包／分包／首屏实际字节，再按真实变化构建缺失/失效目标 | 同源有效 Web/Native 导出直接沿用。必要首件/排障构建允许提前；不以模块数或图片数安排构建，不为追求固定一次而隐藏失败 |
| 8 · 英文候选 | 同一候选、同视口沿真实路线连续采集，执行适用画面/中文/功能项及现行连续游玩 | 采集和功能检查共享可达路线与当前状态，分别留各自必要证据；已通过且依赖未变的结果沿用，不做模块×页面×视口×故障的无条件乘积 |
| 9 · 英文试玩 | 本阶段制作及适用核对完成后交同版双栏 H5 | 左侧游戏、右侧人工清单，只在正式交接调用 Chrome；预览服务、H5 和清单可提前准备，未就绪时内部继续修复 |
| 10 · 反馈与最终交付 | 反馈按真实受影响节点修改，最终核当前证据、最终 ZIP 和同版试玩 | 有效记录沿用，补缺及复验点对点；每次实际交包的分包/体积核对保留，不重新做完整美术回执或无关全量回归 |

统一一轮美工指共用方案与制作队列，不把所有页面塞进一次生图或一张大图集。按实际尺寸、共用样板和切片边界分批，某组失败只回到对应原因和受影响组。

这不是十个新阶段、十份新文档或十个门禁。范围和接口写回已有规格/任务；业务登记仍用 ad_nodes.json，页面用 pages.json，显示槽与采集仍用现有清单。计划项与已创建页面、通过结果分开，不能靠这张顺序表写验收通过。

六类的展示/核实顺序仍为结束、主页、永久皮肤、体力、局内道具、周期试用；实际接线服从依赖。例如周期试用要等对应皮肤或道具的临时权益接口可用，共享存档与发奖事务先于各领奖消费者。只修广告接线、回调或数值而视觉依赖未变时，不安排重生图；某个新页面独立就绪时可完成该组首件，不用等待其他无依赖页面。

生成与切图等待、逻辑实现、同因修复、每次构建和按视口采集分别用既有 stage_timer 节点计时。性能比较看真实批次与构建/采集次数及墙钟；预测与历史回放不能报成新游戏实测。原材料、绑定、采集和工具问题的分流沿用[美工批次处理](../../remake-art/references/art-iteration-workflow.md)。

## 连续决策与并行

主线管理依赖图、受保护业务和验收。每个执行者同时一个当前任务；真正独立且文件/资源无冲突时可并行，不用全项目单任务约束关闭已选择的多应用协作。共享规格、进度汇总和最终验收由单一写者维护，执行者返回自己任务的原始结果。

桌面任务只有用户本轮已选择多应用时按[现行分工](local-agent-dispatch.md)派发；独立可选Grok按[CLI边界](optional-grok.md)执行，完全单应用不调用外部AI；本页不新增应用、权限或默认开启。任务字段可补入已有合同，不再复制一套不同的文件锁/权限/断言规则。QA仍只采证，打包者不改业务或门禁。外部阻塞独立列任务，明确恢复条件并继续无依赖工作。

## 规格、资产与范围变化

实际实现需偏离规则、技术栈、目录职责或资源方案时，记录原因和受影响需求/任务/验证；常规可逆工程选择直接推进。核心方向缺决定时给具体选项，不重复批准已有方案。后端、支付、云存档、社交等只按当前需求与授权采用，不因为模板有字段就预建空目录或服务。

资产表同时记用途与真实绑定：页面/条件状态、画布与显示尺寸、透明边缘/安全边距、默认/按下/禁用/选中、来源/生成提示词/日期/许可、目标路径/meta与实际显示位置。声音另记事件、时长/循环、音色与音量层级。它们接全UI重构（重塑包 remake-copy 板块，英化包不含）、[全量视觉](../../remake-art/references/full-visual-review.md)及[声音实现](../../remake-art/references/common-game-components.md)，不是额外等待用户交素材或只交音频提示词的流程。

## 三个节点的读回

开始核“规格→待创建/复用→任务”；反馈后核“用户反馈→修复→同状态结果→受影响需求”；包前核“已完成任务→同版源/Web/Native→最终ZIP→独立读回”，引用原问题清单/门禁结果。未执行与延期如实保留，不能用任务表绕过现有失败拦截。实际上传/发布只属于用户另已授权的工作。

方法来源与许可见[蒸馏说明](method-provenance.md)。

交付完成后由现有交付入口执行[非阻塞经验回流](production-learning.md)：读取已有修复、问题与计时，形成可携带候选。先记录检查暴露的缺陷应在什么制作节点预防；共享规则去重、替代、冲突处理与补丁验证另走维护工作区，不能成为当前游戏交付的新等待点。
